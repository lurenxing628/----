# 系统使用说明

最后更新：2026年5月

这份说明书是给计划调度员、工艺员和现场管理人员看的。你可以把它当成一套从空库开始建资料、导入表格、补工序、模拟排产、正式排产、看甘特图、导出周计划、查报表和回看历史的操作手册。

这份说明只按现在页面上能看到的入口和现在下载到的 Excel 模板来写。页面上旧入口统一叫 **批量维护**；如果你在老资料里看到“某某 Excel 导入导出”这类叫法，按现在页面上的“批量维护”理解就行。

---

## 0. 先说清楚：第一次正式排产怎么走

从一个空库做到第一次正式排产，推荐按这个顺序来：

1. 先进 **工艺管理 → 工种配置**，把会出现在路线文字里的工种建好，比如 `数铣`、`钳`、`数车`、`标印`。
2. 如果有外协工序，进 **工艺管理 → 供应商配置**，给外协工种配启用状态的供应商和默认周期。
3. 进 **工艺管理 → 零件工艺模板**，用路线文字建零件和工序清单。例子：图号 `P1001`，路线文字填 `5数铣10钳20数车35标印`。
4. 给自制工序补工时：可以在零件详情里逐条填，也可以通过零件工序工时模板批量维护。
5. 进 **人员管理** 和 **设备管理**，建人员、设备、班组和状态。
6. 建人员设备关系。例子：工号 `OP001` 能操作设备 `M001`，技能等级填 `熟练`，主操设备填 `是`；同一个人员只能有 1 台主操设备。
7. 进 **工作日历配置**，按需要维护工作日、假期、加班和调休。没有特殊日期时，系统默认工作日 8 小时，周末和假期不排。
8. 进 **批次管理**，新增或批量维护批次。例子：`B001 / P1001 / 50 / 2026-05-20 / 急件 / 齐套`。
9. 打开批次详情，检查每道自制工序是否已有设备、人员、换型工时、单件工时；外协工序是否已有供应商和周期。
10. 先做一次 **模拟排产**。模拟会生成一个可查看版本，但不会把批次状态改成正式已排。
11. 去 **甘特图**、**周计划导出**、**资源排班中心**、**排产优化分析** 看结果是否合理。
12. 确认没问题后，回 **排产调度** 做 **执行排产**，这才算第一次正式排产。
13. 正式排完后，去 **报表中心** 看超期、资源负荷、停机影响。正式排产和模拟排产成功后都会自动保存版本，**系统管理 → 排产历史** 只用来查看、搜索、分页查看版本摘要和结果概况，不在这里导出或恢复版本。

## 1. Excel 批量维护：表格怎么填

系统很多页面都有 **批量维护** 卡片。基本流程都是：

1. 点 **下载模板**。
2. 按模板第一张工作表填写，表头不要改。
3. 选择写入方式。
4. 点 **上传 Excel 并检查**，看每一行是新增、更新、无变化、跳过还是错误。
5. 没有错误行后，点 **确认写入系统**。
6. 写入后可以再点导出，拿导出的表和你原表对一下。

单个上传文件最大 16MB，只读取第一个工作表。固定选项字段请填写中文值，比如 `启用`、`停用`、`自制`、`外协`、`普通`、`急件`、`特急`、`齐套`、`未齐套`、`部分齐套`。

### 1.0 Excel 模板总表

第一次准备排产资料时，不要一上来只导批次。批次只是“这次要做什么”，还需要前面的工艺、人员、设备、日历这些资料一起支撑，系统才知道“谁、用哪台设备、在哪天、做多久”。

| 模板 | 主要给谁填 | 解决什么问题 | 建议顺序 | 入口 | 完成标志 |
|---|---|---|---:|---|---|
| 工种配置 | 工艺员 | 先告诉系统有哪些工种，比如数铣、钳、标印 | 1 | 工艺管理 → 工种配置 → 批量维护 | 工种列表里能看到要用的工种，名称和路线文字一致 |
| 供应商配置 | 工艺员或计划员 | 外协工序要交给谁、默认几天回来 | 2 | 工艺管理 → 供应商配置 → 批量维护 | 启用供应商能匹配外协工种，默认周期大于 0 |
| 零件工艺路线 | 工艺员 | 每个图号有哪些工序，路线文字怎么拆 | 3 | 工艺管理 → 零件工艺模板 → 批量维护路线文字 | 零件详情里能看到路线拆出来的工序 |
| 零件工序工时 | 工艺员 | 自制工序换型多久、单件做多久；空工时按 0 小时处理 | 4 | 工艺管理 → 零件工艺模板 → 批量维护工序工时 | 自制工序已有换型时间和单件工时 |
| 人员基本信息 | 计划员或班组长 | 哪些人能参与排产、属于哪个班组 | 5 | 人员管理 → 人员管理 → 批量维护 | 在岗人员列表里能看到要排产的人 |
| 设备信息 | 计划员或设备管理员 | 哪些设备能用、能做什么工种 | 6 | 设备管理 → 设备管理 → 批量维护 | 可用设备列表里能看到要排产的设备和工种 |
| 人员设备关联 | 计划员或班组长 | 某个人能操作哪台设备，谁是主操 | 7 | 人员管理 → 人员详情 → 可操作设备；或设备管理 → 设备详情 → 可操作人员 | 批次详情里的自制工序能选到设备和人员 |
| 工作日历 | 计划员 | 哪些日期能排产，日历类型空着按工作日理解 | 8 | 排产调度 → 工作日历配置 → 批量维护 | 工作日、假期、可用工时和效率能在日历页看到 |
| 个人工作日历 | 计划员或班组长 | 某个人请假、加班、临时只排急件 | 9 | 人员管理 → 人员详情 → 个人工作日历 → 批量维护 | 有请假或加班的人能看到自己的单独日历；没有特殊安排可以不填 |
| 批次信息 | 计划员 | 本次要生产哪些批次、数量、交期、齐套状态 | 10 | 排产调度 → 批次管理 → 批量维护 | 批次列表能看到新批次，批次详情里已生成工序 |

填写时有一个总原则：模板里已有的表头不要改，系统靠这些列名认数据；你只改数据行。编号类字段建议先把 Excel 单元格设成文本，避免 `001` 被 Excel 自动变成 `1`。

### 1.1 批量维护写入方式

| 写入方式 | 大白话解释 | 适合什么时候用 |
|---|---|---|
| 更新已有，新增缺少 | 编号已存在就改，编号不存在就新增 | 最常用 |
| 只导入新编号 | 编号已存在的跳过，只补新数据 | 怕误改旧数据 |
| 清空本类数据后重导 | 先删掉这一类旧数据，再按表重建 | 只适合你确认要整批重做时 |
| 更新已有工时 | 只更新已有自制工序的工时 | 零件工序工时专用 |
| 只补空工时 | 已有工时不动，只补空的 | 零件工序工时专用 |

清空重导要非常谨慎。批次被清空时，批次下面的工序和排程记录也会跟着没了；如果不是非常确定，优先用“更新已有，新增缺少”。

上传检查、确认写入、清空重导和失败排查按这个顺序处理：

1. 先点 **上传 Excel 并检查**。这一步只是检查和预览，不等于已经写入系统。
2. 看检查结果。`新增` 表示系统里没有这条；`更新` 表示会改已有数据；`跳过` 表示当前写入方式不处理；`错误` 表示这一行不能写入。
3. 有错误时，不要点确认写入。先按页面提示改 Excel，比如补必填项、改日期、改不存在的图号或工种，再重新上传检查。
4. 没有错误后，再点 **确认写入系统**。只有到这一步，数据才真正进入系统。
5. 如果选择 **清空本类数据后重导**，要先确认你确实要用这份 Excel 重建这一类数据。清空后，旧数据和相关明细可能一起没了，不能把它当成普通更新用。
6. 确认写入后如果发现填错，优先下载当前模板或导出当前数据，改好后再按“更新已有，新增缺少”重新导入；只有整批数据都要推倒重来时，才考虑清空重导。

### 1.2 日期、时间和数字怎么填

| 内容 | 推荐写法 | 说明 |
|---|---|---|
| 日期 | `2026-05-20` 或 `2026/05/20` | 批次交期、齐套日期、日历日期都按这个写 |
| 时间 | `08:00` 或 `08:00:00` | 班次开始、班次结束用这个写 |
| 小数 | `0.5`、`1.25`、`8` | 工时、效率、周期都可以是小数 |
| 是/否 | `是`、`否` | 不建议填 TRUE/FALSE |
| 编号 | 先把单元格设成文本 | 防止 `001` 被 Excel 变成 `1` |

数值字段不要填 `TRUE`/`FALSE` 这类是非值，也不要填 `NaN`、`Inf`、`Infinity` 这类不是正常数字的内容。工序号不要用科学计数法，比如不要写 `5e0` 或 `1E2`；工序号建议按普通整数写，比如 `5`、`10`。模板表头要按下载文件原样保留，不要改名、删列、合并表头或把有效数据放到第二张工作表。

不要在文本日期里带时间，也不要填 Excel 序列号。公式、合并单元格、空表头都容易导致系统读不到值。

第一次建库时按这个顺序最稳：

1. 工种配置
2. 供应商配置
3. 零件工艺路线
4. 零件工序工时
5. 人员基本信息
6. 设备信息
7. 人员设备关联，也可以用设备人员关联，填的是同一类关系
8. 工作日历
9. 个人工作日历
10. 批次信息

### 1.5 常见检查结果怎么看

| 检查结果 | 意思 | 你要做什么 |
|---|---|---|
| 新增 | 系统里还没有这条编号 | 确认没填错就能写入 |
| 更新 | 系统里已有这条编号 | 确认这次就是要改它 |
| 无变化 | 表里和系统里一样 | 不用处理 |
| 跳过 | 当前写入方式不处理这一行 | 看是否符合你的预期 |
| 错误 | 这一行不能写入 | 改 Excel 后重新上传检查 |

只要还有错误行，就不要硬继续。页面会告诉你哪一列有问题，比如“数量必须大于 0”“图号不存在”“日期格式不正确”。

举几个常见例子：

| 场景 | 检查结果 | 为什么会这样 | 你该怎么处理 |
|---|---|---|---|
| 设备表里填了新设备 `M003` | 新增 | 系统里还没有 `M003` | 确认设备编号、工种、状态正确后确认写入 |
| 人员表里已有 `OP001`，这次改了姓名或班组 | 更新 | 编号相同，内容有变化 | 确认这次确实要改旧资料后确认写入 |
| 批次表里 `B001` 和系统里完全一样 | 无变化 | 数据没有变化 | 不用处理，可以直接忽略 |
| 写入方式选“只导入新编号”，表里又有已存在的 `B001` | 跳过 | 你选的方式就是不改旧编号 | 如果想改 `B001`，把写入方式改成“更新已有，新增缺少”后重新检查 |
| 批次表里图号填 `P999`，但系统没有这个图号 | 错误 | 批次引用了不存在的零件 | 先导入或新建 `P999`，或者把批次图号改成正确值，再重新上传检查 |

确认写入也按检查结果来判断：

1. 如果检查结果是 `2 条新增、1 条更新、0 条错误`，并且这些新增和更新都是你想要的，就可以点 **确认写入系统**。
2. 如果检查结果里有 `错误`，不要点确认写入。先改 Excel，再重新点 **上传 Excel 并检查**。
3. 如果检查结果里有 `跳过`，先看它是不是你故意选出来的结果。比如“只导入新编号”导致旧编号跳过是正常的；如果你本来想更新旧编号，就要换写入方式。
4. 点 **确认写入系统** 后，才算真的保存。只上传检查、不确认写入，系统数据不会变。

### 1.6 逐模板填写指南

#### 1.6.1 工种配置

**进入方式**：工艺管理 → 工种配置 → 批量维护。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 工种ID | 是 | 自己定编号，比如 `OT001` | 为空、重复 |
| 工种名称 | 是 | 路线文字里会用到的名字，比如 `数铣`、`钳`、`数车`、`标印` | 为空、重复或不符合页面校验 |
| 归属 | 否 | 推荐填 `自制` 或 `外协`；新文件请只填这两个中文值；不填按自制处理 | 填了系统不认识的词 |

工种名称要和路线文字里的文字一致。你准备写 `5数铣10钳20数车35标印`，就要有 `数铣`、`钳`、`数车`、`标印` 这些工种。

旧模板中已有数据行不会被系统擅自改写；也就是说，如果旧文件里已经有“内部/外部”这类旧写法，系统刷新模板时会优先保住你的原始数据。新填数据请使用 `自制`/`外协`，旧值导入时会尽量兼容识别。

#### 1.6.2 供应商配置

**进入方式**：工艺管理 → 供应商配置 → 批量维护。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 供应商ID | 是 | 自己定编号，比如 `S001` | 为空、重复 |
| 名称 | 是 | 供应商名称 | 为空 |
| 对应工种 | 否 | 工种编号或工种名称 | 填了不存在的工种 |
| 默认周期 | 是 | 必填；大于 0 的有限数字天数，比如 `3`、`1.5` | 空、0、负数、`TRUE`/`FALSE`、`NaN`、`Inf`、`Infinity`、文字 |
| 状态 | 否 | `启用`/`停用`；旧文件里的 `在用`/`正常`/`禁用` 也能识别；新文件建议填 `启用` 或 `停用` | 填了系统不认识的词 |
| 备注 | 否 | 随便写 | 一般不报错 |

路线文字里遇到外协工种时，系统只会拿启用的供应商来配。没有可用供应商时，勾选“发现问题就停下”会直接报错；不勾选时，系统会先按 1 天提醒你后续补正。

#### 1.6.3 零件工艺路线（重点：工艺路线字符串怎么写）

**进入方式**：工艺管理 → 零件工艺模板 → 批量维护路线文字。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 图号 | 是 | 零件图号，比如 `P1001` | 为空、重复或清空重导时已有批次引用 |
| 名称 | 是 | 零件名称 | 为空 |
| 工艺路线字符串 | 是 | 工序号加工种名连着写 | 空、不是以工序号开头、尾部只有数字 |

路线文字推荐这样写：

```text
5数铣10钳20数车35标印
```

这句话表示：

| 工序号 | 工种 |
|---|---|
| 5 | 数铣 |
| 10 | 钳 |
| 20 | 数车 |
| 35 | 标印 |

写路线文字时注意：

- 必须以数字开头。
- 每个数字后面必须跟工种名。
- 可以不加分隔符，也可以加空格、逗号、顿号、箭头。
- 全角数字会转成半角数字。
- 工种没提前配置时，勾选严格检查会报错；不勾选时，系统会给出提醒并尽量生成可确认的工序。

#### 1.6.4 零件工序工时

**进入方式**：工艺管理 → 零件工艺模板 → 批量维护工序工时。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 图号 | 是 | 已存在的图号，比如 `P1001` | 图号不存在 |
| 工序 | 是 | 已存在的正整数工序号，比如 `5` | 工序不存在、0、负数、小数、`TRUE`/`FALSE`、`5e0`/`1E2` 这类科学计数法文本 |
| 换型时间(h) | 否 | 大于等于 0 的有限数字小时数；空着按 `0` 小时 | 负数、`TRUE`/`FALSE`、`NaN`、`Inf`、`Infinity`、文字 |
| 单件工时(h) | 否 | 大于等于 0 的有限数字小时数；空着按 `0` 小时 | 负数、`TRUE`/`FALSE`、`NaN`、`Inf`、`Infinity`、文字 |

换型时间是这道工序开始前准备设备、夹具、刀具的时间。单件工时是做 1 件产品要花的时间。批次数量越大，单件工时占比越大。

更直白地说：工时空着，系统就当它是 `0` 小时。这样做的好处是你可以先把路线搭起来；坏处是正式排产结果会偏短。比如某道工序换型时间填 `0.5` 小时，单件工时填 `0.2` 小时，批次数量是 `50`，这道工序预计用时就是 `0.5 + 0.2 × 50 = 10.5` 小时。如果换型和单件都空着，系统就按 `0 + 0 × 50 = 0` 小时算，现场当然不可能真的不花时间，所以正式排产前要补真实工时。

#### 1.6.5 人员基本信息

**进入方式**：人员管理 → 人员管理 → 批量维护。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 工号 | 是 | 员工编号，比如 `OP001` | 为空、重复 |
| 姓名 | 是 | 员工姓名 | 为空 |
| 状态 | 是 | 新文件建议填 `在岗` 或 `停用`；模板下拉推荐值是 `在岗/停用`；旧文件里的 `启用`、`可用`、`正常`、`休假`、`离岗` 也能兼容读取 | 空、填了系统不认识的词 |
| 班组 | 否 | 班组编号或班组名称 | 填了不存在的班组 |
| 备注 | 否 | 随便写 | 一般不报错 |

如果要在人员 Excel 里填班组，要先到 **人员管理 → 班组管理** 建好班组；否则导入会提示班组不存在。

人员不想参与排产时，优先改成停用，不要急着删除。`休假`、`离岗` 这类旧写法只是为了读懂老文件，新文件按模板下拉推荐写 `在岗` 或 `停用`。删除被历史排程引用的人员可能会被拒绝。

#### 1.6.6 设备信息

**进入方式**：设备管理 → 设备管理 → 批量维护。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 设备编号 | 是 | 设备编号，比如 `M001` | 为空、重复 |
| 设备名称 | 是 | 设备名称 | 为空 |
| 工种 | 否 | 设备能干的工种 | 工种不存在时会提示 |
| 班组 | 否 | 班组编号或班组名称 | 填了不存在的班组 |
| 状态 | 是 | 新文件建议填 `可用`、`停用`、`维修`；模板下拉推荐值是 `可用/停用/维修`；旧文件里的 `启用`、`正常`、`禁用`、`不可用`、`维护`、`维护中`、`维修中`、`保养` 也能兼容读取 | 空、填了系统不认识的词 |

设备 Excel 真实模板只有这 5 列：设备编号、设备名称、工种、班组、状态。这个模板里没有“类别”列，也没有“备注”列。设备类别要在设备页面手工新增或打开设备详情维护，不要往设备 Excel 模板里自己加“类别”或“备注”。

如果要在设备 Excel 里填班组，要先到 **人员管理 → 班组管理** 建好班组；否则导入会提示班组不存在。

设备临时不能用时，建议建停机计划或改成维修；长期不用再停用。旧状态写法只是为了读懂老文件，新文件按模板下拉推荐写 `可用`、`停用` 或 `维修`。

#### 1.6.7 人员设备关联

**进入方式**：人员管理 → 人员详情 → 可操作设备，或设备管理 → 设备详情 → 可操作人员；批量时在对应页面的批量维护里处理。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 工号 | 是 | 已存在的人员工号，比如 `OP001` | 人员不存在 |
| 设备编号 | 是 | 已存在的设备编号，比如 `M001` | 设备不存在 |
| 技能等级 | 否 | `初级`、`普通`、`熟练` | 填了系统不认识的词 |
| 主操设备 | 否 | `是` 或 `否` | 同一人员设多台主操时会被校验 |

真实例子：

| 工号 | 设备编号 | 技能等级 | 主操设备 |
|---|---|---|---|

排产时，自制工序的设备和人员下拉框会受这个关系限制。某道工序下拉没有人或没有设备时，先回这里补关系。

#### 1.6.8 工作日历

**进入方式**：排产调度 → 工作日历配置 → 批量维护。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 日期 | 是 | `2026-05-20` | 空、格式不对 |
| 类型 | 否 | 新文件建议填 `工作日` 或 `假期`；模板下拉推荐值是 `工作日/假期`；空着按 `工作日`；旧文件里的 `周末`、`节假日` 也会按假期处理 | 填了系统不认识的词 |
| 可用工时 | 否 | 大于等于 0 的有限数字小时数 | 负数、`TRUE`/`FALSE`、`NaN`、`Inf`、`Infinity`、文字 |
| 效率 | 否 | 大于 0 的有限数字 | 0、负数、`TRUE`/`FALSE`、`NaN`、`Inf`、`Infinity`、文字 |
| 允许普通件 | 否 | 新文件建议填 `是` 或 `否`；模板下拉推荐值是 `是/否`；不填默认是 | 填了系统不认识的词 |
| 允许急件 | 否 | 新文件建议填 `是` 或 `否`；模板下拉推荐值是 `是/否`；不填默认是 | 填了系统不认识的词 |
| 说明 | 否 | 备注说明 | 一般不报错 |

默认口径：

- 工作日不填可用工时，按 8 小时。
- 假期不填可用工时，按 0 小时。
- 工作日不填效率，按 1.0。
- 假期不填默认高级设置中的"假期默认效率"。
- 类型空着时按 `工作日` 算。
- 常用选项是 `工作日`、`假期`；如果旧文件里手填 `周末` 或 `节假日`，系统也按假期算。新文件按模板下拉推荐写，不要再故意写旧叫法。

#### 1.6.10 批次信息（排产核心）

**进入方式**：排产调度 → 批次管理 → 批量维护，也可以在批次管理页面手工新增。

| 列名 | 必填 | 能填什么 | 会报错的情况 |
|---|---|---|---|
| 批次号 | 是 | `B001` | 空、重复 |
| 图号 | 是 | 已存在的图号，比如 `P1001` | 图号不存在 |
| 数量 | 是 | 正整数，比如 `50` | 空、0、负数、小数、文字 |
| 交期 | 否 | `2026-05-20` | 日期格式不对 |
| 优先级 | 否 | 新文件建议填 `普通`、`急件`、`特急`；模板下拉推荐值是 `普通/急件/特急`；旧文件里的 `急` 也能兼容读取；不填默认普通 | 填了系统不认识的词 |
| 齐套 | 否 | 新文件建议填 `齐套`、`未齐套`、`部分齐套`；模板下拉推荐值是 `齐套/未齐套/部分齐套`；旧文件里的 `是`、`否` 也能兼容读取；不填默认齐套 | 填了系统不认识的词 |
| 齐套日期 | 否 | `2026-05-18` | 日期格式不对 |
| 备注 | 否 | 随便写 | 一般不报错 |

真实例子：

| 批次号 | 图号 | 数量 | 交期 | 优先级 | 齐套 | 齐套日期 | 备注 |
|---|---|---:|---|---|---|---|---|
| B001 | P1001 | 50 | 2026-05-20 | 急件 | 齐套 |  | 第一次正式排产示例 |

这句话 `B001 / P1001 / 50 / 2026-05-20 / 急件 / 齐套` 的意思是：批次 `B001`，图号 `P1001`，数量 `50`，交期 `2026-05-20`，优先排急件，目前判断为齐套。

重点纠偏：齐套日期只有在启用齐套检查时才影响排产。没启用齐套检查时，齐套状态和齐套日期主要是页面显示信息；启用后，只要所选批次里有未齐套或部分齐套，本次排产会报错并停止。系统不会自动跳过这些批次继续排其它批次；齐套日期只对齐套批次作为最早开工日。`急`、`是`、`否` 是为了兼容老文件，新批次表按模板下拉推荐写。

批次导入页还有两个重要开关：

- **导入后自动生成批次工序（推荐）**：确认写入时，系统会按零件工艺模板给批次生成工序。空库第一次导入批次时建议开启，这样导完批次就有批次工序，后面可以直接进批次详情补设备、人员和工时。
- **发现问题就停下（严格模式）**：开启后，按路线生成工序时，如果缺工种、缺供应商或外协周期不正确，会停止导入并告诉你哪一行、哪一项要补。不勾选时，能确认的数据会继续处理，缺少外协周期这类可补内容会先按 1 天记录并提醒你后续补正；但批次号、图号、数量这类必填项有问题仍然会报错。

更新已有批次时，要特别小心“导入后自动生成批次工序”。只要开启它，已有批次会按当前零件模板刷新批次工序，之前在批次详情里手工补过的设备、人员、换型时间、单件工时、供应商和外协周期，都可能被新模板重新写入或清空。已经手工细调过的批次，导入前先确认这些内容可以重新补。

如果自动生成批次工序时产生提醒，当前页面确认写入后只会展示去重后的前 3 条提醒；如果还有更多提醒，页面会显示“另有 X 条提醒未在当前页显示，请处理已展示提醒后重新检查”。所以提醒很多时，先处理当前页已经展示的提醒，再重新上传检查或重新确认。

提醒去向要分清：批次自动生成工序时的模板提醒，是当前页局部提醒，不承诺一定能在系统历史里查到；正式排产或模拟排产成功后的排产结果提醒，属于某个历史版本的结果，可以到系统历史查看。

## 2. 从空库到第一次正式排产

### 2.1 准备一个最小可排示例

下面这个示例适合你第一次跟着做：

| 内容 | 示例 |
|---|---|
| 图号 | `P1001` |
| 路线文字 | `5数铣10钳20数车35标印` |
| 批次 | `B001` |
| 数量 | `50` |
| 交期 | `2026-05-20` |
| 优先级 | `急件` |
| 齐套 | `齐套` |

你至少要准备：

- 工种：`数铣`、`钳`、`数车`、`标印`。
- 自制设备：能做 `数铣`、`钳`、`数车` 的设备。
- 人员：能操作这些设备的人。
- 人员设备关系：比如 `OP001 / M001 / 熟练 / 是`。
- 自制工序工时：每道自制工序的换型时间和单件工时。
- 如果 `标印` 是外协：要有对应外协供应商和默认周期。

### 2.2 第一次不要先正式排

先做模拟排产。模拟排产能让你看到结果，但不污染正式批次状态。你能用它检查：

- 有没有工序没设备。
- 有没有工序没人。
- 有没有工时仍然是 0，需要工艺员补成真实工时。
- 有没有外协供应商或周期缺失。
- 交期是否明显会超。
- 甘特图上有没有排到不该排的假期。

确认后再正式排产。

## 3. 基本概念：用白话理解

| 名词 | 大白话 |
|---|---|
| 工种 | 这道活是什么类型，比如数铣、钳、标印 |
| 归属 | 自制就是厂内做，外协就是交给供应商做 |
| 零件工艺模板 | 图号和工序清单，后面建批次会照它生成工序 |
| 工序 | 一件产品生产路线上拆出来的一步活，比如先数铣、再钳、再数车 |
| 批次 | 这次要生产的一批东西 |
| 批次工序 | 这个批次真实要排的每一道工序 |
| 换型时间 | 开始做之前的准备时间 |
| 单件工时 | 做 1 件花多久 |
| 齐套 | 物料够不够开工的显示状态 |
| 外协 | 这道工序不在厂内做，交给供应商做，需要供应商和外协周期 |
| 关键链 | 影响整批任务完工时间的关键任务串；这条链上某个任务晚了，整个批次通常也会跟着晚 |
| 齐套检查 | 一个排产开关；打开后只要所选批次里有未齐套或部分齐套，本次排产就会报错并停止；系统不会自动跳过这些批次继续排其它批次，齐套日期只对齐套批次作为最早开工日 |
| 排产版本 | 每次排产留下的结果编号，比如 v1、v2 |
| 模拟排产 | 只看结果，不改正式批次状态 |
| 正式排产 | 生成正式排程并更新批次状态 |

| 设备管理 | 维护设备、设备人员关系、停机计划 |
| 物料管理 | 维护物料、批次物料需求、齐套显示 |
| 排产调度 | 批次管理、排产、甘特图、周计划、资源排班、高级设置 |
| 报表中心 | 看超期、资源负荷、停机影响 |
| 系统管理 | 备份恢复、操作日志、排产历史 |

## 5. 数据准备：排产前必须做的事

### 5.1 工艺管理

#### 零件列表

入口：**工艺管理 → 零件工艺模板**。

这个页面用来维护图号、名称、路线文字和工序清单。按钮含义：

| 按钮 | 作用 |
|---|---|
| 添加零件 | 新增一个图号 |
| 批量维护 | 用 Excel 整批维护路线文字或工时 |
| 查看/编辑 | 打开零件详情，补工时和外协周期 |
| 删除 | 删除未被批次引用的零件 |
| 批量删除 | 删除勾选的零件；被批次引用会失败 |

批量删除前先确认筛选条件、已选条数和本次删除范围。

#### 零件详情（工序清单）

入口：零件列表里点 **查看/编辑**。

这个页面做三件事：

1. 改零件名称、路线文字和备注。
2. 点 **按路线重新生成工序清单**，按当前路线文字重新生成模板工序。
3. 给自制工序填换型时间、单件工时；给连续外协工序设置周期。

注意：重新生成工序清单会按路线文字重做模板。生成失败时，原工序清单不会被改动。

#### 工种配置

入口：**工艺管理 → 工种配置**。

手工新增时填工种编号、工种名称、归属和备注。归属选自制或外协。路线文字里写的工种名必须能在这里找到，排产才容易顺。

#### 供应商配置

入口：**工艺管理 → 供应商配置**。

手工新增时填供应商编号、名称、对应工种、默认周期、状态和备注。默认周期必须大于 0。状态停用的供应商不会被路线文字自动匹配。

### 5.2 人员管理

入口：**人员管理 → 人员管理**。

人员页面用来维护工号、姓名、状态、班组和备注。按钮含义：

| 按钮 | 作用 |
|---|---|
| 新增人员 | 手工加一个人 |
| 批量维护 | 用 Excel 批量维护人员、人员设备关系或个人日历 |
| 查看/编辑 | 打开人员详情 |
| 批量改状态 | 把勾选人员改成在岗或停用 |
| 批量删除 | 删除勾选人员；被引用时会失败 |

人员详情里可以维护“可操作设备”。同一人员只能有 1 台主操设备。排产时如果打开“优先推荐主操/高技能人员”，主操和熟练人员会优先被推荐。

### 班组管理

入口：**人员管理 → 班组管理**。

班组可以同时挂人员和设备。资源排班中心支持按班组查看任务，也能看班组里是按人员轴还是设备轴展开。班组不是必须项，但现场按班组管理时建议维护。

照着做：

1. 打开 **人员管理 → 班组管理**。
2. 在“新增班组”里填 **班组编号**，比如 `TEAM-01`。
3. 填 **班组名称**，比如 `车工一组`。
4. 选择 **状态**，常用选 `启用`。
5. 备注可填可不填。
6. 点 **添加班组**。
7. 新增后，下面“班组列表”会出现这条班组；如果要改班组名称、状态或备注，直接在这一行改，改完点这一行右侧 **保存**。
8. 如果要删除班组，点这一行右侧 **删除**。已经被人员或设备引用的班组会删除失败，需要先把人员或设备上的班组改掉。

人员 Excel 和设备 Excel 里的“班组”列不会自动新建班组。要在 Excel 里填班组，必须先在这里建好；Excel 里可以填班组编号，也可以填班组名称。

### 5.3 设备管理

入口：**设备管理 → 设备管理**。

设备页面用来维护设备编号、名称、工种、类别、班组、状态和备注。按钮含义：

| 按钮 | 作用 |
|---|---|
| 新增设备 | 手工加一台设备 |
| 批量维护 | 用 Excel 批量维护设备和设备人员关系 |
| 查看/编辑 | 打开设备详情 |
| 批量改状态 | 把勾选设备改成可用、维修或停用 |
| 批量删除 | 删除勾选设备；被引用时会失败 |

设备详情里可以维护“可操作人员”和停机计划。停机计划会影响排产和停机影响报表。

### 批量停机计划

入口：**设备管理 → 批量停机计划**。

这个页面可以按单台设备、按设备类别、或全部设备批量建停机。你要填开始时间、结束时间、停机原因和备注。开始和结束建议写成 `2026-05-20 08:00` 这样的格式，结束时间必须晚于开始时间。

重点纠偏：按类别或全部批量停机时，默认只作用于状态为 **可用** 的设备。已经停用或维修的设备，不会被默认批量建进去。

### 5.4 物料管理

### 物料主数据

入口：**物料管理 → 物料主数据**。

物料主数据维护物料编号、名称、规格、单位、库存数量、状态和备注。库存数量可以为 0，但不能为负数。

### 批次物料需求（齐套判定）

入口：**物料管理 → 批次物料需求（齐套判定）**。

这个页面按批次维护物料需求。选择批次后，可以新增物料、需求数量、到料数量。

- "需求数量"必须大于 0。
- 新增物料需求时，到料数量不填，系统按“到料数量等于需求数量”处理，也就是默认到齐。
- 更新已有物料需求时，到料数量不填或清空，系统会保留原来的到料数量，不会把它改成 0；如果你确实要改成 0，必须明确填 `0`。
- 到料数量填不足时，该物料行显示未齐套。
- 一个批次没有任何物料需求行时，默认按齐套显示。大白话说，就是系统没有看到缺料明细，所以先按齐套看；如果现场确实要管物料，就要把需求行补上。
- 有需求行时，系统会按到料情况自动更新齐套、部分齐套或未齐套。

再次强调：齐套状态只有在启用齐套检查时才会真正影响本次排产；只要所选批次里有未齐套或部分齐套，本次排产会报错并停止。系统不会自动跳过这些批次继续排其它批次；齐套日期只对齐套批次作为最早开工日。

### 5.5 工作日历配置

入口：**排产调度 → 工作日历配置**。

这个页面维护某一天是不是工作日、能干几小时、效率是多少、能不能排普通件或急件。

| 页面字段 | 怎么填 |
|---|---|
| 日期 | `2026-05-20` |
| 类型 | 工作日或假期 |
| 班次开始 | 默认 08:00 |
| 班次结束 | 可选；填了会参与计算 |
| 可用工时 | 工作日不填默认 8，假期不填默认 0；填写时必须是大于等于 0 的有限数字 |
| 效率 | 工作日不填默认 1.0，假期不填默认高级设置中的"假期默认效率"；填写时必须是大于 0 的有限数字 |
| 允许普通件 | 是或否 |
| 允许急件/特急 | 是或否 |

常用类型是 `工作日` 和 `假期`。类型空着时按工作日处理。如果你在 Excel 里手填 `周末` 或 `节假日`，系统也会按假期处理。

### 5.6 个人工作日历

入口：**人员管理 → 人员详情 → 个人工作日历**。

个人工作日历适合记录请假、个人加班、临时只排急件。它比全局工作日历更细。同一天既有全局日历又有个人日历时，排这个人会优先看个人日历。

个人工作日历里的可用工时必须是大于等于 0 的有限数字；效率必须是大于 0 的有限数字。`TRUE`/`FALSE`、`NaN`、`Inf`、`Infinity` 和文字都不能当作数字用。

## 6. 排产操作：完整指南

完整排产路线可以按这 6 段记：

| 段 | 入口 | 要做什么 | 完成标志 |
|---:|---|---|---|
| 1. 先建基础资料 | 工艺管理、人员管理、设备管理、排产调度 → 工作日历配置 | 工种、供应商、零件路线、工序工时、人员、设备、人员设备关系、日历都准备好 | 后面建批次时不会再提示缺工种、缺人员、缺设备或缺日历 |
| 2. 再建批次 | 排产调度 → 批次管理 | 新增或导入批次，确认图号、数量、交期、优先级、齐套状态没有填错 | 批次列表能看到要排的批次，状态通常是待排 |
| 3. 生成并补齐批次工序 | 排产调度 → 批次管理 → 点批次号或查看/编辑 | 让系统按零件工艺模板生成工序，再补设备、人员、工时、供应商和外协周期 | 批次详情里每道自制工序都有设备、人员、换型和单件工时；外协工序有供应商和周期 |
| 4. 先模拟排产 | 排产调度 → 排产调度 → 模拟排产（插单模拟） | 先试算一版，不推进正式批次状态 | 模拟成功后通常跳到甘特图，能看到刚生成的版本 |
| 5. 再正式排产 | 排产调度 → 排产调度 → 执行排产 | 确认模拟结果可用后生成正式排程 | 正式成功后回到排产调度页，最近一次排产快照能看到新版本 |
| 6. 最后复盘和下发 | 甘特图、周计划导出、资源排班、报表中心、系统管理 → 排产历史 | 看任务排布、导出现场周计划、查资源负荷和超期，必要时回看版本摘要 | 现场拿到周计划，计划员知道是否超期、哪里资源紧张、历史版本在哪里查 |

### 6.1 排产调度

入口：**排产调度 → 排产调度**。

这里列出待排、已排、加工中、已完成、已取消等批次。你可以按状态和齐套显示筛选。要排哪些批次，就勾选哪些批次。

执行前先看三件事：

1. 批次图号是否正确。
2. 批次数量和交期是否正确。
3. 批次详情里的自制工序是否补了设备、人员、换型时间、单件时间。

### 6.2 补充工序信息

入口：**排产调度 → 批次管理 → 点批次号或查看/编辑**。

手工补工序按这个顺序做：

1. 进入 **排产调度 → 批次管理**。
2. 找到要排的批次，点批次号，或点这一行的 **查看/编辑**，进入批次详情。
3. 在“批次工序（可编辑补充）”表里逐行检查。
4. 自制行要补 **设备**、**人员**、**换型（小时）**、**单件（小时）**。
5. 外协行要补 **供应商** 和 **外协周期(天)**。
6. 每一行填完，都要点这一行最右侧的 **保存**。只填表格不点这一行的保存，系统不会把这一行写进去。

设备和人员下拉受人员设备关联限制。如果某道自制工序没有可选设备或人员，先去人员管理或设备管理补“可操作关系”。如果你点 **按最新工艺模板刷新本批次工序**，本批次已补的设备、人员、工时、供应商和外协周期会被清空，需要重新检查。

### 6.3 执行排产与模拟排产

入口：**排产调度 → 排产调度**。

操作步骤：

1. 筛选出待排批次。
2. 勾选要排的批次。
3. 填排产开始时间；不填时，默认明天 08:00。
4. 如有需要，填排产截止日期。
5. 按本次要求勾选或取消 **本次启用齐套检查**。日常不想让齐套挡住排产时可以不勾；这次必须确认物料齐套才能开工时再勾。
6. 勾选或取消 **发现参数问题就停止排产**。勾上以后，关键参数有问题会直接停下；不勾时，能用默认值补齐的项目会先继续跑，并在结果里提醒你。
7. 先点 **模拟排产（插单模拟）**。
8. 模拟成功后通常会跳到 **甘特图**，先核对版本号，再看任务有没有排到不该排的日期、设备或人员。
9. 没问题后，回 **排产调度 → 排产调度**，再点 **执行排产**。
10. 正式成功后通常会回到 **排产调度** 页，方便你看批次状态和“最近一次排产快照”。

模拟排产和正式排产都会生成排产版本。区别是：模拟排产不影响批次正式状态；正式排产会把结果作为正式排程使用。

排产成功后，如果系统生成提醒，页面只展示前 5 条。提醒很多时，不代表后面的提醒不存在；先处理页面已经展示的提醒，再回到排产调度重新模拟或重新执行。

排产跑完后，先按页面提示判断是哪种结果：

| 结果 | 页面上通常怎么看 | 代表什么 | 下一步 |
|---|---|---|---|
| 成功 | 绿色成功提示，生成新版本，批次数和工序数有数值 | 系统保存了可查看的排产结果 | 看甘特图、周计划、资源排班和报表 |
| 部分完成 | 黄色提醒或“部分完成”，有版本，但同时有提醒或部分数据需要复核 | 系统保存了能确认的结果，但有些工序、资源、提醒需要人工看 | 先看页面展示的提醒，再去排产历史看完整摘要；必要时补资料后重新模拟 |
| 失败 | 红色错误提示，没有可用新版本，或提示缺少必要数据 | 这次没有形成可正常使用的结果 | 按错误提示补批次、工序、设备、人员、工时、日期或齐套状态后重试 |
| 无可保存结果 | 明确提示“本次排产没有生成可保存结果” | 系统没有排出能保存的任务，常见原因是自制工序缺设备、缺人员，或关键工时/时间数据不合法 | 回批次详情逐行补齐设备、人员、换型时间、单件工时；确认每行点了保存后再排 |

常见报错：

| 报错 | 大白话解释 | 怎么处理 |
|---|---|---|
| 请至少选择 1 个批次执行排产 | 没勾批次 | 勾选批次 |
| 以下批次未齐套，禁止排产 | 启用了齐套检查，批次不是齐套 | 补物料或关闭齐套检查 |
| 所选批次没有可重排工序 | 批次没有能排的工序 | 回批次详情生成或检查工序 |
| 本次排产没有生成可保存结果，存在自制工序缺设备/人员 | 有自制工序没补设备或人员；如果工时是负数、不是数字、不是有限数字，也会导致排不出可保存结果。工时空着会按 0 处理，但正式排产前仍建议补成真实工时 | 回 **批次管理 → 批次详情**，把自制行的设备、人员、换型时间、单件工时补齐，每一行点右侧 **保存** 后再排 |
| 开始时间格式不合法 | 时间写法不对 | 写 `2026-05-20 08:00` |
| 结束日期不能早于开始时间所在日期 | 排产截止比开始还早 | 调整日期 |

### 6.4 甘特图

入口：**排产调度 → 甘特图**。

甘特图用条形图看排程。可以切换设备视图和人员视图，也可以按周、指定日期范围、指定版本查看。

页面上常用控件：

| 控件 | 作用 |
|---|---|
| 设备视图/人员视图 | 按设备或人员分行看任务 |
| 上周/本周/下周 | 快速换周 |
| 排产区间起止 | 看自定义日期范围 |
| 版本 | 看某一次排产版本 |
| 时间粒度 | 日视图、周视图、月视图 |
| 配色 | 按批次、优先级、归属、工序状态配色 |
| 批次筛选/资源筛选 | 只看某批次或某设备、某人员 |
| 仅超期 | 只显示超期任务 |
| 仅外协 | 只显示外协任务 |
| 高亮关键链 | 标出影响总工期的关键任务 |

红色边框表示该批次在该版本里被判定为超期。工作日历加载失败时，页面会提示暂时不显示假期或停工背景。

**版本不存在** 要和 **甘特图空白** 分开看。

版本留空、版本填 `latest`，通常表示看最新排产历史。你手工填了不存在的版本号时，页面会提示类似“排产版本不存在”或“无对应排产历史”，不会偷偷改看最新版本。这时不要按“甘特图空白”处理，先换成下拉框里的已有版本，或把版本改成空 / `latest`。

如果已经选到一个存在的版本，但图上还是空白，再按这几件事排查：

1. **日期范围没覆盖任务**：任务排在别的周或别的日期区间，当前范围内就会空白。
2. **筛选条件太窄**：只看某个批次、设备、人员、仅超期或仅外协时，可能把任务过滤没了。
3. **本次排产没有保存出可用结果**：比如自制工序缺设备、缺人员，或正式排产没有成功保存。
4. **选择了另一种视图**：设备视图看设备，人员视图看人员；如果某类资源没有任务，对应视图里也会少。
5. **系统还没有任何排产历史**：页面会提示先去执行排产。先模拟或正式排一版，再回来看甘特图。

### 6.5 周计划导出

入口：**排产调度 → 周计划导出**。

周计划用于把一周内任务给现场复核。页面字段包括日期、批次号、图号、工序、设备、人员、时段。跨天工序会按天拆成多行。

页面上常用按钮和筛选：

| 控件 | 怎么用 |
|---|---|
| 去执行排产 | 回到排产调度页，重新模拟或正式排产 |
| 排产区间（起）/排产区间（止） | 指定要看的日期范围 |
| 指定周 | 填任意一天，系统会按这一周查看 |
| 版本 | 选择要导出的排产版本，避免把模拟版和正式版拿错 |
| 查询 | 改完日期或版本后点它，页面预览会刷新 |
| 导出周计划表.xlsx | 把当前版本、当前日期范围内的完整周计划导出成 Excel |

重点纠偏：页面只预览前 50 行，并显示总行数。完整周计划以 **导出周计划表.xlsx** 为准。

也就是说，页面预览是给你快速扫一眼用的：看列对不对、日期对不对、有没有明显漏任务。真正要发给现场或留档时，要点导出，导出的 Excel 才包含完整周计划。

### 6.6 资源排班中心

入口：**排产调度 → 资源排班**。

资源排班可以按三种视角看：

| 视角 | 适合看什么 |
|---|---|
| 人员 | 某个人这段时间排了什么活 |

区间类型有按周、按月、自定义。重点纠偏：自定义日期范围最多 62 天；查更长时间要分段查。

页面上常用按钮和筛选：

| 控件 | 怎么用 |
|---|---|
| 去执行排产 | 回到排产调度页，重新生成版本 |
| 视角 | 选人员、设备或班组 |
| 人员/设备/班组 | 按你选的视角继续选具体对象 |
| 班组轴 | 选班组时再决定按人员轴还是设备轴展开 |
| 区间类型 | 选按周、按月或自定义 |
| 查询日期/开始日期/结束日期 | 决定要看哪段时间 |

页面里有任务明细、日历矩阵、甘特图三个视图。导出前一定先确认版本、视角、资源和日期范围；导出的不是全部历史，而是当前查询结果。

### 6.7 排产优化分析

入口：**排产调度 → 排产优化分析**。

这个页面主要看当前排产结果的汇总指标，比如总工期、超期批次数、拖期小时、设备平均利用率、人员平均利用率。它适合用来比较不同方案或不同版本哪个更好。

版本口径和其他排产结果页面一致：不填版本、版本为空，或版本填 `latest`，都会查看最新的历史排产版本。输入不存在的数字版本时，页面会保留这个版本号并提示没有找到，不会自动改看最新；输入 `abc` 这类不是数字的版本号会报“版本号不对”。

如果发现超期很多，先回看：

- 甘特图红框是不是集中在某个设备或人员。
- 资源负荷里是否某些资源利用率特别高。
- 工作日历是否漏了加班或误设假期。
- 批次优先级和交期是否填错。

## 7. 高级设置：每个开关的作用

入口：**排产调度 → 高级设置**。

日常建议先用常用方案。确实要调时，再看下面这些字段。

| 设置 | 大白话解释 |
|---|---|
| 排产策略 | 决定先排急件、先排交期近的，还是综合看 |
| 优先级权重 | 数值越大，越照顾急件和特急件 |
| 交期权重 | 数值越大，越照顾交期近的批次 |
| 假期工作效率 | 假期安排生产但没单独填效率时用它 |
| 默认启用齐套检查 | 关闭时齐套只显示；打开后只要所选批次里有未齐套或部分齐套，本次排产就会报错并停止；系统不会自动跳过这些批次继续排其它批次，齐套日期只对齐套批次作为最早开工日 |
| 优先推荐主操/高技能人员 | 补工序时更偏向主操和熟练人员 |
| 未指定设备或人员时，系统自动分配 | 自制工序缺设备或人员时，允许系统帮你补 |
| 派工方式 | 按批次顺序排，或由系统自动挑更合适的任务 |
| 智能派工策略 | 只在智能派工时生效 |
| 计算模式 | 快速计算或精细计算 |
| 计算时间上限 | 精细计算最多算多久 |
| 深度优化 | 精细计算时额外尝试更好的排法 |
| 锁定近期排程 | 复用上一版本近期排程，减少现场波动 |
| 锁定天数 | 锁定近期排程的天数 |

常用动作：

- **切换方案**：换成系统已有或你保存过的方案。
- **保存为方案**：把当前设置保存成一个名字，方便以后复用。方案名称不要超过 50 个字。
- **删除方案**：只删保存的方案，不删批次、工艺、设备、人员和历史排程。
- **保存当前设置**：保存页面上的参数。
- **恢复默认**：把页面参数恢复成系统初始设置。

## 8. 算法选择：怎么判断结果好不好

不用先懂算法。第一次用时建议：

1. 批次少、只想快速看结果：用快速计算。
2. 批次多、想多试几种排法：用精细计算。
3. 交期很重要：策略选交期优先，或提高交期权重。
4. 急件很重要：策略选优先级优先，或提高优先级权重。
5. 现场排程不想天天大变：打开锁定近期排程。

判断结果好不好，先看三件事：

- 超期批次数有没有降。
- 总拖期小时有没有降。
- 甘特图上关键设备和关键人员是否被挤爆。

## 9. 报表中心

入口：**报表中心**。

报表中心有三张常用表：超期清单、资源负荷与利用率、停机影响统计。

报表中心先记住一个总规则：改完筛选条件后要点 **查询**，有数据时再点 **导出 Excel**。导出的都是当前报表、当前版本、当前日期范围下的结果，不是完整数据库，也不能拿来恢复排产版本。

### 9.1 超期清单

入口：**报表中心 → 超期清单**。

超期清单按排产版本查看。已排程超期是完工时间晚于交期；未排程超期是到当前截至时间还没完工，并且已经过了交期。

页面操作：

| 控件 | 怎么用 |
|---|---|
| 排产版本 | 选择要查看的版本；别人给你版本号时，先确认下拉框里确实有这一版 |
| 查询 | 按当前版本刷新超期结果 |
| 导出 Excel | 有超期数据时可用，导出当前版本的超期清单 |

表格列：

| 列 | 意思 |
|---|---|
| 类别 | 已排程逾期或未排程逾期 |
| 批次号 | 哪个批次 |
| 图号 | 哪个产品 |
| 名称 | 零件名称 |
| 数量 | 批次数量 |
| 交期 | 应该完成的日期 |
| 完工/截至时间 | 已排程看完工时间，未排程看截至时间 |
| 超期(天) | 超了多少天，可以是小数天 |
| 超期(小时) | 超了多少小时 |

重点纠偏：报表里的超期天数是小数天，不是只取整天。比如超 12 小时，会显示约 0.5 天。

筛选和导出边界：页面筛选按你当前选择的版本来算；导出时导出的也是当前筛选结果，不是自动导出系统里所有历史超期记录。要导另一个版本，先改版本并点查询，再导出。

### 9.2 资源负荷与利用率

入口：**报表中心 → 资源负荷与利用率**。

这个页面按排产版本和日期范围看设备、人员的负荷。

页面操作：

| 控件 | 怎么用 |
|---|---|
| 排产版本 | 选择要统计的版本 |
| 开始日期/结束日期 | 选择要统计的日期范围；页面有时会按所选版本自动带出排程范围 |
| 查询 | 按当前版本和日期范围刷新设备、人员负荷 |
| 导出 Excel | 有设备或人员负荷数据时可用，通常会带出设备和人员两个工作表 |

| 列 | 意思 |
|---|---|
| 负荷(小时) | 这段时间排给它的任务小时数 |
| 任务数 | 这段时间有几条任务 |
| 可用工时(小时) | 这段日期里单个资源的可用工时口径 |
| 利用率(%) | 负荷小时除以可用工时后转成百分比 |

重点纠偏：资源负荷与利用率不展示完全没任务的资源。某台设备或某个人这段时间一条任务都没有，就不会出现在设备负荷或人员负荷表里。

筛选和导出边界：这个报表只统计当前版本、当前日期范围内有任务的资源。导出表不会补上完全没任务的设备或人员；如果你要查另一个版本或日期范围，先在页面上改筛选并点查询，再导出。

### 9.3 停机影响统计

入口：**报表中心 → 停机影响统计**。

这个页面按版本和日期范围统计设备停机，以及停机是否和已排任务重叠。

页面操作：

| 控件 | 怎么用 |
|---|---|
| 排产版本 | 选择要对比的排产版本 |
| 开始日期/结束日期 | 选择要统计的停机日期范围 |
| 查询 | 按当前版本和日期范围刷新停机影响 |
| 导出 Excel | 当前范围有停机影响结果时可用，导出当前查询结果 |

| 列 | 意思 |
|---|---|
| 设备编号/设备名称 | 哪台设备 |
| 停机时长(小时) | 停机总小时数 |
| 停机次数 | 有几段停机 |

筛选和导出边界：停机影响按当前版本和日期范围统计。导出的是当前查询结果，不会把未筛进来的日期、设备或其它版本一起带出去。它也不是停机台账备份，不能用来恢复停机计划。

## 10. 系统维护

### 10.1 备份与恢复

入口：**系统管理 → 备份/恢复**。

这个页面可以手动备份、恢复数据、清理过期备份，也能切换现代/经典界面。

按钮含义：

| 按钮 | 作用 |
|---|---|
| 手动备份 | 立即保存一份当前数据库 |
| 清理过期备份 | 按保留天数清理旧备份 |
| 批量删除选中 | 删除勾选的备份，删除后不能恢复 |
| 恢复 | 用某个备份覆盖当前系统数据 |
| 删除 | 删除单个备份 |

恢复会覆盖当前数据。恢复前系统会自动生成一份“恢复前自动备份”。如果恢复过程失败，系统会尝试恢复到这份备份。

备份文件名由系统自动按时间生成，不需要你自己起名。常见样子是 `aps_backup_20260508_153012.db`，中间那串数字就是生成时间；恢复前自动备份会在文件名后面带 `before_restore`，方便你知道它是恢复动作开始前留下的保护备份。

重点纠偏：恢复成功的完整口径是 **已从备份恢复并完成结构校验**。只看到“文件已复制”还不算完整成功；恢复后结构校验失败时，不要继续当作恢复成功使用。

### 10.2 操作日志

入口：**系统管理 → 操作日志**。

操作日志用来查什么时候、哪个模块做了什么动作，以及操作目标或结果说明。可以按开始时间、结束时间、模块、动作、日志级别、查看条数筛选。

查看条数默认是最近 50 条，可填 1 到 500。批量删除前先确认筛选条件、已选条数和本次删除范围。

### 10.3 排产历史

入口：**系统管理 → 排产历史**。

每次执行排产或模拟排产都会生成一个版本。历史页可以按版本或最近记录条数查询，能看到版本、时间、排产方式、结果、批次数、工序数、摘要和提醒。

历史页主要用于追溯和复盘。这里能做的事是：查看版本摘要、按版本搜索、按最近记录条数分页查看、看结果概况和提醒。这里不能导出版本，也不能恢复某个排产版本；排产历史不是备份恢复功能。想看具体每道工序排在哪天、哪台设备、哪个人员，请去甘特图、周计划或资源排班中心。

## 12. 常见问题

### 齐套日期为什么没影响排产？

先看高级设置里是否启用了“默认启用齐套检查”，或本次排产页面是否勾选启用齐套检查。没启用时，齐套日期只做显示；启用后，齐套日期只对齐套批次作为最早开工日。如果同一次选择的批次里有未齐套或部分齐套，系统会先报错并停止本次排产，不会自动跳过这些批次继续排其它批次。

### 工作日历填了周末为什么变成假期？

这是当前规则。模板常用项是工作日和假期，但手填周末、节假日也按假期处理。

### 为什么资源负荷表里找不到某台设备？

资源负荷与利用率只汇总有任务的资源。完全没任务的设备或人员不会显示。

### 周计划页面怎么只有 50 行？

页面只是预览前 50 行，完整内容要点导出周计划表。

### 批量停机为什么没给停用设备建停机？

按类别或全部批量停机时，默认只作用于可用设备。停用、维修设备默认不在批量范围里。

### 利用率超过 100% 一定错吗？

不一定，但要检查。它表示排程负荷超过可用工时，可能是日历没配好，也可能是任务确实太挤。
