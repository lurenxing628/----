# 说明书可用性审校执行记录

- 执行日期：2026-05-11
- 审校对象：主说明书、镜像说明书、页面帮助卡、页面可见提示、相关回归测试
- 当前定位：这份文件记录本轮已经按审校建议落地的结果，供后续复查和交接使用

## 1. 本轮处理背景

这次审校的起点不是“补一篇新文档”，而是把已有说明书和真实页面重新对齐。原始建议里指出了三类问题：

1. 新手刚进入系统时，先看到操作步骤，后看到概念解释，理解顺序不够友好。
2. 同一个功能在主说明书、页面帮助卡、模板提示里有不同说法，现场人员容易以为是不同功能。
3. 一些页面已经具备入口、反馈和保护机制，但说明书没有把“怎么做、看到什么算完成、做错了怎么退回”讲清楚。

本轮修改按“先核实页面事实，再改说明书，再补测试”的顺序执行，避免把已经存在的功能误写成缺功能。

## 3. 已修正的关键事实

### 3.1 排产页默认状态

当前 `/scheduler/` 不带状态参数时，默认显示待排批次。只有用户主动选择“全部”或其它状态时，排产面板和勾选框才可能隐藏。

说明书现在按这个真实规则写，不再把默认状态说错。

### 3.2 模拟排产和正式排产

模拟排产会生成一个可查看版本，方便先看甘特图和结果；但它不会把批次改成已排。

所以说明书现在明确提醒：模拟排产后如果要正式排产，需要回到执行排产页重新勾选批次。

### 3.3 齐套检查

齐套资料默认是显示和参考信息。只有本次排产启用齐套检查，或系统高级设置默认启用时，未齐套和部分齐套批次才会挡住排产。

启用后不是自动跳过问题批次，而是整次停止，让操作人员先处理齐套状态。

### 3.4 周计划和导出

周计划页面只预览前 50 行，是为了避免页面太长；导出文件会按当前查询范围导出完整结果。

说明书现在把“页面预览”和“导出文件”分开讲，避免用户以为只导出了前 50 行。

### 3.5 排产历史边界

排产历史用于查看版本、结果和摘要，不承担数据库恢复功能。

需要恢复数据库时，去系统管理里的备份页面；报表导出也不能当作数据库备份使用。

### 3.6 资源排班任务明细

资源排班页面实际表头包含：

| 列 | 用途 |
|---|---|
| 开始 | 任务开始时间 |
| 结束 | 任务结束时间 |
| 批次号 | 对应批次 |
| 图号 | 产品图号 |
| 工序编码 | 系统生成的工序编码 |
| 工序 | 工序号 |
| 查询对象 | 当前视角正在看的人员、设备或班组 |
| 对应资源 | 与查询对象配合的设备或人员 |
| 班组关系 | 是否属于当前查询班组 |
| 来源 | 自制或外协 |
| 状态 | 锁定、超期、跨天等标签 |

本轮已把说明书和页面帮助卡都改成 11 列。

## 4. 新增和强化的验收

本轮不只改文字，还补了回归检查：

1. 主说明书和镜像说明书必须完全一致。
2. 页面帮助卡不能再出现旧页面名、旧算法名、旧字段名和容易误导的说法。
3. 排产调度默认待排、模拟排产后需要重新勾选、齐套检查启用后整次停止，这些规则都由测试守住。
4. 周计划预览 50 行、导出完整数据的口径由测试守住。
5. 资源排班任务明细必须包含“查询对象”列。
6. 新增的高风险回归测试已纳入质量门禁清单，后续不会只靠人工记忆。

## 5. 对项目的影响

这次修改对项目的影响主要在用户理解和后续维护：

1. 现场操作人员按说明书走流程时，更容易知道先做什么、后做什么、什么情况算完成。
2. 页面帮助卡和主说明书说法更一致，减少“这个页面是不是另一个功能”的误解。
3. 排产、齐套、周计划、资源排班这些高频页面的边界更清楚，减少误操作。
4. 测试覆盖了这批文案和页面事实，后续再改页面时更容易发现说明书漂移。

## 6. 后续复查建议

后续如果继续改说明书，建议按这条路线复查：

1. 先看页面真实按钮、表头和提示。
2. 再改主说明书。
3. 同步改对应页面帮助卡。
4. 最后补测试，确保主说明书、镜像说明书和页面帮助卡不会再次分叉。
