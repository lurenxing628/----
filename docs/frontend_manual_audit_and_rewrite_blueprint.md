## 2. 说明口径红线表

| 不要这样写 | 推荐这样写 | 为什么 |
|---|---|---|
| 系统自动考虑所有限制并保证全局最优 | 系统按已维护资料尽量排出可用方案，精细计算会多试几种排法，但不保证唯一最优 | 当前不是全量 APS/CP 全局最优系统 |
| 未齐套批次一定不参与排产 | 只有本次启用齐套检查时，未齐套或部分齐套才会挡住本次排产 | 齐套默认主要是页面显示信息 |
| 系统会自动跳过缺料批次继续排其它批次 | 启用齐套检查且选中未齐套/部分齐套批次时，本次排产会报错并停止 | 当前行为不是自动跳过 |
| 物料库存会自动扣减 | 物料模块用于登记需求和到料数量，帮助判断齐套状态 | 当前不能写成库存扣减系统 |
| 供应商产能会参与排产 | 外协主要按周期天数处理，不写成会计算供应商产能 | 避免夸大外协能力 |
| 备份文件由用户按日期和用途命名 | 备份文件名由系统生成，用户根据时间和用途后缀识别 | 页面没有命名输入框 |
| 停机时间可以直接缩短或延长 | 如果停机时间填错，先取消原停机，再按正确时间新建，也就是取消后重建 | 页面没有编辑停机时间入口 |
| 历史页可以导出或恢复版本 | 历史页只看版本摘要和结果概况；导出看周计划/甘特图/报表，恢复走备份 | 避免把历史页当备份恢复 |
| 模拟排产结果可以直接发现场执行 | 模拟用于复核方案；正式执行排产后的版本才建议发现场 | 模拟不推进批次/工序状态 |
| 保存补齐资源是用户可直接改的高级开关 | 如果页面显示“保存补齐资源”，它只是展示系统补齐资源是否回写；不引导用户找隐藏字段 | `auto_assign_persist` 是隐藏配置 |

## 3. Excel 推荐值、兼容旧写法和内部口径

### 3.1 总原则

- 用户新填 Excel 时，只写模板下拉推荐值。
- 旧文件兼容值只用于说明“老数据能尽量读懂”，不要写成推荐。
- 英文底层值、宽松别名、落库值只适合内部维护人员知道，不要放到普通页面帮助里抢主线。

### 3.2 字段口径表

| 字段 | 新模板推荐值 | 兼容旧写法 | 仅内部知道 |
|---|---|---|---|
| 人员状态 | `在岗`、`停用` | `启用`、`可用`、`正常` 按在岗；`休假`、`离岗`、`停用/休假` 按停用 | `active`、`inactive` |
| 设备状态 | `可用`、`停用`、`维修` | `启用`、`正常` 按可用；`禁用`、`不可用` 按停用；`维护`、`维护中`、`维修中`、`保养` 按维修 | `active`、`inactive`、`maintain` |
| 工种归属 | `自制`、`外协` | `内部`、`外部` 可以兼容，但不要放在推荐值前面 | `internal`、`external`，以及更宽的别名 |
| 批次优先级 | `普通`、`急件`、`特急` | `急` 按急件兼容 | `normal`、`urgent`、`critical` |
| 批次齐套 | `齐套`、`未齐套`、`部分齐套` | `是` 按齐套，`否` 按未齐套 | `yes`、`no`、`partial` |
| 工作日历类型 | `工作日`、`假期` | `周末`、`节假日` 按假期理解 | `workday`、`holiday`、`weekend`；落库只保留工作日/假期含义 |

### 3.3 正式模板表头

| 模板 | 表头 | 说明口径 |
|---|---|---|
| 人员基本信息 | 工号、姓名、状态、班组、备注 | 状态推荐 `在岗 / 停用` |
| 人员设备关联 | 工号、设备编号、技能等级、主操设备 | 主操设备填 `是 / 否` |
| 人员专属工作日历 | 工号、日期、类型、班次开始、班次结束、可用工时、效率、允许普通件、允许急件、说明 | 类型推荐 `工作日 / 假期` |
| 设备信息 | 设备编号、设备名称、工种、班组、状态 | 没有“设备类别”和“备注”列 |
| 设备人员关联 | 设备编号、工号、技能等级、主操设备 | 和人员设备关联方向不同，别混用 |
| 工种配置 | 工种ID、工种名称、归属 | 归属推荐 `自制 / 外协` |
| 供应商配置 | 供应商ID、名称、对应工种、默认周期、状态、备注 | 状态推荐 `启用 / 停用` |
| 零件工艺路线 | 图号、名称、工艺路线字符串 | 路线文字要能匹配工种 |
| 零件工序工时 | 图号、工序、换型时间(h)、单件工时(h) | 工时要能转成有效数字 |
| 批次信息 | 批次号、图号、数量、交期、优先级、齐套、齐套日期、备注 | 优先级和齐套使用新模板三档推荐值 |
| 工作日历 | 日期、类型、可用工时、效率、允许普通件、允许急件、说明 | 没有“班次开始/班次结束”列 |

## 5. 完整排产流程验收表

这段不是说“首页现在缺路线”，而是给以后验收完整路线是否倒退用。

| 步骤 | 去哪个页面 | 要做什么 | 检查什么 | 常见错误 |
|---|---|---|---|---|
| 1 | 系统管理 -> 备份/恢复 | 正式数据先手动备份 | 备份列表出现系统生成的新文件 | 误以为能手工命名备份 |
| 2 | 工艺管理 -> 工种配置 | 建工种并区分自制/外协 | 路线文字里的工种都能匹配 | 把内部/外部当新推荐值 |
| 3 | 工艺管理 -> 供应商配置 | 给外协工种建供应商和默认周期 | 外协工种有启用供应商 | 写成供应商产能参与排产 |
| 4 | 工艺管理 -> 零件工艺路线 | 给图号维护路线文字 | 路线顺序和现场工艺一致 | 工种名称写错导致后续生成失败 |
| 5 | 工艺管理 -> 零件工序工时 | 给自制工序维护换型和单件工时 | 工时为有效数字 | 空值或非法数字导致排不出可用结果 |
| 6 | 人员管理 / 设备管理 | 维护人员、设备、状态、班组和可操作关系 | 自制工序能选到人员和设备 | 人员停用或设备维修还期待参与排产 |
| 7 | 排产调度 -> 工作日历 | 维护节假日、加班、效率、急件限制 | 类型使用工作日/假期 | 把工作日历 Excel 当作有班次开始/结束 |
| 8 | 物料管理 | 需要管缺料时维护物料需求和到料数量 | 齐套显示符合现场 | 误以为库存自动扣减 |
| 9 | 排产调度 -> 批次管理 | 新增或批量维护批次 | 批次号、图号、数量、交期、优先级、齐套正确 | 旧值兼容写法当新模板推荐 |
| 10 | 批次详情 | 生成并补齐批次工序 | 自制行有设备/人员/工时；外协行有供应商/周期 | 刷新工序后覆盖手工补充信息 |
| 11 | 高级设置 | 日常优先用默认，特殊目标再调整 | 齐套检查、自动分配等符合本次目的 | 找隐藏字段或乱改策略 |
| 12 | 排产调度 | 先模拟排产 | 红色失败、黄色提醒、结果版本都看清 | 把模拟结果直接发现场 |
| 13 | 甘特图 / 资源排班 / 分析 / 报表 / 周计划 | 复核模拟结果 | 超期、冲突、空态、冻结窗口、导出边界 | 空白图直接当系统坏了 |
| 14 | 排产调度 -> 正式执行 | 确认后正式排产 | 正式版本可用于周计划等输出 | 未修基础资料就反复重排 |

## 6. 排产能力和失败提醒验收表

### 6.1 系统会考虑什么

| 能力 | 用户该怎么理解 | 影响排产吗 | 资料来源 |
|---|---|---|---|
| 批次工序顺序 | 同一批次前一道没结束，后一道不会先开始 | 会 | 批次详情、零件工艺路线 |
| 设备占用 | 同一台设备同一时间只能排一个自制任务 | 会 | 设备、批次工序 |
| 人员占用 | 同一个人同一时间只能排一个自制任务 | 会 | 人员、人员设备关系、批次工序 |
| 工作日历 | 哪天上班、可用几小时、效率多少会影响时间 | 会 | 全局工作日历、个人工作日历 |
| 设备停机 | 停机资料加载成功时，系统会避开停机窗口 | 会 | 设备详情、批量停机计划 |
| 工时 | 换型时间和单件工时影响任务长度 | 会 | 零件工序工时、批次详情 |
| 外协周期 | 外协工序主要按周期天数往后推 | 会 | 供应商、零件详情、批次详情 |
| 齐套检查 | 只有启用后才会挡住未齐套/部分齐套批次 | 条件影响 | 批次信息、物料需求、排产选项 |

### 6.2 系统当前不会自动做什么

| 不会自动做的事 | 正确解释 | 用户应该做什么 |
|---|---|---|
| 不保证全局最优 | 系统尽量排可用方案，不承诺唯一最佳 | 用模拟多比较，人工复核 |
| 不自动扣物料库存 | 物料只帮助判断齐套 | 维护需求数量和到料数量 |
| 不自动跳过缺料批次继续排 | 启用齐套检查且选中缺料批次会报错停止 | 补齐物料、取消勾选或关闭本次检查 |
| 不计算供应商产能 | 外协主要按周期天数处理 | 维护供应商和周期，不写成产能排程 |
| 不自动知道法定假期 | 没维护就不会凭空知道 | 在工作日历或个人日历里维护 |
| 不直接编辑停机时间 | 页面只有新增和取消 | 填错就取消后重建 |

### 6.3 失败和提醒

| 情况 | 页面可能怎么提示 | 能不能继续用 | 应该去哪修 |
|---|---|---|---|
| 自制工序缺设备或人员 | 没有生成可保存结果、缺设备/人员 | 不能当可用排产结果 | 批次详情、人员/设备关系 |
| 工时非法 | 工时不是有效数字或无法排出结果 | 不能当可用排产结果 | 零件工序工时、批次详情 |
| 启用齐套检查且有未齐套/部分齐套 | 未齐套禁止排产 | 本次停止 | 物料需求、批次齐套状态、排产选项 |
| 版本不存在 | 找不到指定版本 | 不能当普通空白 | 回版本下拉或历史页确认 |
| 黄色提醒 | 结果需要复核 | 不一定失败，但不要盲目发现场 | 按提醒类型回对应页面修资料 |
| 部分成功 | 有些记录成功，有些跳过或失败 | 必须复核影响范围 | 看页面提示和错误明细 |

## 7. 已收口与后续验收清单

| 状态 | 哪块 | 为什么要守住 | 验收标准 |
|---|---|---|---|
| 已收口 | 人员状态推荐值 | 新模板推荐值写错会直接误导 Excel 填写 | 页面帮助和蓝本都只把 `在岗 / 停用` 写成推荐 |
| 已收口 | 备份文件命名 | 错写成用户能命名，会误导恢复定位 | 说明写成系统生成，按时间和用途后缀识别 |
| 已收口 | 停机时间口径 | 写“缩短/延长”会让用户找不到按钮 | 写成“取消后重建” |
| 已收口 | 齐套检查触发条件 | 少写触发条件会让用户误解排产失败 | 必须写“启用齐套检查且选中未齐套/部分齐套” |
| 已收口 | 历史页导出/恢复边界 | 把历史页写成恢复入口风险大 | 明确恢复走备份，导出看周计划/甘特图/报表 |
| 已收口 | 首页统计卡 | 用户容易把数字理解成可直接改数据 | 每张卡写清含义和下一步，已排批次按批次状态解释 |
| 已收口 | 优化分析冻结窗口 | 字段较专业，用户不容易理解 | 用大白话解释它只是结果说明和稳定性提示 |
| 已收口 | 周计划空态 | 用户容易把空态都理解为系统坏 | 分清无历史、版本不存在、区间无任务、坏时间过滤 |
| 已收口 | 主说明书和镜像生成链路 | 两份说明书一旦不同，用户看到的内容就会不一致 | 本轮保持两份文件完全一致；后续可单独做自动同步脚本 |
| 后续另开 | Excel 模板填写说明工作表 | 能降低现场填表成本，但会改变真实模板交付物 | 另开任务，不能只写在蓝本里 |

## 8. 测试和验收要求

### 8.1 本蓝本自身合同

新增或维护 `tests/regression_frontend_manual_blueprint_contract.py`，至少锁住：

- 本文件必须声明自己是内部蓝本，不是最终用户说明书。
- 必须出现 `已覆盖`、`仍需补强`、`需修正`、`需核实` 四类，其中“仍需补强”只能放后续可打磨项，不能把已收口内容写成当前待办。
- 首页路线、结果页主要说明、工艺说明补强不能再写成旧的当前缺口。
- Excel 必须区分“新模板推荐值”“兼容旧写法”“仅内部知道”。
- 必须包含备份系统生成文件名、停机取消后重建、人员状态推荐值、齐套检查边界、历史页不能导出/恢复这些红线。
- 不能出现会误导用户的旧表达，比如“系统保证全局最优”“物料库存会自动扣减”“历史页可以恢复版本”。

### 8.2 现有守护

| 测试 | 主要守什么 |
|---|---|
| `tests/regression_excel_template_contracts.py` | 页面说明、整本说明书、真实 Excel 模板表头和下拉值一致 |
| `tests/regression_frontend_ui_language_polish.py` | 前端说明和页面文案里推荐值、兼容旧写法、通俗表达不倒退 |
| `tests/regression_page_manual_registry.py` | 页面说明主题、页面入口、锚点、速览卡和关键事实口径 |
| `tests/regression_config_manual_markdown.py` | 整本说明书、镜像说明书、页面/整本模式、Markdown 口径 |
| `tests/regression_manual_entry_scope.py` | “本页说明”入口、弹层、页面级说明、下载和链接安全 |

### 8.3 建议执行命令

## 9. 子代理执行与验收要求

后续继续做说明书大改时，默认按这个分工执行：

| 阶段 | 子代理分工 | 输出 |
|---|---|---|
| 只读核实 | 蓝本结构、页面说明、Excel 模板、已收口口径、结果页薄点、测试守护、主/镜像说明书关系 | 每组输出证据和不确定项 |
| 写入 | 改文档的人只改蓝本或说明书；改测试的人只改测试；不要多人同时改同一文件 | 小范围补丁 |
| 主代理收敛 | 统一口径、删掉证据不足内容、避免范围外改动 | 可执行交付 |
| 对抗验收 | 一个查事实是否准，一个查旧诊断口吻是否残留 | 修正清单或可以收口的结论 |

证据不足时必须写“证据不足”，不要为了让清单好看而硬凑结论。
