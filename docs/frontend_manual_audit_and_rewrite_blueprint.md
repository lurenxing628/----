# 前端页面说明书现状核查与改写蓝本（极细颗粒度版）

> 用途：本文件汇总本次只读扫描得到的全部结论，供后续改写前端各页面“本页说明”和整本系统说明书时使用。
> 面向读者：计划调度员、工艺员、系统维护人员。
> 改写目标：让使用者能按照说明一步一步完成一次完整排产，知道表格怎么填、能填什么、什么会报错、按钮点了有什么用、结果怎么看、后续该做什么。

---

## 0. 总体结论

### 0.1 当前说明书“不算没有”，但“不够像操作手册”

当前系统已经有比较完整的说明书框架：

- 主要业务页面基本都有“本页说明”入口。
- 说明书主题大约覆盖 45 个业务页面。
- 页面说明主要来自 `web/viewmodels/page_manuals_*.py`。
- 整本静态说明书位于 `static/docs/scheduler_manual.md`。
- Excel 导入页、物料页、系统备份页等部分内容已经比较细。

但当前说明书仍不满足目标：

- 不能让计划调度员从首页开始照着一步步完成一次排产。
- 很多页面说明偏“提醒”和“原则”，不是“操作步骤”。
- 一些页面功能已经变了，说明没有完全跟上。
- 很多字段没有逐项解释“怎么填、能填什么、填错会怎样”。
- 很多按钮没有解释“点完会发生什么”。
- 报错场景、黄色提醒、部分成功、版本状态等解释不足。
- 系统真实排产能力和边界没有讲清，容易让用户误以为系统会自动处理更多东西。

### 0.2 后续改写必须坚持的总原则

1. **讲人话，不堆术语**
   不要上来讲“启发式算法、SGS、warm-start、constraint”等。可以用“系统会按这些规则排”“系统会多试几种排法”来讲。

2. **默认读者是计划调度员和工艺员**
   说明要能回答：我下一步点哪里？这格填什么？错了怎么改？排完怎么看？能不能发给现场？

3. **每个页面都按同一种颗粒度写**
   建议每页至少包含：
   - 这个页面是干什么的。
   - 什么时候来这里。
   - 操作前要准备什么。
   - 字段怎么填。
   - 按钮点完会发生什么。
   - 常见报错怎么看。
   - 和其他页面有什么关系。
   - 一个具体例子。

4. **不能夸大系统能力**
   当前系统不是全量 APS/CP 全局最优系统。说明书不能写成“系统会自动考虑所有限制并保证最优”。应该写成“系统会根据已维护资料尽量排出可用方案，精细计算会多试几种排法”。

5. **黄色提醒要解释清楚**
   黄色提醒不一定代表失败，但代表这版结果需要复核。说明书必须告诉用户：有提醒时不要直接盲目发现场。

6. **模拟版和正式版边界要反复强调**
   模拟排产可以看结果，但不能直接作为现场执行依据。正式执行排产后的版本才建议发给现场。

## 2. 必须补上的完整排产流程

### 2.1 首页必须给出“一次完整排产怎么做”

建议首页说明增加一节，标题可写：

> 第一次完整排产，照这 14 步走

建议内容：

1. **先确认数据安全**
   如果是正式生产数据，先去系统备份页做一次手动备份。

2. **先维护工艺资料**
   到工艺模块维护：
   - 工种配置
   - 供应商配置
   - 零件工艺路线
   - 自制工序工时
   - 连续外协工序周期

3. **再维护设备资料**
   到设备模块维护：
   - 设备编号
   - 设备名称
   - 工种
   - 班组
   - 状态
   - 设备人员关系
   - 设备停机计划

4. **再维护人员资料**
   到人员模块维护：
   - 工号
   - 姓名
   - 状态
   - 班组
   - 人员设备关系
   - 个人工作日历

5. **维护全局工作日历**
   到排产工作日历页面维护节假日、周末加班、调休、特殊效率。

6. **如果要管缺料，先维护物料**
   到物料模块维护：
   - 物料主数据
   - 批次物料需求
   - 需求数量
   - 到料数量

7. **新增或导入批次**
   到批次管理页手工新增，或者用批次 Excel 批量维护。

8. **确认批次已经有工序**
   批次只是订单本身；真正让系统能排的是批次下面的工序。
   新增或导入批次后，要确认是否已经生成批次工序。

9. **到批次详情补齐关键资料**
   自制工序要看：
   - 设备
   - 人员
   - 换型时间
   - 单件工时

   外协工序要看：
   - 供应商
   - 外协周期
   - 是否整组周期

10. **到高级设置确认排产方案**
    日常可以先用默认方案；如果要赶交期、减少换型或精细计算，再调整高级设置。

11. **先模拟排产**
    到排产调度页，筛选待排批次，勾选批次，设置开始时间和截止日期，先点模拟排产。

12. **看模拟结果**
    重点看：
    - 甘特图
    - 资源排班
    - 排产优化分析
    - 超期清单
    - 周计划预览

13. **不合理就回去修资料再模拟**
    如果发现设备冲突、人员冲突、缺工时、缺外协周期、缺料、停机没避开，就回对应页面修资料，再模拟一次。

14. **确认后正式执行排产**
    模拟结果确认后，再点正式执行排产。正式版本才建议导出周计划给现场。

### 2.2 首页必须讲清各结果页分工

建议补一张表：

| 想看什么 | 去哪里 | 大白话说明 |
|---|---|---|
| 看任务时间轴 | 甘特图 | 看每道工序什么时候开始、什么时候结束、占哪台设备或哪个人 |
| 看人和设备每天排了什么 | 资源排班 | 更适合班组长、调度员按人/设备/班组查看 |
| 看哪些批次会晚 | 超期清单 | 找延期风险 |
| 看资源忙不忙 | 资源负荷与利用率 | 看哪些设备或人员太满、太闲 |
| 看停机有没有撞任务 | 停机影响统计 | 查停机和排产任务是否重叠 |
| 发给现场执行 | 周计划 | 导出现场更容易看的周计划表 |
| 回看版本摘要 | 排产历史 | 看某次排产是否成功、有没有提醒或错误 |

## 3. 当前系统真实排产能力和限制

### 3.1 说明书必须新增“系统会考虑什么”

建议放在首页、排产调度页、高级设置页都能看到。

#### 系统会真正影响排产的内容

1. **批次里的工序顺序**
   同一批次按工序先后排。前一道工序没结束，后一道不会先开始。

2. **设备占用**
   自制工序会占用设备。同一台设备同一时间只能排一项任务。

3. **人员占用**
   自制工序会占用人员。同一个人同一时间只能排一项任务。

4. **人员和设备同时满足**
   自制工序要同时有设备和人员。缺设备或缺人员时，可能排不出来。

5. **全局工作日历**
   哪天上班、哪天休息、每天多少可用工时，会影响排产时间。

6. **个人工作日历**
   某个人请假、加班、夜班，会优先覆盖全局日历。

7. **设备停机计划**
   设备停机资料加载成功时，系统会避开停机时间。

8. **工时**
   自制工序用：
   - 换型时间
   - 单件工时
   - 批次数量

   计算大致是：

   ```text
   总工时 = 换型时间 + 单件工时 × 批次数量
   ```

9. **外协周期**
   外协工序不占内部设备和人员，只按外协周期天数往后推。

10. **连续外协组**
    连续几道外协工序可以按整组周期处理。

11. **排产截止日期**
    如果设置截止日期，超过这个日期会导致工序失败或排产结果出现失败工序。

12. **齐套检查**
    只有本次启用齐套检查时才生效。启用后，未齐套和部分齐套批次会挡住本次排产。

13. **齐套日期**
    启用齐套检查时，齐套批次如果有齐套日期，不能早于齐套日期开工。

14. **冻结窗口**
    开启后，会尽量沿用上一版本近期已经排好的任务，减少计划波动。

15. **自动分配设备人员**
    开启后，自制工序缺设备或人员时，系统会尝试从可用资源里补上。

### 3.2 说明书必须新增“系统当前不会自动做什么”

必须避免用户误解。

#### 当前不应夸大的能力

1. **不会自动扣库存**
   物料模块会帮助判断批次齐套状态，但当前不应写成自动库存扣减系统。

2. **不会自动根据库存细节排产**
   排产主要看批次齐套状态。只有启用齐套检查时，未齐套或部分齐套才会挡住本次排产。

3. **不会自动跳过缺料批次继续排其它批次**
   启用齐套检查后，只要选中的批次里有未齐套或部分齐套，本次排产会报错并停止。

4. **不会计算供应商产能**
   外协主要按周期天数排，不占内部设备和人员。当前不应写成会考虑供应商产能、供应商日历或供应商停机。

5. **不会自动知道法定节假日**
   法定节假日、调休、周末加班都需要维护到工作日历。

6. **没有设备专属工作日历**
   当前主要靠全局日历、人员日历和设备停机计划。不要写成每台设备都有自己的日历。

7. **深度优化不保证一定更好**
   深度优化只是多花几秒尝试找更好的排法，不保证每次一定更优。

8. **精细计算不是全局最优保证**
   精细计算会多试几种方案，结果通常更好，但不是数学意义上保证最优。

9. **主操和技能不代表加工更快**
   主操和技能影响推荐或自动选择顺序，不会直接缩短工时。

10. **颜色筛选不影响排产结果**
    甘特图里的颜色、筛选只是观察工具，不会改变已经生成的版本。

## 4. 排产失败、警告、降级说明

### 4.1 什么情况会直接失败

说明书应集中列出：

1. 没选择批次。
2. 选择的批次已完成或已取消。
3. 所选批次没有可重排工序。
4. 批次没有生成工序。
5. 开始时间格式不合法。
6. 截止日期早于开始日期。
7. 启用齐套检查后，选中了未齐套或部分齐套批次。
8. 自制工序缺设备或人员，且没有开启自动分配。
9. 自制工序缺设备或人员，虽然开启自动分配但系统找不到合适资源。
10. 工时不是数字。
11. 工时是负数。
12. 数量不是正数。
13. 外协周期为空、0、负数或不是数字。
14. 设置了截止日期，但工序预计完工超过截止日期。
15. 冻结窗口内已经没有可调整工序。
16. 配置项严重不合法，并且勾选了“发现参数问题就停止排产”。

### 4.2 什么情况可能继续跑，但要看提醒

1. 停机数据部分加载失败。
2. 自动分配资源池构建失败。
3. 外协组资料不完整，非严格模式下可能先按临时规则处理。
4. 旧配置值不合法，系统先按默认值继续。
5. 旧历史版本缺少新字段，分析页只能展示部分指标。
6. 日历效率缺失时，部分场景可能按默认效率处理。
7. 工艺路线导入非严格模式下，缺供应商或周期可能先按 1 天处理并提醒。

说明书要写：

> 黄色提醒不一定表示排产失败，但表示这版结果需要复核。
> 如果页面提示有失败工序、未排批次、数据异常批次，不要直接发给现场执行。

| 首页看到的情况 | 下一步 |

# 5.2 工艺模块

## 5.2.1 工种配置

### 页面路径

- `templates/process/op_types_list.html`
- `templates/process/op_type_detail.html`
- `web/routes/process_op_types.py`
- Excel：`templates_excel/工种配置.xlsx`

### 页面功能

- 新增工种。
- 编辑工种名称、归属、备注。
- 删除工种。
- 批量维护工种。
- 导出当前工种。

### 字段怎么填

| 字段 | 是否必填 | 填写说明 |
|---|---:|---|
| 工种编号 | 必填 | 唯一编号，例如 `OT001`。后续被设备、路线、供应商引用，不要随便改。 |
| 工种名称 | 必填 | 例如 `数车`、`数铣`、`钳`、`标印`。路线文字必须和这里完全一致。 |
| 归属 | 必填/默认 | 自制或外协。决定工序是排内部设备人员，还是按外协周期排。 |
| 备注 | 可选 | 人工说明，不参与排产计算。 |

### 常见错误

- 工种编号为空。
- 工种名称为空。
- 工种编号重复。
- 工种名称重复。
- 归属不是自制或外协。
- 删除时已被设备、供应商、零件工序、批次工序引用。

## 5.6.6 高级设置

### 页面路径

- `templates/scheduler/config.html`
- `templates/scheduler/_config_switches.html`

### 页面字段和开关

| 字段 | 大白话说明 |
|---|---|

| 排产策略 | 决定批次大致先后顺序，如优先级优先、交期优先。 |

| 优化目标 | 精细计算时更看重什么，如超期、拖期、换型。 |
| 优先级权重 | 综合排序时，越大越照顾急件/特急。 |
| 交期权重 | 综合排序时，越大越照顾交期近的批次。 |
| 派工方式 | 按批次顺序排，或智能派工。 |
| 智能派工策略 | 仅智能派工时生效，决定就绪任务怎么挑。 |
| 计算时间上限 | 精细计算最多尝试多少秒。 |
| 假期工作效率 | 假期安排生产且没单独填效率时使用。必须大于 0。 |
| 锁定近期排程 | 尽量保持近期上一版排程不变。 |
| 锁定天数 | 锁定多少天。未开启锁定时不生效。 |
| 优先推荐主操/高技能人员 | 主要影响推荐或选择顺序，不改变工时。 |
| 默认启用齐套检查 | 控制进入排产页时默认是否勾选。真正本次是否启用，看排产页勾选。 |
| 未指定设备或人员时自动分配 | 自制工序缺设备或人员时，系统尝试自动补。 |
| 深度优化 | 只在精细计算时尝试，不保证一定更好。 |
| 深度优化尝试时间 | 深度优化最多额外尝试多少秒。 |
| 保存补齐资源 | 系统自动补的设备/人员是否保存回工序。 |

### 当前说明缺口

1. 字段多，但没有一张完整大白话字段表。
2. 深度优化和精细计算容易被误解成“保证最优”。
3. 默认齐套检查和本次齐套检查容易混淆。
4. 自动分配和保存补齐资源的区别要讲清。
5. `prefer_primary_skill` 不要写成唯一影响自动分配的开关。

## 7. 通用 Excel 导入口径统一建议

当前有些地方口径不一致，建议统一成下面这段：

> Excel 导入分两步：先检查，再确认写入。
> 上传检查只读文件，不会改系统数据。
> 检查结果里如果还有错误，系统会拒绝确认写入。
> 确认写入时，系统还会再检查一次，防止预览后别人改了系统数据。
> 大多数导入会尽量避免把错误数据写进系统；如果写入阶段遇到并发变化、数据库问题或特殊业务拦截，以页面最终提示为准。
> 看到“部分完成”时，要按页面列出的新增、更新、跳过、错误数量逐项复核。

### 三种导入模式统一解释

| 模式 | 大白话说明 | 风险 |
|---|---|---|
| 更新已有，新增缺少 | 编号已存在就更新，不存在就新增 | 日常最常用 |
| 只导入新编号 | 已存在的跳过，只新增新编号 | 适合只补新资料 |
| 清空本类数据后重导 | 先清空本类数据，再按 Excel 重建 | 风险最高，很多被引用数据会禁止清空 |
