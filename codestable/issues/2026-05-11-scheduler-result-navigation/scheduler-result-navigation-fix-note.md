# 排产结果查看链路修复记录

## 问题背景

真实从页面使用排产功能时，用户生成或模拟排产之后，会继续查看甘特图、周计划、资源排班、历史记录和批次列表。之前这些页面能打开，但有几处信息对不上用户的实际操作：

- 模拟排产跳到甘特图时，只按一个开始日期往后推 7 天，遇到跨周任务会看不全。
- 周计划和资源排班里的跨天任务，拆到每天后可能显示成 `00:00-00:00`，用户会误以为任务没有时长。
- 资源排班默认停在“请选择人员”，不能直接看全部人员任务。
- 系统历史只告诉用户有一个排产版本，没有直接给出查看结果的入口。
- 批次页面能填写齐套日期，但列表和创建成功提示里看不到，用户不知道系统是否真的保存了这个日期。

## 根因

这些问题不是排产计算本身坏了，而是排产结果出来以后，页面展示和页面跳转没有共用同一套“用户要看什么”的规则。

- 正式排产和模拟排产各自拼甘特图跳转参数，模拟排产没有优先使用版本真实时间范围；在测试或旧路径拿不到历史范围时，也没有把本次排产摘要里的开始日期作为打开甘特图的依据。
- 跨天任务按天拆分后，结束时间落在第二天零点时，页面仍按普通时间格式显示。
- 资源排班的后端日历数据已经能算出每天的正确时段，但页面出结果前还有一层“展示文字整理”。这层又从开始时间和结束时间重新拼了一遍文字，把正确的 `24:00` 和 `全天` 覆盖回了旧的 `00:00` 写法。
- 资源排班把人员、设备、班组三种视角都当成必须选择单个对象，但人员和设备视角其实可以自然地查看全部。
- 历史版本列表缺少继续查看结果的按钮，用户只能自己猜入口。
- 批次列表漏掉齐套日期这一列，创建成功提示也没有回显用户刚填的关键日期。

## 修复内容

- 把正式排产和模拟排产成功后的甘特图跳转收进同一个方法：能拿到版本真实范围时按真实范围打开；拿不到时按本次排产摘要里的开始日期打开一周范围。
- 给跨天任务增加统一的每天时段展示规则：当天结束在零点时显示 `24:00`，完整自然日显示 `全天`。
- 资源排班日历数据把“当天时段文字”作为明确字段带到页面展示层，展示层只负责补齐设备、人员、图号等可读信息，不再重新计算当天时段。
- 资源排班默认展示全部人员；切到设备时默认展示全部设备；班组视角仍要求用户选择具体班组。
- 资源排班明细表增加“查询对象”列，让用户能看出每条任务实际落在哪个人或哪台设备上。
- 系统历史详情和历史列表都增加直达入口：设备甘特图、人员甘特图、周计划、资源排班、优化分析。
- 批次列表和批量维护列表增加“齐套日期”；创建成功提示回显交期和齐套日期。
- 批次新增表单补齐齐套日期格式提示，避免用户填了错误日期却不知道哪里错。

## 验证结果

- 已补回归测试，覆盖跨天时段、模拟排产跳转范围、资源排班默认全部人员、历史页结果入口、齐套日期前端提示。
- 已用浏览器打开系统历史和资源排班，确认历史列表能直达结果页，资源排班默认显示全部人员，日历矩阵显示 `08:00-24:00`、`全天`、`00:00-08:54` 这类清楚时段。
- 已跑针对性测试，确认相关页面合同和服务输出一致。
- 已跑代码检查，确认这次涉及的 Python 文件和测试文件通过检查。
