# APS 方案对比、延期解释和现场反馈使用说明

最后更新：2026年5月27日

这份说明给计划员、现场人员和管理人员看。它只讲页面上能怎么用、结果该怎么理解、出问题时该先看哪里，不讲程序内部的字段名和数据库名字。

## 1. 这次补齐了什么

这一轮主要补齐三类能力：

- **方案对比更好懂**：排完计划后，系统会把正式采用的方案、原算法代表方案、重点工序优先代表方案放在一起，用中文说明推荐看哪套、好在哪里、代价在哪里。
- **延期解释更可查**：超期清单不只告诉你“晚了”，还会告诉你可能先查哪道工序、看到了哪些证据、还有哪些数据不足。
- **现场反馈能进系统**：现场可以在正式计划的任务上下文里反馈开工、完工、暂停、继续生产和报异常。计划员可以再用复盘页面看计划和现场实际差了多少。

## 2. 方案对比怎么用

进 **排产优化分析** 页面时，先看页面上的推荐结论卡。

- 如果系统能比较多套代表方案，会直接说明建议先看哪套方案。
- 三张摘要卡分别说明正式采用方案、原算法代表方案、重点工序优先代表方案的总表现。
- 差值只用中文解释，比如“少了多少超期批次”“总拖期少了多少小时”“基本持平”。
- 参考方案只是拿来比较，不等于已经发给现场。
- 只有当前最新的正式采用方案，才能继续用于派工和现场反馈。

如果页面提示“暂无方案对比”，通常说明本次没有生成可比较的代表方案，或历史记录里缺少明细。这个时候不要把空表理解成系统推荐为空，而是回到排产结果和历史记录里看本次排产有没有成功。

## 3. 延期解释怎么用

进 **报表中心 -> 超期清单**，可以查看哪些批次晚了。

现在页面会尽量补充三类话：

- **已经能确认的事实**：例如计划完成时间晚于交期。
- **建议先复核的线索**：例如某道工序排得晚、某类资源比较紧、停机时间和计划时间重叠。
- **当前数据不足**：例如没有现场反馈、没有物料明细，就不能直接判断是现场做慢了或物料不够。

导出超期清单时，工作簿里会带上中文的诊断依据，方便计划员把“为什么这样提示”一起带出去。证据不足时，文件也会用中文说明缺什么信息，不会把系统猜测写成已经确认的结论。

## 4. 现场反馈怎么用

现场反馈只对当前最新的正式计划开放。历史计划、对比参考方案和模拟预览都只能查看，不能写现场反馈。

在 **资源排班** 页面进入现场反馈区域后，按任务卡操作：

- **开工**：记录实际开始时间、实际设备和实际人员。
- **完工**：记录实际结束时间和完成情况。
- **暂停**：记录暂停原因和说明。
- **继续生产**：从暂停或异常状态恢复生产。
- **报异常**：记录异常原因、严重程度、影响时间、影响资源、处理状态，以及是否建议重新排程。

这些反馈不会覆盖原来的计划开始和计划结束。计划时间仍然代表“原本怎么排”，现场反馈代表“现场实际怎么做”。

## 5. 计划和现场实际怎么看

进 **报表中心 -> 计划和现场实际**，可以把计划和现场实际放在一起看。

页面和导出会用中文列出：

- 计划开始和计划结束。
- 实际开始和实际结束。
- 开工偏差和完工偏差。
- 实际设备和实际人员。
- 暂停时长、异常原因、处理状态。

如果某个任务还没有现场反馈，页面会明确显示暂无实际信息。不要用计划资源去当成现场实际资源。

## 6. 重排时现场事实怎么保护

重新排程前，系统会先看现场已经发生了什么：

- 已经开工或暂停的任务，默认不随便移动。
- 已经完工的任务，保留真实完成时间，不再重新安排。
- 异常中的任务，普通自动重排会先停下，提示计划员先处理异常。
- 如果计划员保存了模拟方案，后来现场状态变了，正式采用前系统会重新检查，发现不一致就拒绝采用，避免把旧现场状态下的模拟结果直接变成正式计划。

这样做的目的很简单：已经在现场发生的事，不能被新的计划悄悄改掉。

## 7. Win7 和离线使用注意

- 目标电脑按 Win7 x64 离线场景准备，不要求连外网。
- 页面脚本、样式和说明书都随系统本地交付，不依赖外部网站。
- 建议用交付包里配套的本地浏览器环境打开系统；如果必须人工验收浏览器兼容，按 Chrome 109 口径检查页面能正常打开、按钮可点击、表格不遮挡、导出能下载。
- 正式库做批量导入、恢复备份、正式排产、正式采用模拟方案前，都建议先做一次手动备份。

## 8. 遇到提示时怎么处理

- 提示切换到最新正式计划：说明你当前看的不是能写反馈的正式计划，先回到最新正式结果再操作。
- 提示证据不足：说明系统还缺数据，不要把线索当成最终原因。
- 提示现场状态变化：说明你查看或保存方案之后，现场又有新反馈，重新打开最新结果再操作。
- 提示模拟预览还未改变正式计划：说明你现在只是在看试算结果，现场不要按它直接执行。
