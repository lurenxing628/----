# ADR-0010: 批次外协工序快照策略

- **状态**：已实施（Schema v33）
- **更新日期**：2026-09-28
- **依据**：工作台明确承诺模板变更不自动更新已有批次；本轮修复消除动态回查导致的周期漂移。

## 决定

新增一对一的 `BatchExternalContexts`，由 `operation_id` 关联批次工序。
保存捕获时的模板工序与外协组永久引用、确切成员、起止序、周期模式、整组天数及来源。
模板/组字段不设回当前模板的外键，避免模板删除或重建改变既有快照。

新外协工序以及自制改外协时捕获当前上下文；正常模板复制发生在模板资料已就绪之后。
若先写批次外协、后补模板，快照保持其缺失事实并阻止排产，不能在读取时猜测补齐。
只有明确预览并同步批次工序会重新捕获。复制已有批次/分件继承源快照，不采用当前模板。

排产、预检、批次详情和试调读取同一批次快照。成员关系由逐道快照记录保存，不重复存整段名单。算法组键以永久组引用及范围、模式、供应商和周期的摘要组成，
不用可复用的业务组号判断同组。资源当前可用性仍按现行资源档案校验。

## 迁移与证据边界

v33 仅在迁移事务中冻结升级时可核实的当前上下文，`origin=migration_v33`。
页面说明这是升级时资料，不冒充原批次创建时的历史证据。复制此类批次继续保留此来源标记。
缺失模板、损坏组关系和非法周期保留原值，相关外协排产明确拒绝；不静默回查活动模板或改用单道周期。
迁移不修改 `BatchOperations`、既有 `Schedule` 时间、报工或外协登记事实。

复制已有但不完整的快照时原样保留其资料与诊断；复制不代表通过排产验证。合并段的实际成员供应商必须一致且符合冻结规则，批次页不允许逐道改派；组校验一次完成后各工序读取缓存结果。
明确归档版本为1～32且同份归档DDL没有v33对象的旧候选，可以只从该归档解释本次试调选中外协工序的上下文，标记内存来源 `archive_pre_v33`。未选批次缺模板不影响选中工序；新版缺失快照仍拒绝，不查询当前模板补齐旧档案。

## 验证入口

- `tests/workbench/test_batch_external_context.py`：模板周期变化、删除/重建、显式同步差异、批次和分件复制、缺失快照。
- `tests/migration_db/test_batch_external_context_v33.py`：v32 升级来源、旧事实保留、新库结构一致、损坏上下文诊断。
- `tests/schedule/service/test_schedule_template_lookup_contract.py`：冻结输入读取及组身份隔离。
- `tests/workbench/test_trial_archived_external_context.py`：真实旧版捕获、归档结构证明、选中范围隔离及试调读取原周期。
