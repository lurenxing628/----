# APS 架构合规审计

## 适用范围

按根目录 `AGENTS.md` 确认本次是只读分析还是已授权运行检查。局部架构问题先读取相关代码；明确要求全项目架构体检时，使用下面的专项能力。审查本身不授权改产品代码、刷新基线或豁免历史问题。

## 运行入口

下列 `python` 应按入口选择解释器：适应度测试使用项目 `.venv`；纯宿主扫描工具遵循 `.codestable/attention.md` 的工具约定，不将产品语法约束扩大到宿主工具。宿主扫描结果不是 Win7 / Python 3.8 运行证明：

```bash
python .limcode/skills/aps-arch-audit/scripts/arch_audit.py
python -m pytest tests/gate_meta/test_architecture_fitness.py -v
```

脚本报告位于 `evidence/ArchAudit/arch_audit_report.md`。适应度规则以 `tests/gate_meta/test_architecture_fitness.py` 和实际收集、执行结果为准，不在技能里复制测试数量或逐条清单。已有同范围、同版本有效结果可复用。

脚本提供分层方向、越层导入、循环依赖、文件大小与命名、禁止模式、枚举、注解、复杂度和疑似死代码线索。完整质量验证按 [开发文档/README.md](../../../开发文档/README.md) 选择 daily、full、final 或 fast-precheck；本专项结果不能代替最终 clean proof。

## 如何判断

- 分层、循环依赖：读取实际边界与消费者，说明具体业务影响和可行拆分；不要只凭导入关系定风险级别。
- 超长文件、复杂度：对照当前门禁与已登记历史约束，按职责提出拆分，不能为过线机械移动代码。
- Vulture 默认置信度较高，不覆盖所有未使用函数；无调用者不等于死代码。反射、回调和 dataclass 钩子要结合动态证据核实，不能据静态结果直接删代码。
- 裸字符串集合可能是输入校验，需读上下文；脚本提示不直接等于业务 bug。
- 适应度失败需核实失败原因：可能是新增违反、基线过期或检查环境问题，不能把所有 FAILED 都写成新增架构违反。

## 汇报与完成

报告实际覆盖范围、检查结果、失败/跳过原因，以及经核实的问题、证据、影响和建议。区分静态疑点与已确认缺陷，不能编造动态验证结果。

默认在对话中给结论。只有用户要求保存或已授权流程要求落档时，使用 `.codestable/audits/` 或当前流程的证据位置；原始脚本报告保留在 `evidence/`。发现问题不自动修复或启动循环复审。
