# 经验记录

启动、授权与续作遵守根目录 `AGENTS.md`；读取或复用 `.codestable/attention.md`。路径、状态、查重与取代关系按需查 `.codestable/reference/shared-conventions.md`。

只在用户要求记录或已明确授权沉淀时保存。普通修复或验收结束不自动启动归档；确有价值时合并提示一次即可。

## 两类记录

- `track: pitfall`：现象、失败尝试、根因、解法及下次如何更早发现。
- `track: knowledge`：经验证的做法、适用条件、理由及限制。未拍板的经验不能冒充项目长期硬约束。

模板按需读 `reference.md`。没有发生过的失败尝试、没有证据的根因不为填章节补写。

## 操作

1. 从本轮对话、实际代码和验证记录提取来源及已知信息；不让用户复述已完成的调查。
2. 检索相近 learning，更新目标明确时直接更新；新事实取代旧结论时按共享规范保留取代关系。
3. 只澄清影响结论的缺项。完整上下文足够时直接起草、核验并保存；用户要求先审稿或关键事实矛盾时才等待。
4. 新建 `.codestable/compound/YYYY-MM-DD-learning-{slug}.md`，保留 `doc_type: learning`、`track`、`date`、`slug`、`component`、`tags`，pitfall 可含 `severity`；更新补 `updated`。
5. 记录有效边界、实际验证及相关来源。学习点可以不适用于其他模块，不能默认所有经验都是强制规则。

## 收尾

短而稳定、频繁使用的项目事实适合 attention 摘要，重要长期选择适合 decision。只有当前授权包含这些更新时才联动写入；否则合并提示，不逐项追问或重复建立同一份记录。
