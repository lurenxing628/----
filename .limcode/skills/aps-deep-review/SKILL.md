# APS 深度代码审查

## 范围与证据入口

遵循根目录 `AGENTS.md`。先确认本次指定的文件、提交或改动范围，区分已有 dirty 内容与本轮产物。审查本身只读，不自动修复、刷新基线或循环复审；已有修复及复审授权时按其范围执行。

使用 `python3 -m tools.symbol_locator` 定位定义、调用者与被调用者；指定变更范围的调用链核对、证据等级与索引新鲜度边界见 [.codestable/reference/symbol-locator.md](../../../.codestable/reference/symbol-locator.md)。

纯宿主定位/维护工具遵循 `.codestable/attention.md` 的宿主工具约定，实际产品测试与正式门禁仍使用项目 `.venv`；宿主静态结果不能作为 Win7 / Python 3.8 运行证明。按本次确认的文件、提交基线或实际变更定义查询 `whereis`、`callers`、`callees`，不要默认将 `HEAD~1` 等同本次范围，也不生成固定调用链子报告文件。定位工具输出不能代替完整动态调用图，须先核对实际变更范围并回到源码确认签名、空值、事务、状态和跨层合同。

## 按相关边界深入

下列检查按变更涉及的合同选择，不为未涉及的层补做全量扫描。重要公共边界不能只凭文件数量缩减；大型变更应说明覆盖顺序和未覆盖范围。

- **调用者适配**：核对参数、默认值语义、返回形状、空结果及异常处理。读取实际调用上下文，不能只看函数名或搜索命中。涉及模板/JS/导出消费者时一并定位。
- **数据流**：涉及写入时追踪输入 → Route → Service → Repository → DB；核对类型转换、字段白名单、SQL 参数顺序、`from_row()`、schema 与迁移。只读变更不自动扩展成全库写链审查。
- **事务与失败**：检查边界是否产生重复事务、遗漏回滚、吞异常或跨层语义变化；错误能否被现有 handler 和审计链正确处理。
- **状态与输出**：配置/运行状态、公开输出与内部诊断是否混用，持久化、历史读取、页面与导出是否消费了改变的字段。
- **边界与回归**：按真实输入合同检查空值、错误类型、重复提交、相关锁与日历/排产边界；不机械假设所有参数都允许 `None`。定位相关测试、缺少的行为断言及必要新增用例。
- **疑似死代码**：文本搜索无调用者不等于未使用，检查回调、反射和动态路径后再下结论。

需要子代理时遵循 `.limcode/skills/_shared/subagent-compat.md`，仅委派可独立核验的风险面；主代理综合实际返回证据。不固定代理数量、历史模型或五阶段逐项输出模板。

## 汇报与完成

优先报告可行动的问题：位置、触发条件、违反的合同、实际影响和证据；明确哪些是已确认缺陷、静态疑点或覆盖不足。没有问题时说明审查范围与剩余限制，不制造修复任务。

涉及运行验证时，按 [开发文档/README.md](../../../开发文档/README.md) 区分局部检查、daily、完整门禁和最终 clean proof。未经运行不能声称测试通过；深审完成也不代替最终门禁证据。

默认对话汇报。只有用户要求保存或当前已授权流程要求落档时，写到 `.codestable/audits/` 或当前 issue/refactor 的证据位置；不再默认另建 `.limcode/review/` 或根目录 `audit/`。已有历史报告不因整理而迁移或删除。
