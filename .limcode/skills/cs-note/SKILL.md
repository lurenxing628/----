# 项目常驻提示

启动与授权遵守根目录 `AGENTS.md`。目标文件是 `.codestable/attention.md`；它补充项目规则，不替代规则优先级。

## 哪些内容适合常驻

- 一两句能讲清、长期有效、多数项目任务会用到的环境限制、命令陷阱、事实源或路径约定。
- 仅特定任务用到的操作参考放 `cs-trick`；经验及背景放 `cs-learn`；重要决定和取代关系放 `cs-decide`。
- 临时绕过、近期进度、某次 bug 的完整修法不进入常驻提示。

分类可从内容直接判断，无需让用户选择技能。用户要求记录的事实已明确时直接维护；含义或适用范围有实质歧义才澄清。

## 维护步骤

1. 读取现有 attention 及相关规则，确定事实与适用范围。已有记录直接复用，不因切换技能重复读取。
2. 查关键词及近义表达。相同内容不重复写；已明确要求更新时直接更新原条目。新事实与现行规则冲突且无法判断取代关系时再询问。
3. 按现有分节写入，保留无关内容和项目定制。用户明确授权多条时可以一并处理，不强制一次一条。
4. 复核事实来源、链接、重复与长度，报告实际变化。常驻提示过长时提出移入专题参考的具体建议，不自动迁移历史内容。

缺 attention 时，可在明确授权创建或维护该文件的范围内建最小骨架；缺完整 CodeStable 目录不要求先初始化整个体系。

## 新文件最小骨架

```markdown
# Attention

项目注意事项补充适用的 AGENTS.md；本轮已读且未变化时复用。

## 项目碎片知识

<!-- cs-note managed: 用 cs-note 维护，新条目按下面分节追加 -->

### 编译与构建
### 运行与本地起服务
### 测试
### 命令与脚本陷阱
### 路径与目录约定
### 环境变量与凭证
### 其他
```

分节服务检索，可以按用户授权和内容实际需要调整。识别已有结构时匹配 `cs-note managed` 标记及标题，不因注释文字略有不同重复插入整块骨架。

只有发现确有长期价值的新事实时才合并提示一次保存建议；用户未要求保存则不自动写入，用户拒绝后不重复追问。
