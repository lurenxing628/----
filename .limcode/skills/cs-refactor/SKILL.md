# 行为不变的重构

启动、授权与续作遵守根目录 `AGENTS.md`；读取或复用 `.codestable/attention.md`。记录规范按需查 `.codestable/reference/shared-conventions.md`。

## 选择范围

- **只读研究或建议**：查看目标代码、契约和相关验证，交付实际问题、证据、建议及限制，不改代码或生成文档。
- **已授权局部修改**：目标明确、行为边界清楚且能验证，按 `cs-refactor-ff` 连续修改和验证；是否局部取决于职责和影响，不由文件数、改动行数决定。
- **复杂调整或明确要求完整流程**：按下方 scan → design → apply 组织工作。用户只要方案时到方案交付为止；已批准方案并要求实施时连续完成。

外部可观察行为改变时，说明实际属于功能变更或故障修复，沿用户已授权目标进入 `cs-feat` / `cs-issue`；不能把行为变化称作等价重构。范围大时按模块分批覆盖，不因规模直接拒绝。

## scan：找有证据的调整点

1. 从用户指定文件或模块定位实际职责、公开接口、调用方及测试。产品实现前按项目要求使用 symbol-locator。
2. 核对行为等价能否验证、目标是否为生成产物、是否存在跨模块约定。具体判断见 `reference/refusal-routing.md`，只读扫描本身不需要先补测试。
3. 记录发生条件、实际维护或性能影响、文件位置、建议改法和验证方式；零发现是有效结果，不凑数量或风格问题。
4. 方法库 `reference/methods.md` 仅在需要操作参考时读取相关方法；不全量加载，也不要求每条建议都能映射到固定方法号。

用户要求保存完整扫描时，写 `.codestable/refactors/{YYYY-MM-DD}-{slug}/{slug}-scan.md`，格式按需查 `reference/scan-checklist-format.md`。已有明确选定范围直接复用；候选之间存在实质取舍时再请用户选。

## design：形成可执行方案

完整流程保留 `{slug}-refactor-design.md` 和 `{slug}-checklist.yaml`。记录：

- 范围与行为不变量；实际选定的扫描项和明确不做项。
- 依赖、执行顺序、每步退出信号、测试或页面验证、回退边界。
- 验证不足时需要补的刻画测试；公开接口或模块边界变化的存量影响。
- 无法自动执行的真实现场检查；不能把所有前端验证都指定给用户。

方案 frontmatter 沿用 `doc_type: refactor-design`、`refactor`、`status`、`scope`、`summary`；批准后 `status: approved`。checklist 的 `steps` 与 `checks` 对应实际操作和退出信号，用项目 YAML 工具校验。

方案未获实施授权或存在新的重大取舍时等待决定；已获批准的范围不按阶段重复确认。目标态架构留在方案或 roadmap 中，不能先改当前架构文档冒充现状。

## apply：实施与验证

1. 沿依赖顺序执行，每步完成记录真实结果。独立且可共同验证的内部动作可以合并，不为形式机械拆步。
2. 验证原有行为、公开契约、调用方和直接影响范围；可见渲染或交互变化补适用页面验证。
3. 原范围内的实现细节和必要调整自行处理并验证；新增业务取舍、外部约定变化或范围扩大时说明影响再确认。
4. 只有确需用户现场操作的项目才等待用户，并保持待验证状态；工具检查通过不能替代未执行的现场确认。
5. 完整流程写 `{slug}-apply-notes.md`：`doc_type: refactor-apply-notes`、`refactor`，正文记录实际步骤、改动、验证与偏离。

完成后按影响执行项目适用测试和质量门禁，遵守根规则区分局部验证与 clean-worktree proof。未完成的检查说明限制，不虚报通过；不自动提交或清空工作区。

## 完成标准

- 已完成用户所选的研究、方案或实施范围，没有夹带行为变化。
- 实施有行为等价和影响面验证；未验证项明确列出。
- 已授权完整流程的 scan、design、checklist、apply-notes 可追溯且状态真实；局部流程不强制补全这些产物。
- 实质范围变化和剩余风险已报告；提交遵守共享 scoped-commit 规则。
