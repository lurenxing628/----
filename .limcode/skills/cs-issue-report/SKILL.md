# 问题记录

启动、授权与续作遵守根目录 `AGENTS.md`；读取或复用 `.codestable/attention.md`。路径、状态与收尾按需查 `.codestable/reference/shared-conventions.md`，缺辅助材料不阻断只读调查或已授权局部工作。

兼容阶段入口：问题处理范围由 `cs-issue` 和当前用户要求决定。本技能记录已知事实，不把猜测写成根因。

## 读取与查重

- 从用户描述、实际日志和代码中复用已知信息，只澄清影响复现、预期行为和判断的缺项。
- 检索相关 issue；同一问题已有记录时按任务更新，不重复创建。续作目标明确时不重复确认新建还是更新。
- 只读现象提问直接回答；已授权局部修复且根因已核实时可转 `cs-issue-fix`，无需先填写完整报告。

## 要核实的事实

1. **现象**：具体异常与发生条件；用户的原因猜测明确标为线索。
2. **复现**：最小触发路径、频率和条件差异；无法稳定复现时如实记录。
3. **期望与实际**：分别说明做了什么、应该出现什么、实际出现什么。
4. **环境**：相关模块、版本或数据条件；可自行查到的不让用户重述，未知位置可写待定。
5. **影响与严重程度**：按证据及项目分级判断，不要求用户替代理确认每个分类；重要业务影响未知时再澄清。

这是信息核实清单，不是固定问卷，也不要求用户知道代码位置。

## 保存与结束

用户已授权记录时，在 `.codestable/issues/YYYY-MM-DD-{slug}/{slug}-report.md` 保存；沿用已有目录与 slug，新增 slug 可从现象拟定。模板按需读 `reference.md`。

沿用 `doc_type: issue-report`、`issue`、`status`、`severity`、`summary`、`tags`。事实已核实且无待决歧义时可记 `confirmed`；存在重要待确认事实时保持 `draft` 并说明缺项，不能把文件写完当作已复现。

报告只需包含适用事实，交付记录位置、结论和限制。用户只要求记录时到此结束；已经授权分析或完整修复时继续 `cs-issue-analyze` 或 `cs-issue-fix`，不把阶段切换变成重复审批。
