# 开发者与用户指南

启动、授权与续作遵守根目录 `AGENTS.md`；读取或复用 `.codestable/attention.md`。路径、状态、查重与取代关系按需查 `.codestable/reference/shared-conventions.md`。

guide 回答“如何用 X 完成 Y”；逐接口的参考交给 `cs-libdoc`。用户只问用法时直接回答，不自动创建文档。

## 操作

1. 确定读者与范围：开发者、终端用户或两者；按已有项目 docs 结构定位目标，缺明确结构时使用 `docs/dev/{slug}.md`、`docs/user/{slug}.md`。
2. 检索同主题文档；相关现行代码和行为是事实依据，设计稿与用户素材补充目标和术语。没有 design 也能写指南，不为补文档搭完整功能流程。
3. 按需读同目录 `reference.md`，选择适用章节。代码示例核对真实接口；用户步骤用实际操作与可用截图，不虚构已验证演示。
4. 自查读者能否完成目标、步骤是否正确、例子与实现是否一致。已授权且内容明确时直接保存；实质范围或读者定位未知时澄清，用户要求先审稿时一次交付完整稿，不逐节重复确认。
5. 沿用 `doc_type: dev-guide` / `user-guide`、`slug`、`component`、`status`、`summary`、`tags`、`last_reviewed`。草稿用 draft，已核实当前内容用 current；过时记录在获准维护时标 outdated。

## 更新与结束

现有同主题指南优先原地更新并保留可追溯历史，不因结构变化自动另起同主题副本。需要重命名、搬迁或保留独立历史版本时按用户授权执行并核对链接。

只读架构检查发现指南过期时只报告，不自动修改其状态。涉及 API 参考、长期决定或额外指南的联动，按当前授权完成或一次说明建议；不能固定推送一串技能。

交付实际文件、内容范围、核验方式和未确认部分，不将未运行示例写成已经通过。
