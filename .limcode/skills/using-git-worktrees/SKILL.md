# 工作树隔离

先查看当前工作区和已有 worktree，区分本轮与他人的修改。用户明确选择当前 checkout 时遵守；不要求所有实施任务都新建工作树。

需要隔离时优先使用当前宿主的工作树能力或仓库已有约定，记录起点、路径和分支。注意新 worktree 默认不复制当前未提交修改，不能把旧现场当成已随分支带入。

若使用仓库内目录，先确认忽略规则；目录无约定时可选择宿主管理的仓库外位置，不为普通目录选择反复询问。不擅自安装或升级全局依赖，复用符合项目约束的运行环境。

选择与任务相关的基线检查，区分已有失败与新增失败；无关基线问题记录后继续可独立完成的工作。

worktree 的 `.git` 通常是文件，Git 内部路径用 `git rev-parse --git-path <名称>` 解析。完成后是否提交、推送、合并或移除工作树按用户授权处理；清理前核实路径及未提交、未跟踪内容，保护他人的工作。
