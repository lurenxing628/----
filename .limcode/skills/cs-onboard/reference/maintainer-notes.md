# CodeStable 维护与续作

本页用于恢复工作或维护技能，普通任务无需读取。

## 恢复已有工作

先核对用户最新要求、当前文件与已有记录，报告从哪里继续。已完成且未变化的步骤和有效验证可复用；未完成的补齐，不从头重做，也不固定询问“继续还是推翻”。无法确认工作状态时只补查必要证据。

- design：保留已确认范围，补实际缺项。
- implement：依据 checklist 和当前代码核对 done/pending，不仅凭文件存在判定完成。
- acceptance：继续尚未验证的契约，不能为完成状态而修代码或改需求；修复按授权执行。
- issue：代码已改时核对根因与实际行为，再补相关验证及授权范围内的任务记录。

## 维护职责

AGENTS.md 管授权、范围、平台与完成；SKILL.md 管触发、选择和必要操作；参考模板管产物字段与具体方法。模板中的示例不能另立权限或强制执行序列。

更新技能时检查其直接引用的正文、模板、角色及宿主适配，清除同一规则的冲突副本。只在新增入口或改变分工时更新总览；普通文字修订不需要制造索引变更。

项目共享约定先在 `.codestable/reference/` 维护；可复用变化再同步 onboard 模板，保留项目已有定制和专题工具说明。历史记录保留原位，新决定写明取代关系，不回写历史使其看起来一直正确。

## 验证整理结果

检查 name/description、引用能否解析、模板字段/状态是否与流程一致，以及只读、小修、完整验收、批量任务等情景是否正确分流。脚本改动用隔离行为测试；不靠匹配措辞的测试宣称行为正确。
