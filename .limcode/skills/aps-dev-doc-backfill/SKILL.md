# APS 开发文档同步

## 范围与事实源

遵循根目录 `AGENTS.md`。先确定是只读核对、局部同步还是明确的全量文档核对；已授权更新文档时连续完成必要修改与验证，不重复确认。发现疑似代码 bug 只报告，不把文档任务扩大为产品修复。

- 默认只处理授权变更涉及的文档和章节。`git status` / diff 用于区分已有与本轮内容；不把无关 dirty 文件纳入本轮清单。
- 当前行为以实现、schema 和相关测试证据核验。实现与批准的合同冲突时标明差异，不把疑似 bug 写成新的业务要求。
- `.codestable/` 是当前工作流事实源：需求、架构、issue/refactor 等更新回到对应文件。`开发文档/` 仍承接已有开发说明、速查表、接口清单与验收记录；按信息职责更新，避免复制新的事实源。
- 只读核对默认在对话汇报；用户要求保存报告时用 `.codestable/audits/` 或当前流程指定位置。

历史忽略范围不读不改，除非用户明确指定历史任务：`开发文档/V1.2/**`、`开发文档/拆分高耦合文件_2026-01-29.md`、`开发文档/拆分高耦合文件_P1P2_实施策划.md`、`开发文档/拆分高耦合文件.md`、`开发文档/自检报告_2026-01-26.md`。

## 局部同步

1. 从已授权的文件、提交或需求取得变更证据，列出实际受影响行为；必要时检查 staged/unstaged/untracked，避免混入他人工作。
2. 按变化选择事实面：路由与页面、数据库、排产与日历、Excel、交付或门禁。只读取相关实现及消费者；模块路径与检查细节见 [reference.md](reference.md)。
3. 找到承载这些事实的现有章节及相关 CodeStable 当前说明，更新过期内容与必要交叉引用。公共参数、默认值、用户可见文案应能追溯到代码。
4. 核对路径、链接、字段与命令是否真实，说明修改、证据和未决差异。纯文档同步不自动运行排产或全量产品测试；验证入口和 clean proof 含义以 `开发文档/README.md` 为准。

独立且足够大的事实面可按 `.limcode/skills/_shared/subagent-compat.md` 委派；不固定四路、不要求每次扫描全部模块。没有子代理时完成同一已授权范围，不能据此跳过必要核对。

## 明确的全量核对

用户要求“所有开发文档逐章对齐”时，先界定当前文档集合与历史排除项，再列标题逐章检查，覆盖该集合涉及的全部事实面。所有范围内文档都应有已核对、已更新或未完成原因，不得将局部同步冒充全量完成。

全量也不包含无关 dirty 文件的自动回填，不能因“以实现为准”抹去批准的需求、历史决定或验收记录。若用户同时授权修改，更新确认过期的当前内容；否则仅报告差异。

## 完成标准

本轮涉及的行为都有对应文档、无需更新的理由或明确未决项；新增/变更的 URL、参数、默认值、枚举和字段能找到证据；用户可见中文文案与实际页面一致；路径统一使用正斜杠。汇报实际覆盖范围、修改文件、关键证据与未解决问题即可，无需套固定长模板。示例见 [examples.md](examples.md)。
