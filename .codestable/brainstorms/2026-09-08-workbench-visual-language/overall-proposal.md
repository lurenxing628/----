# APS 工作台视觉与布局总体方案

## 1. 结论

**保留现有 APS 扁平工作台的外观和操作习惯，做一轮有共同标准的整理，不更换整套设计语言。**

现有侧栏、蓝色主色、深浅主题、小圆角和甘特表现方式是基础。参考 SAP Fiori 的企业任务组织、Carbon 的数据工作区和文字层级、Fluent 的分隔与控件语义；不把三家的按钮、字体、导航和表格拼成另一套界面。

本稿最初为只读研究方案。2026-09-08 用户明确要求“那开改吧”，并允许 subagent 并行，现已进入批准范围的实施与验证。之前未验收的系统管理调整仍须按本稿收敛和验收，不因已经落盘就自动成为定稿。

本轮原型实施与局部验收已完成，实际页面覆盖、测量、测试及 Win7 验收边界见 [实施记录](/Users/lurenxing/GitHub/----/.codestable/issues/2026-09-08-workbench-visual-language/workbench-visual-language-fix-note.md)。

### 1.1 产品前提：Win7 单机离线软件

- **目标是 Win7 x64 单机离线运行，不是云端 SaaS 后台。** 后续所有页面与技术取舍先服从这个前提，继续保持 Python 3.8 兼容；目标机不要求另装 Python。
- 外部设计系统只提供视觉和组织方法，不据此更换框架、升级运行时或要求更高版本浏览器。前端能力须在项目实际交付的浏览器环境中验证。
- 脚本、样式、图标、字体均随软件本地交付，正常操作不依赖 CDN、在线字体、外部接口或网络连接。本轮联网仅用于研究设计规范。
- 系统管理面向本机程序、本地数据、备份恢复、运行日志和维护参数；不套用云租户、组织管理、云同步或网络服务监控的后台模板。
- 单机离线并不表示没有本机后端服务。原型没有接入真实数据时应说清“本原型尚未读取本机运行数据”，避免“正式服务未连接”等措辞让人误认为依赖云端；也不能把未知状态改成正常。
- 以桌面鼠标、键盘、表格阅读和连续录入为主要操作方式。1920×1080 是主要设计视口，Mac 上的截图只用于设计评审，不能代替 Win7 目标机验收。

## 3. 现场证据与问题判断

研究阶段用隔离 Chrome 读取真实 `file://` 入口，未修改用户浏览器的主题偏好或示例数据。以下是实施前默认报表状态的测量，不是所有专题、数据源和展开状态的通用结论。

| 报表中心 | 1920×1080 浅色 | 1392×924 浅色 |
| --- | ---: | ---: |
| 主内容可用宽度 | 1632px | 1104px |
| 筛选区域高度 | 132px | 132px |
| 表格顶部位置 | 约 751px | 约 751px |
| 完整可见的数据行 | 4 行 | 2 行 |
| 首屏可见 input/select | 10 个 | 10 个 |

- **报表不是单纯“控件太多”，而是层层排成纵向队列。** 来源说明、筛选、范围复述、专题、指标、图表入口、口径长文、明细标题、排序各占一层。即使整个 132px 筛选区消失，表格仍要从约 619px 开始。仅调输入框间距解决不了问题。
- **系统管理不能靠把设置摊满屏幕来利用大屏。** 原先标签和控件相距过远；后续草稿虽然缩短了距离，但顶部状态、配置分组、规则说明和按钮仍需作为整页统一决定，不能逐块定稿。
- **文字层级与现有令牌脱节。** 原型已有 12/13/14/17/22px 字号档位，报表局部却仍使用 11px 标签和大量 12px 说明。先减少重复，再恢复可读字号，不能靠继续缩字装进首屏。
- **配色问题主要是使用方式。** 现有调色板已经包含适合文字的蓝、绿、橙、红；大量信息却同样铺浅底、用近似字重，重点状态没有形成足够清楚的阅读顺序。

定位：[报表内容顺序](/Users/lurenxing/GitHub/----/前端设计/ui_kits/workbench/ReportsScreen.jsx:188)、[报表局部样式](/Users/lurenxing/GitHub/----/前端设计/ui_kits/workbench/report-workbench.css:1)、[配置草稿](/Users/lurenxing/GitHub/----/前端设计/ui_kits/workbench/SystemManagementScreen.jsx:132)、[字号令牌](/Users/lurenxing/GitHub/----/前端设计/tokens/typography.css:28)。这些是原型证据，不是对生产软件的审计结论。

## 4. 外部规范怎么借鉴

| 来源 | 借鉴的内容 | 不照搬的内容 |
| --- | --- | --- |
| SAP Fiori | 紧凑布局不缩小字体；关键筛选优先；收起条件仍可追溯；合并重复标题和工具栏 [S1-S3] | 不机械套像素尺寸、单行截断、空单元格表示缺失，也不新增整套保存视图流程 |
| IBM Carbon | 表格获得足够空间；整表操作与行内操作分开；产品型文字层级；背景、边线、文字、状态分别定义 [S5-S8] | 不换 IBM Plex、IBM 品牌色或壳层；不另加一套表格搜索和全局右面板 |
| Microsoft Fluent | 用分隔线、留白和标题共同分组；区分组内短线和严格分界；区分即时开关与需提交的设置 [S9-S10] | 不照搬整套按钮位置、圆角和主题材质，不把所有操作改成图标 |
| Ant Design / W3C | 对齐与邻近关系；文字与颜色可访问性 [S11-S13] | 不把某家表单冒号、标签方向当成所有页面的硬规则，不用“通过规范”代替实际看图 |

这些设计体系提供的是其体系内的要求或建议。下文的尺寸和首屏位置是针对本原型的提案，不是 SAP、Carbon 或 Fluent 的强制数值，也不代表取得了规范认证。

## 5. 共同视觉规则

### 5.1 分隔：保留认读所需的一层边界

| 位置 | 处理方式 |
| --- | --- |
| 同一面板内的多项设置、检查清单 | 行与行之间保留 1px 细线，两端与内容对齐；不再给每行另套外框 |
| 详情里的基本信息、分析、处理动作 | 语义分组之间留一条线和适当间距，不要求每个字段下都画线 |
| 表格 | 保留表头与数据行分隔；列线按对照需要使用，不画满所有格子 |
| 甘特 | 保留时间网格、资源分组、固定列和真实冲突提示，不当成装饰线删掉 |
| 页内不同大功能区 | 优先用 24px 组距和必要的底色区分；若同底色仍易混淆，再留一条分界 |
| 固定操作栏、表单提交区、弹窗正文与操作区 | 保留清楚边界，让用户知道动作作用于哪一块内容 |
| 已有标题底色的区域 | 不再同时叠加上下双线、竖色条和外围框；选足够清楚的一种标题处理 |

分隔线不是越多越专业，也不是越少越高级。Fluent 对整宽线与内缩线的区分可以借鉴；其组件间距不能原样累加到每个表格行，否则又会浪费高度。[S9]

### 5.2 文字与强调色

继续使用现有本地字体，不增加字体下载或更换全站字形。

| 用途 | 提议字号/行高 | 表现 |
| --- | --- | --- |
| 页内主标题 | 22/30px | 600 字重，当前主题下的高对比中性色 |
| 功能分区标题 | 17/24px | 600 字重，不为每个分区分配一种颜色 |
| 表单、主要操作、重要正文 | 14/20px | 正常或中等字重 |
| 数据密集表格 | 13/20px | 对齐清楚，长内容允许合理换行 |
| 辅助说明、单位、时间补充 | 12/18px | 次要文字色，但不能灰到难读 |
| 报表关键值 / 值班台重点值 | 22px / 28px | 沿用已有字号档位；不把所有统计都做成大数字 |

颜色要用到文字和数字上，而不只用于按钮和底色。浅色主题优先复用以下现有文字令牌，深色主题使用它们已有的主题值：

| 文字含义 | 既有令牌及浅色示例 | 示例 |
| --- | --- | --- |
| 普通标题、重点总数 | `--ui-text`，`#0f172a` | 工序总数、总工时；重要不等于成功或失败 |
| 辅助上下文 | `--ui-info-muted`，`#475569` | 数据截至时间、单位、样本量 |
| 链接、可执行动作、选中 | `--ui-info-text`，`#1d4ed8` | 查看工序、当前专题；保留链接形态或跳转图标 |
| 已确认完成、检查通过 | `--ui-success-text`，`#15803d` | 已完成、已通过 |
| 待确认、待补资料 | `--ui-warning-text`，`#b45309` | 到期未确认完成、资料待补 |
| 明确失败、明确延误 | `--ui-danger-text`，`#b91c1c` | 备份失败、晚完工超过 10 分钟 |

- 普通完成率没有业务目标阈值时，不擅自染红或染绿；未连接和未知不伪装成健康。
- 非交互蓝色标题不作为通用规则。现有蓝色进行中状态保留明确状态形态，不将蓝色扩展成任意装饰字色。
- 状态同时有文字，必要时再配图标；不能只让人分辨颜色。普通文本以至少 4.5:1 对比度为目标，深浅主题分别核对。[S4、S7-S8、S12-S13]

### 5.3 控件与按钮

- 同一工具栏的输入、选择和按钮统一 32px；需要持续录入的表单统一 36px。两档按用途区分，不把全系统的不同用途强行做成一种尺寸。
- 图标工具默认 32×32px、图标 16px，名称可由悬浮和键盘焦点获得；不是靠微小符号猜功能。
- 一个明确的工作区只突出一个主要提交动作；次要操作用普通按钮，行内导航用轻量动作。不为凑“主按钮”而突出禁用的生产功能。
- 刷新、关闭、展开、上一页等熟悉工具用正确图标；采用方案、导出 CSV、处理缺项等业务命令保留文字。不能让同一个历史图标同时代替刷新、日志和重置。
- 数值输入保持固定合理宽度，单位紧邻输入；字段错误显示在字段附近，不推挤同排其他控件。
- 配置草稿用复选框，保留“样例草稿”“检查通过，未保存”等状态。真实即时偏好与草稿设置分区；主题现有单选已经有效，不为外观统一重造控件。开关的即时语义参考 Fluent，而不是一项新的业务规则。[S10]

### 5.4 间距和容器

沿用现有 4/8/12/16/24/32px 间距档位：字段标签到控件 4-8px、同组控件 8-12px、组内分段 16px、主要区块 24px。整体保持左侧阅读起点一致。

表格优先使用可用宽度，配置表单则按内容限宽。普通单行表格试排 40px、双行 56px，长内容自然增高；这不是为了首屏行数而固定裁切高度的规则。输入框、表头和主要数据不使用 11px 字号来换空间。

## 6. 两个重点页面

### 6.1 报表中心

建议阅读顺序如下，仍使用原有五个专题和现有组件能力：

```text
报表中心                         刷新 / 查看复盘 / 查看实际甘特
来源身份与数据截至时间（清楚显示，但不重复铺多段）
现有报表专题
常用筛选：来源 / 计划完工日期范围 / 批次 / 搜索 / 更多筛选
非默认条件摘要；需要时显示缺数警告
当前专题关键指标（保留分母及必要短口径）
明细名称与数量                  排序 / 顺序 / 导出 CSV
明细表格
分页
趋势与分布（原入口，按需展开）
数据范围与计算方法（原入口，按需展开）
```

具体取舍：

1. 整理的是首屏已有内容的分组、去重和排列位置，不仅仅是工具栏。合并明细标题、数量、排序和导出，不给它们各占一层。
2. 次要筛选在原筛选区内收展，不新增抽屉或新的导航。已生效条件收起后仍显示实际值，并可清除；不能只显示“已筛选”。
3. 必须常驻：来源是否示例、按计划完工日期选工序、数据截至时间、影响统计的缺数警告。数据截至时间不是点击刷新的时间。
4. 指标的分母、未确认不等于未生产、未知工时未计入等短信息保留在相关结果附近；长公式解释和趋势入口不再占据表格之前的大段高度。
5. 对没有额外警告且筛选收起的默认状态，表格顶部试排目标为 1920 宽度约 360-420px、1392 宽度不超过约 460px。展开条件或出现警告允许下移，不能为了达标藏警告、截文字或缩字。
6. 用不少于 10 条记录的样例检查首屏阅读量；当前仅 5 条的样例应尽量完整展示，不补造记录。指标、表格和导出仍使用同一数据范围，导出不改成仅导出可见行。

Carbon 的表格空间和工具栏原则、Fiori 的筛选摘要与标题去重支持上述方向；具体排列和像素目标是本项目提案。[S2-S3、S6]

### 6.2 系统管理

- 定位是本机维护工作区，不是云端运维控制台；沿用已有本地能力，不借改版新增云端功能。
- 保留“概况、备份恢复、运行日志、配置”四个页签和当前来源切换，不再引入新的设置导航。
- 概况把维护事项作为主要内容，页面环境自检为次要内容；1920 下可并列，较窄时根据可读性上下排列，不强留狭窄表格。
- 顶部四项状态收成克制的状态带。页面依赖 8/8 只说明页面检查，不代表数据库或备份健康。
- 配置区分“即时页面偏好”和“样例草稿参数”。配置正文按约 960-1120px 的内容宽度试排，两组参数不拉满整屏；标签列约 140-160px，数值和单位紧邻。长标签允许换行，不能硬截字。
- 同一配置区内保留参数行、备份/日志分组和提交区的必要细线。规则说明使用现有展开入口，避免常驻大段解释挤占参数区；是否保留右侧说明区由整页样稿比较决定，不预先锁死三栏布局。
- 备份与日志保持表格、筛选、分页、详情和导出能力。整表操作集中，行内详情轻量；未连接、读取失败、确实为空必须继续区分。
- 灰白工作面承载内容，彩色文字表现失败、待处理和通过；不靠给每个模块换一种底色来分区。

## 7. 全页面覆盖方式

总体方案覆盖全部 14 个主页面及独立试调样板，但不能视为一次没有风险的小修。以下是批准的应用和复核范围；实施情况与实际验证结果另记于本轮修复记录。

| 页面组 | 页面 | 应用重点 |
| --- | --- | --- |
| 数据列表 | 基础资料、批次管理、主数据总览、工时定额校准 | 筛选与整表操作同区；字段/单位对齐；列表和详情保持关系；不必每页强加指标条 |
| 排产决策 | 执行排产、选择排产方案、交付风险 | 规则与检查同排对应；结论与动作相邻；同面板内保留细线；方案身份常驻 |
| 甘特工作区 | 计划甘特、方案试调 | 先保证时间区空间；工具栏按任务分组；真实重叠、文字完整性和详情关系不可退步 |
| 现场执行 | 现场记录、现场实际甘特 | 录入区字段组与提交区清晰；计划与实际区分；保留必要网格与报工状态 |
| 统计 | 执行复盘、报表中心 | 减少首屏层级；指标与短口径相邻；表格、图表、导出同源；共享 ScopeBar 分别验收 |
| 待办与维护 | 值班台、系统管理 | 重点事项、状态和处理动作形成阅读顺序；普通信息不冒用状态色 |

## 8. 文案一起统一，不机械替换词语

| 现有说法 | 建议给用户看的说法 | 必须保留的含义 |
| --- | --- | --- |
| 工序兑现 | 工序完成情况 | 不是批次交付 |
| 应完兑现率 | 到期工序完成率 | 已确认完成 / 计划已到期，不等于按时完成率 |
| 应完未闭合 | 到期未确认完成 | 未确认不等于未生产 |
| 超容差晚完工 | 晚完工超过 10 分钟 | 沿用现有大于 10 分钟的判定 |
| 容差内 ±10 分钟 | 提前或延后不超过 10 分钟 | 这是偏差分布的对称区间 |
| 按时完成率旁的容差说明 | 提前完成或延后不超过 10 分钟，按现有规则计为按时 | 不能错误改成只有 ±10 分钟才算按时 |
| 超时未闭合 | 距计划完成时间已超过 10 分钟，尚未确认完成 | 不能暗示已有实际完工时间 |
| 账龄 | 距计划完成时间已过多久 | 与已完工偏差区分 |
| 数据时点 | 数据截至 | 不是刷新动作的时间 |

上表中的 10 分钟来自当前模型，不是新业务建议；落地时从现有数值生成说明，不在多处写死。UI、悬浮说明、图例及导出标签一并核对，内部字段、公式、筛选 ID 和导出数值不变。若导出列名被外部程序消费，先核对兼容影响，不能把文案调整当作无影响的接口变更。

## 9. 主代理与 subagent 的讨论取舍

研究阶段实际使用 1 个 subagent，独立检索 SAP Fiori / Carbon，并与主代理往返讨论，完成后已关闭。批准后的实施另使用 4 个 subagent，按报表与复盘、系统管理、数据列表、现场与值班台分工；主代理负责共享规则、排产页面和集成验证。

| 初始想法 | 讨论中的反对意见 | 总体方案采用的结果 |
| --- | --- | --- |
| 整理工具栏就能解决拥挤 | 删除整个筛选区都不够，重复信息和中间层仍存在 | 整理已有首屏内容，不再把范围说成仅工具栏微调 |
| 尽量把表格固定提到某个坐标 | 警告和展开条件会需要更多高度 | 坐标只用于默认态试排，异常信息优先 |
| 换复选框就能修正草稿误解 | 还必须说明只是独立样例，未接入正式保存 | 控件语义和区域状态一起修正，现有主题单选不重造 |
| 重要文字可以广泛使用强调色 | 状态色会暗示业务判断；蓝标题可能被当链接 | 普通重点用中性字重，真实状态才用语义色 |
| 两张大屏稿认可后即可全局推广 | 共享样式会影响不同页面，默认态截图不证明功能 | 先整页比较，再按页面组逐项验证所有原有动作 |

## 10. 后续实施与验收边界

**本稿已获整体实施授权。按同一批页面完整验证，不再逐控件试探；出现实质新增范围或数据风险时再确认。**

1. 先按同一套标准制作系统管理、报表中心的完整页面样稿，作为一批评审，不逐控件拍板。
2. 以 1920×1080 为主要视口，同时检查 1392×924 和深浅主题。长名称、多行说明、缺数警告、展开筛选、已选条件、禁用/空/错误/成功态必须出现。
3. 评审的是阅读顺序、颜色含义、分组是否清楚、按钮是否好找，不仅是控件没有溢出。放大文字后不得以裁切维持首屏行数。
4. 方向确定后再应用到其他页面组；同用途共享样式可以统一，不同工作区不能盲目全局替换。每个页面都列出保留的数据动作并回归，不漏掉原来“不显眼”的功能。
5. 单独验证筛选、排序、分页、跨页返回、导出、配置草稿与计划采用，证明整理没有改变范围或数据。UI、图表和 CSV 的数字保持一致。
6. 继续离线交付，保留现有本地资源和字体，不动生产后端；在 Win7 目标环境检查断网加载、实际浏览器兼容、字体与显示缩放、键盘操作和本地文件交互。Mac 截图、交互回归、Win7 实机验收与生产门禁是不同证据，不互相冒充。
