# 工作台入口与真实只读闭环

## 0. 术语与来源

原型指`前端设计/ui_kits/workbench`，并非生产数据源。工作台指新Flask入口及其本地预编译资产。页面依赖检查、数据库可读取、备份文件存在、备份已校验是四个不同状态。

完整目标和共享协议采用roadmap及`workbench-contracts.md`，本feature只完成首个技术闭环，不缩减后续206能力族的范围。只读投影可被后续系统维护feature复用，暂不提供维护写入动作。

## 1. 决策与约束

- 采用项目默认复杂度档位；独立工作台Blueprint，不把页面逻辑追加进factory或旧system路由。
- 主入口先为`/workbench?view=system`，旧`/`和全部旧路由保持可用，最终退役由roadmap第18/19项负责。
- 样板资产进入仓库可重建的源目录，预编译交付；不依赖Git忽略目录才能重建，不在目标浏览器编译JSX，无CDN和目标机Node要求。
- 先支持系统概况真实读取。未迁移页面/维护动作明确不可用，不挂样例冒充真实数据；原型继续作为独立设计基线，不改其文件。
- 测试进程在导入app之前设置隔离数据库、日志、备份、模板目录；不能在当前用户库做GET自检或维护测试。
- 明确不做：本feature不改schema/业务表、不开备份恢复删除、不改变排产算法/正式版本、不开启其他页面演示写入，也不提前下线旧页。

## 2. 名词与编排

### 2.1 名词层

现状：`index.html:305`起本地React/Babel运行时加载；`SystemManagementScreen.jsx:182`使用固定管理样例或未知状态；`web/bootstrap/factory.py:244`只注册旧业务蓝图。

变化：新增预编译资产manifest、WorkBench启动配置、真实系统概况和统一QuerySuccess/Failure。`GET /api/workbench/v1/system/overview`读真实请求连接、日志/备份目录元信息与只读配置，返回`{database,backups,logs,config,maintenance}`；业务查询不创建目录/补默认配置/执行备份，读取失败明确显示。meta按共享合同带schema_version/source/as_of/snapshot_ref；快照引用在本只读功能只用于辨认本次数据，不充当写令牌。

示例：空测试实例的数据库可读取，备份目录存在且无文件 -> 显示“可读取”和“暂无备份”，不是“备份健康通过”；目录无法读取 -> 局部错误而非数量0；API/依赖失败 -> 显式错误和重试，不回退样例。

### 2.2 编排层

```text
修改前源码备份已核验
  -> [离线源导入/编译 | 系统只读投影 | Blueprint/请求外壳]
  -> 模板加载manifest及live入口
  -> 浏览器同源请求系统概况
  -> 呈现真实状态 / 显式错误 / 重试
  -> 隔离接口与109浏览器验证
```

现状：原型自行生成管理状态，无后端请求，原型CSS不在正式资产包中。

变化：Flask提供独立HTML宿主和同源只读API，浏览器transport严格解析协议，系统页面只从当前响应呈现。旧入口不被截走；未建好的asset manifest返回明确503而不是返回缺资源的200空页面。并行节点写集分离，由主代理集成。

### 2.3 挂载点

- factory中的工作台Blueprint注册；移除后新入口消失，旧页面仍可独立运行。
- 工作台独立模板和asset manifest；移除后新入口明确不可用，不影响旧static。
- live入口中的系统页面登记和transport；移除后不再执行该真实读取。

### 2.4 推进策略

第1步并行实现资产、只读计算节点和协议/外壳；第2步集成真实系统页面；第3步隔离后端及Chrome109验证。三步分别按退出信号收口，不把正在运行的验证标成done。

### 2.5 结构健康度

不做无关微重构。factory仅增加注册挂载，不继续堆业务；全新代码按资产构建、请求协议、系统投影和页面呈现分责。旧大组件只导入/复用必要部分，不在旧文件上同时改业务和视觉。

## 3. 验收契约

- 两种主题、1920×1080和1392×924打开新入口，样板侧栏/页眉/分区/控件尺寸保持，页面非空无整页横向溢出。
- 系统概况响应含真实临时库/目录/配置事实；刷新和重复读取不改变业务表或配置，不把缺省读取变成写入。
- 断开/非法JSON/协议不匹配时显示失败，可显式重试；不会显示样例健康或假保存成功。
- 主题继承既有本机偏好，切换和刷新保持；偏好保存失败明确提示，不改计划状态。
- 资产均从同源本地加载，JSX已预编译，构建可从导入源独立重建，源码来源和内容哈希可查。
- 旧首页/旧关键入口仍保持原合同；生产数据库/原型/他人暂存修改未动。
- 不以本feature检查证明其余页面、维护写入、完整压测或Win7真机已完成。

## 4. 后续衔接

完成后为主数据、计划查询和完整系统维护提供统一宿主与错误处理。只有实际验证满足第3节才回写本item done；完整goal仍由19项及全部验收共同决定。
