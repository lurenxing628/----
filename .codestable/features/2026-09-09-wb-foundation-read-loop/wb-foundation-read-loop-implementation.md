## 验证过程发现并处理的问题

1. 新投影/资源加载函数复杂度超限：按结果解析、结果判定、资源校验拆分，未添加门禁白名单。
2. 自检在 DOM 挂载前执行，首次误报样式不可用：改为挂载后检查；保留真实 DOM 样式标记判断。
3. 新 HTML 入口仍触发旧自动维护：将本阶段三个只读入口一起豁免，旧首页行为不变。首次手动实例确实发生缺省配置补写，已关闭，不能作为只读通过证据；修复后的新实例重新验收。
4. 畸形 200 响应可能绕过五个顶层状态检查并导致渲染崩溃：新增实际消费字段合同校验，转为明确失败及重试。
5. 旧页面更新主题被原型残留键覆盖：以已有 `aps_theme` 为正式偏好，`aps_kit_theme` 仅兼容首次原型迁移来源。
6. 请求缺少时限、维护中止返回旧协议：增加覆盖响应体读取的20秒超时；维护锁保持生效，仅统一新只读 API 的失败格式。
7. 文件表沿用样例的按列序号宽度，短文件名被挤折而大小列留白：改为按真实列合同设宽，文件名使用剩余宽度，增加四档浏览器断言。
