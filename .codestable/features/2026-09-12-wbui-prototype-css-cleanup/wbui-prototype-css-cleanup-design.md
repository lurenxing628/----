# 原型样式清理

## 0. 术语与依据

死规则必须有实际源码证据：限定于当前导入的原型入口闭包及生产 foundation/app 中无元素创建者，且无对应动态类生成；或同一条件下同选择器同属性被后置规则确定覆盖。仅截图中没命中不是删除依据。

## 1. 目标与范围

用户已授权整路线图实施。此项独占 `前端设计/` 的被导入 CSS/入口内联 CSS 与协调指定的 SMOverview 自检折叠；必须经 `import_prototype.py --update` 更新快照，主线程统一构建，不修改 static 或其他 owner 在途 app JSX。

目标是减少有证据的冗余，字号使用 12/13/14/17/22/28 令牌，保留日期弹层、窄屏弹窗、打印和触屏专用媒体条件。现有演示组件仍使用的样式不按“生产未加载”粗暴删除，保留观察结论。基础资料产能链首屏结构不变。

## 2. 接口、流程与挂载点

现状：114 文件快照与 `前端设计/` 哈希一致；生产构建使用受控 foundation 声明与 live 清单，原型入口仍引用历史样式。

流程：冻结原始源文件及统计 → 原型与生产创建者核对 → 删除限定死规则/确定覆盖声明 → 字号令牌映射、明确别名和桌面断点收口 → 原型样式合同对照 → 源到快照导入 → 主线程统一构建/浏览器验收。

保留每条删除的源路径、原行号、选择器、删除文本、判定依据及前后哈希。数字字号选最近的现有档位，等距向上；不改字体家族与数据。颜色仅替换已明确同语义的硬编码，例如白色主按钮文字映射 `--ui-text-inverse`，不猜测调色板语义。

挂载点仍是 source-manifest 与原有 CSS 加载顺序，无新增产品 API。SMOverview 的“页面环境自检”改为默认关闭 details，诊断数据和原时区转换保持。

## 3. 验收契约

- 变更清单可从本轮冻结原始字节复核，删除规则在导入闭包及生产代码中无固定或动态创建者。
- 非法 CSS 不被导入；字体不再使用半像素声明；桌面断点统一时不吞掉小视窗专门行为。
- 原型哈希校验通过，导入不更改 app 文件；已有原型样式测试区分改前既有失败与本轮回归。
- 总构建及当前工作区浏览器几何验收由主线程完成，本线程不提前宣称 G1–G6 或整仓门禁通过。

## 4. 文档边界

记录当前残余 app 内联 style 清单交主线程安排。其他代理完成前不批量迁移其 JSX，避免并发覆盖；生产样式落层由当前任务持续收口。
