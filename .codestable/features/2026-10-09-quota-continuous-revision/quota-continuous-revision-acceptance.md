# 1. 接口契约

普通保存、工作台保存、CSV/XLSX 工时导入和校准采用共用 `ProcessTemplateHours.revise`。旧锁服务、查询、写入、导入跳过和替换工种阻断全部退役。采用预检返回 `latest_adoption`，新回执不再返回 `locked`；旧回执仍原样查询和显示。工艺文件预检不再要求文件摘要，仍保留解析内容和写事务中完整预检重核。

# 2. 行为与决定

v39 保留每个已有采用行的版本、旧值、新值、原因、人员、时刻和样本依据，去掉模板引用 UNIQUE，并删除锁表及触发器。历史行的不可更新/删除/替换规则只保护历史，不阻止当前模板继续修订。真实工种变更清除原工时。校准样本仍认同模板版本，至少 5 条、最近最多 20 条中位数；没有后台自动改定额。

实际检索：当前 `core/services/process`、`core/services/workbench/process`、`core/services/workbench/calibration` 和对应前端及静态资源无旧 `quota_protection` 引用、`calibration_quota_locked`、`quota_lock`、锁定跳过状态或导入 `file_sha256`。移除共同 `revise` 会切断三类定额写入；移除 v39 会使旧锁结构无法升级，当前新 DDL 因而不能用于旧库。这两个挂载点各承担独立职责。

# 3. 验收与实际验证

最终同一代码状态的 17 项 Python 用例通过（`17 passed in 9.25s`），包含连续修订、采用事务、旧计划迁移、旧路线保留/清空工时、新库与完整旧迁移链结构一致性、应用启动及离线资源冒烟。初次用例的三处夹具/断言问题已修正；旧路线验证发现模板 Model 将 NULL 转成 0，已从读取源头改为保留未知值并完成相关重验。


- 旧锁迁移前后的所有业务表逐行相同，只有锁表退役。迁移 DDL 失败时采用历史和旧锁完整回滚。
- 同一模板经普通保存、工作台保存、CSV、XLSX 四次修订，引用不变、版本递增；旧采用值仍是 3。旧批次工时、排程和历史计划逐行相同，新批次取得最新 7.5。
- 再积累当前模板版本的 5 条真实完工记录后可再次采用，历史保存 `(1,3)`、`(3,6)` 两笔。样本不足时人工仍能保存 8。
- 同值采用不推进工时版本，但新增历史事实使原预检过期；重新预检后仍可采用。
- 工作台路线与归属两种实际工种变更都保留原模板引用，清空不适用的旧工时；旧路线重建入口只在工种相同才保留工时，实际工种变化保存 NULL，模板 Model 不再把未知工时读成 0。
- 原采用事务回滚与双连接竞争用例通过。早期带计划数据的升级回归证明备份原始行、升级后的计划引用及再次启动均保持原职责。
- `quota_revision_contract.cjs` 通过：有过采用记录仍可预检，新回执不要求锁字段，旧回执可查询；采用确认说明及工时导入统计无永久锁。
- 7 个受影响前端资源使用固定 Babel 7.29.0 / Chrome 109 目标实际编译并写入本地静态目录。只编译受影响文件，没有运行生成哈希的完整构建器；相关清单的旧摘要及整个旧 build_id 已去掉，其他任务的清单内容保留。
- 实际浏览器使用临时本地组件页，真实 React 与已编译采用控件，测试数据及通用 Modal/Button 包装器；验证确认前后按钮状态和“以后仍可继续修订”的结果文案。未连接用户数据库、未在浏览器实际提交生产采用。截图：`evidence/QuotaContinuousRevision/adoption-result.jpg`。
- 改动 Python 文件 `ruff check` 通过，29 个工作区改动 Python 文件通过 Python 3.8 语法解析；暂存运行产物检查及 `git diff --check` 通过。

验证入口是仓库保留的 pytest、Node 契约、固定编译器和暂存产物检查。为遵守本轮禁止运行哈希，当前任务的 Python 业务验证用测试替身隔离已有摘要函数：按完整输入相等性分配测试身份，并在执行期禁止 `hashlib.sha256`。SQLite、业务写入、版本、事务、回执内容、迁移、报工与样本选择执行真实代码；未验证摘要算法本身。未新增摘要脚本、文件指纹或哈希清单。
