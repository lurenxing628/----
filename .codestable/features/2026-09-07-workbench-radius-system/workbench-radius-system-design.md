## 0. 用户确认

用户接受上一轮方案并要求“先把这一版保存了，然后调用 Sub agent 并发修改”。实施范围是当前工作台入口及其实际子页面，不是生产后端和旧独立方案稿。本轮连续完成已批准的统一、回归和记录，不重复请求同一授权。

## 1. 目标与边界

- 现状：表格/统计已经扁平，部分图表、内容分区、内部容器和弹出菜单仍混用 5/6/8/10/12/14px 及胶囊形状。
- 变化：通用内容面 0px、普通控件 4px、浮层 8px 三档。圆点、原生单选、真实开关滑块和微型图例等功能图形保留。图标内部 SVG 几何不受圆角规则影响。用户后续明确要求产能链主线保留原版圆角，因此该专用图作为局部例外，不推广到下方统计和表格。
- 普通页面内容区不包浮卡；同级标题对齐。可独立选择的方案卡、资源入口卡可保留边框和 4px 圆角。甘特外框 0px，内部任务条/状态标签 4px；实际时间位置、长度、虚实线和业务色不变。
- 报表页“资源负荷”去掉独立外框/背景/整块 padding，与超期明细平级对齐。用户追加要求两区等高：桌面两区共用同一网格行高度，标题固定，真实表格与资源列表填满数据区；不添加空白记录，不写死行数。窄屏堆叠时恢复自然高度。设备名、百分比、负荷条保持原有数据和功能。
- 不新增依赖、业务数据、计算、流程或后端接口，不改变现有输入校验、事件、导入/导出文件、自动完工规则和更正审计。

## 2. 实现组织

先完整保存并验签 -> 共用三档令牌和局部组件适配 -> 四个互斥写范围并行 -> 主代理整合 -> 原入口回归与样式检查。

共用层在工作台目录内扩展，普通 DS Button/Meter 通过局部适配继续委托原组件，不改全局 DS 或 bundle。原生页面和图表直接调整原样式声明，避免在不相干位置堆叠覆盖。跨页筛选浮层用工作台 body 标记限定样式作用域。

结构健康度：不做行为无关的大型拆分；已有样式文件按原职责修改，共用令牌不扩散到生产端。没有新增业务实体或公开后端合同。移除本轮局部适配、样式接入与静态 class 即可撤销形状规范，不改变数据模型。

## 3. 验收

- 备份完整覆盖前端目录与相关测试，复制前后文件摘要一致；原暂存内容不动。
- 当前 12 个主入口、上下文延期页及实际原生/批次子页，同用途组件遵循同档半径；表格内外容器都检查。
- 报表左右标题及内容起点按平级区域组织，不再一侧表格一侧卡片。
- 小卡片原有留白和长名称换行、响应式布局、日期浮层、筛选/排序/选择/列宽处理不回退。
- 产能链主线按保存版恢复圆角分组、边框与轻阴影，保留 28px 图标、12px padding、13px 名称及换行、1280px 纵排；不回退主线以下的新规范。
- 深浅模式形状一致；旧对比度和甘特几何/状态合同不回退。选链主动淡化态、圆点和真实开关保持功能例外。
- 明确区分源码/JSDOM/CSS 合同验证与浏览器像素验证；不把局部测试说成整仓 clean proof。
