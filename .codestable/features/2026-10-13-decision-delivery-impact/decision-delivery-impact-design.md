# 第 2 阶段：交付影响

## 0. 术语

- 搜索覆盖：各候选是否计算完成；兄弟候选失败或预算跳过单列。
- 可排工序覆盖：本次应排工序是否齐全；合法待料暂缓从应排集合中单列，普通漏排保留。
- 全链交付覆盖：每个批次全部工序的安排与完工；合法待料暂缓仍显示后道未完成。
- 比较基准：同次候选，或受理时归档的正式计划。差值均为所选候选减基准。
- 交期状态：`specified / unspecified / invalid`。`9999-12-31` 为未指定；缺失和非法值保留具体原因。

## 1. 决策与约束

主对话已按用户第 0—8 阶段连续授权派发第 2 阶段。前置第 0、1 阶段实施验收和两项返修的主对话复验均通过。本阶段完整实现主方案第 4.2、6、8.3 节；完成实施验收后交回主对话，第 3—8 阶段等待逐段派发。

采用现有离线、单机、Win7 x64 / Python 3.8 产品结构和工作台控件。共同规则归入已有交付投影，各调用者提供自己的保存事实。算法保存的评分、选择结论和正式采用事务沿用原职责。受理时正式基准从归档读取；当前资料变化不改变历史比较。

正式基准按每道工序在受理版本及以前的最后正式安排归并，保留多段、原来源绑定、零工时实际工作和合法待料事实。只解析归档绑定的不可变候选或试调来源；当前 Schedule 和业务目录不作为历史回填来源。旧显式历史版本 API 保留原版本范围，当前候选分析/值班台比较使用共同归并范围。缺正式基准与具体来源缺项分别表达。

计数合同：`due_eligible_count` 计 specified，`excluded_due_count` 计 unspecified，`invalid_due_count` 计 invalid；三者合计批次数。`due_evaluation_count` 为 specified 加 invalid；已知/未知交期数量合计此评价范围。完整且交期合法的批次为已知，非法交期或未完成的 specified 为未知；全 unspecified 才是 `not_applicable`，拖期为 null。指标保留已知小计，未知覆盖使全范围总值为 null。

## 2. 名词与编排

### 2.1 现状 → 变化

现状：`plan/delivery_projection.py` 已负责批次全链完工与交付风险，`candidate_delivery.py` 和 `candidate_comparison.py` 有各自汇总；第 1 阶段 `decision_metrics.py` 又独立计算交期。候选详情、正式计划、值班台和试调各自校验与显示交付状态。

变化：所有入口消费共同批次投影、汇总和成对差值。工艺完成性与交期评价分别表达；未指定交期保留其独立状态。总览消费同一规则，新增批次、工序明细消费同一 scope 与永久身份。

例：所选候选完整排出批次 A，交期为 `9999-12-31` → 全链完成、未指定交期、拖期 null；候选 B 漏排有交期批次的后道 → 部分完成、交期评价未知、拖期总值 null、已知小计独立显示。

批次影响包含身份、零件、优先级、数量、交期、双方完成状态与完工、拖期差、提前/延后、新增/解除超期和未排工序。工序按永久身份匹配，包含双方起止、设备、人员、变化类型、工时需求、执行/冻结及已有约束事实。未保存的变化原因用可核对的已知事实表达。

### 2.2 编排

保存的运行与归档 → 选择候选/比较模式/基准 → 总览 → 按需加载批次交付或工序变化 → 筛选、排序、分页 → 钻取同方案甘特 → 恢复原比较上下文；明细导出直接消费相同数据与筛选。

同次候选模式与受理时正式计划模式共享 scope。缺正式基准时明确显示缺少基准，所选候选事实仍可查看。批次/工序默认 20 行，可选 50；空值排末，同值按永久身份稳定排序。整表导出读取相同筛选的全部记录，页码只影响屏幕。

总览、批次交付、工序变化用页签组织，当前选择与操作保留首屏密度；沿用第 1 阶段行表。甘特按批次或工序永久身份定位，带所选候选、比较模式、基准、时间窗、明细页签和列表条件的返回上下文。

### 2.3 挂载点

- 现有工作台 decision 路由注册批次和工序查询，并扩展同一导出入口。
- 同一 decision 路由增加正式基准只读 workspace，前端甘特入口按 `reference_view` 分派；显式 URL 通过既有 navigation_boot 校验。
- 候选 analysis 工作区挂载批次交付/工序变化页签，原甘特工作区接收批次/工序定位及返回上下文。
- 候选、正式计划、值班台、试调及对应导出的交付读取调用共同投影；既有前端消费同一状态枚举与汇总值。

### 2.4 推进策略

共同交期/完成性与旧入口迁移、决策明细服务、前端明细及旧枚举适配分工实现；接口字段直接协同。相关契约和实际浏览器/导出验证贯通后，同步架构、需求、说明与实施验收。主对话独立验收结论单列。

### 2.5 结构健康度

交付规则和汇总当前分散，统一在现有投影职责内，删除替代的重复计算。明细按独立投影组织，避免把所有明细塞进总览回复。分页、导出、筛选共享服务数据；错误由实际负责边界表达。

## 3. 验收契约

- C01：specified、unspecified、invalid 混合与全 unspecified；原始原因、三组计数、已知/未知覆盖、null 和 not_applicable 一致，算法原分数保持。
- C02：完整、普通漏排、合法 stage 待料；搜索、可排工序、全链交付分别准确；双方完成集合不同的交付差值显示覆盖事实。
- C03：候选对候选及候选对受理时正式计划；修改当前资料后回看仍用归档，无正式基准时明确其缺失。
- C04：逐批/工序身份与数值准确；恶化/改善/拖期排序、变化筛选、20/50 分页、空值与同值稳定顺序正确。
- C05：批次/工序钻取正确甘特定位；返回保持模式、候选、基准、范围、页签、指标视图及列表条件，浅深桌面尺寸可用。
- C06：批次/工序 CSV/XLSX 与屏幕 scope、身份、筛选、数值一致；普通文字原样、空值留空，XLSX 数值类型保持。
- C07：共同规则实际接入候选、正式计划、值班台、试调与导出；相关契约、适用日常门禁、离线构建和文档同步完成。
