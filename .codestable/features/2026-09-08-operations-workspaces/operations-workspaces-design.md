# 三个工作台的实施方案

## 0. 授权与术语
- 用户已授权“直接做，完成以后验收”，本文件记录实施取舍，不表示已完成人工验收。
- 三个入口：执行复盘·报表中心（两个子视图）、主数据总览、系统管理。
- 当前会话指页面内存数据；独立样例只供复杂场景演示。两者都不是生产数据库。
- 已报有效工时、计划时间跨度、资源利用率是不同概念，不相互替代。工序完工不等于批次准时交付。

## 1. 决策与约束
- 属于 `前端设计/ui_kits/workbench` 的交互原型，保留现有正式页面和后端边界，不改生产服务。
- 布局采用现有平直指标条、表格、左侧筛选和右侧数据操作；长表分页，详情就地展开或侧区显示。浅深色共用已有颜色变量，不重新设计甘特或产能链。
- 复盘只读当前报工模型和独立场景；主数据从基础资料同一会话快照读取，不复制一套计数；系统把本页可检测状态与未接入的生产健康、备份、日志分开。
- 每个下载生成与当前筛选一致的真实文件；不以提示框冒充 Excel、备份或写入成功。
- 明确不做：生产数据库连接、真实备份恢复/删除、调度算法修改、联网认证、OEE/成本/良率推测、新运行时升级。
- 复杂度：原型默认档位，增加密集数据、空结果、缺失值、长文本与跨页一致性验证；不宣称正式生产容量已验收。

## 2. 设计
### 2.1 数据与能力
现状：`ReportsScreen.jsx` 的 KPI 与三条明细独立写死；`app.jsx` 将主数据总览映射到设备列表、系统管理映射到通用演示列表。

变化：
- 报工任务/报工记录 → 同源统计、工序复盘、资源工时汇总和导出。例如当前报工 5 道工序、4 次记录、已知工时 7.5 h，工时待补不能当作 0。
- 基础资料会话 → 只读实体快照、引用/完整性检查、问题到维护入口。未加载与实体数为 0 必须区分。
- 系统管理 → 当前页面检测，以及明确标记的管理样例；生产能力可见但没有服务回执时不得显示健康/成功。
- 生产复盘数据身份仍遵循 `core/services/report/execution_review.py` 的正式采用方案限定；将来接线直接消费公开字段和中文标签，不另造状态解释。

### 2.2 编排
```mermaid
flowchart LR
  A[选择工作台与数据范围] --> B[读取已有模型或只读快照]
  B --> C[计算统计与缺口]
  C --> D[搜索/筛选/排序/分页]
  D --> E[详情与原页面维护定位]
  D --> F[当前筛选结果导出]
```
现状是三个孤立演示页面。变化是页面在导航或刷新检查时读取同一会话，样例切换隔离，生产操作无连接就明确不可用。系统检查仅检查前端，不调用生产 API。

### 2.3 挂载点
- 报表路由的新两个子视图。
- 主数据路由与基础资料只读快照/定位入口。
- 系统路由及主题设置回调。
- 原型入口的本地脚本与样式资源注册。

### 2.4 推进
1. 核实字段、登记能力边界与各页职责。
2. 三个独立页面并行实现，主代理接入入口、本地依赖与页面上下文。
3. 分页/过滤/导出对账、同源变更回读、现有页面回归。
4. 留实现证据，用户现场检查观感与提出修改意见。

### 2.5 结构健康
不做独立微重构。页面计算从视图分离到各自模型，页内 CSS 隔离；主数据只加必要快照与导航接口，不改基础资料既有编辑逻辑。现有大文件只做挂载点修改，不扩大为全仓治理。

## 3. 验收契约
- 当前报工修订后重新进入复盘，统计与明细同时变化，不丢草稿。
- 复杂/密集样例可筛选分页；空结果不保留旧明细；导出覆盖当前筛选全量而非本页。
- 无实际完工时间不计算完工偏差；无日历可用时长不声称资源利用率；缺数据与 0 区分。
- 主数据列表与维护页来源一致，修改后能回读；问题可定位到相关维护域。
- 系统未连接时不显示生产健康/备份成功；样例操作不能进入真实备份/恢复/删除 API。
- 不新增外网资源。现有三个远程依赖按相同版本、相同摘要本地化。
- 新页面控件可键盘操作，长文本可读取，表格限定横向滚动范围；两主题采用现有语义颜色。
- 验证是局部模型/DOM/CSS 合同；真实浏览器页面访问此前被拒绝，不绕过，不以 DOM 检查冒充像素验收。
