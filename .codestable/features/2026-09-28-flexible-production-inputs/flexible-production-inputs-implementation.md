# 分阶段生产输入实施记录

用户已批准三项能力，并明确40/100先预览确认拆分、排产页提供选项、默认08:30–11:50及13:30–17:30、页面可改默认、复用原样式、只跑相关测试。本次未运行日常/全量门禁，未提交、推送或修改生产数据库。

## 最终实现

1. v34多时段日历：全局/个人/轮换逐段维护、文件一日一行、可持久修改默认工作时间；旧明确班表保持原值。统一实际工作区间处理午休、跨夜、效率与日历容量，历史版本34前的归档按旧默认解释。
2. v35设备多工种与工种双归属：保留Machines原主工种，MachineOpTypes增加能力；工种category可为both，工序source仍明确internal/external。页面、可读文件、资源统计、人员技能/设备授权、排产候选和采用校验同步。扩展工种适用范围不抹掉已确认的工序归属。
3. v36分阶段物料：使用工序绑定准确实例ID；批次已有到料与逐次带日期到料分开，避免双计；核对批次数量后保存需求。按当前日期只读计算齐套显示/筛选和值班台风险，查询不落库。数量改变后旧需求需要重新核对。
4. 排产本次strict/stage/split选项。按工序放行将日期下界绑定算法输入；缺料影响当前及后序，合并外协段等所有成员用料齐后整段发出。候选、正式采用、正式计划摘要及试调保留策略。
5. 数量拆批使用已有预览令牌、事实指纹、命令回执、事务：100→40/60，保持需求/已有量/逐次到料总量，按准确旧工序ID→新工序ID重新关联。取消不写库、重复确认不重拆、并发变化拒绝、晚期故障全事务回滚、受保护批次不能拆分。确认后界面选择子批，仍需用户检查并启动计算。
6. 界面使用现有ResourceControls、WorkbenchControls、Modal、Field、Button、表格和布局类；本次feature没有新增或修改CSS。默认时间和拆分弹窗均在Chrome109真实页面验证并检查截图。

## 验证边界

相关测试按功能分批执行，范围与日志见同目录验收记录。日历/资源既有相关测试中出现的旧默认值断言、旧迁移仅允许加表的断言，已改为明确旧8小时测试输入或精确核对新增nullable列；没有改变产品默认来迁就测试。旧schema只读路径明确核对版本，当前结构缺失仍报错。

代码保持Python3.8，静态资源按Chrome109编译、离线随包。Schema导出和模板文档同源检查通过；目标Pyright、Ruff及复杂度检查通过。工作区包含之前278个未提交路径，本轮开始前的快照在/tmp/aps-flexible-production-before-20260928.tar.gz；不是clean-worktree proof。

## 使用边界

数量拆分针对尚未排产/开工、无计划或执行/外协保护的整批工序，按件数同比分配需求。整批固定耗用不能套用同比拆分，页面和手册已提示先人工核对；单件分支不是数量分批，二者不混用。物料总库存不会自动扣减。预览按所选排产开始日期分配到料。
