# 第 3 阶段：资源影响

## 1. 授权与目标

第 2 阶段已获主对话独立验收通过，两项 P3 已关闭。本阶段按主对话派发完整实施主方案 4.1、4.3、8、9 的资源部分；实施、验证和文档同步完成后交回主对话独立验收。第 4—8 阶段等待逐段派发，提交、推送、发布另按用户授权执行。

资源影响回答共同时间窗内哪些设备、人员更紧张，变化来自容量、占用、独立工序需求、班外安排还是冲突。共同规则供新比较页和既有同义资源读者消费。算法保存的分数和推荐证据保留原来源、范围和版本。

## 2. 共同事实与范围

- 工厂本地时间使用左闭右开 `[range_start, range_end)`；默认受理起日 00:00 至截止日次日 00:00。双方与全部候选共享一个窗口。
- `selected_batches` 默认只看本次选批贡献；`full_candidate` 看候选自己的完整安排，正式基准取每道工序最后正式安排的完整归档。候选缺少的正式工序单列覆盖缺口，本次普通未排与合法待料暂缓分别保留。
- 每个视角使用同次全部候选与基准实际涉及的永久设备、人员并集。切换所选候选和同次候选基准保持资源分母固定；正容量且未使用的资源以 0 参与占用率和均衡度。
- 正式工序覆盖与采用预检共享纯集合规则；具体采用拒绝、身份绑定和事务沿原职责执行。只读比较展示缺口，不代替采用决定。

运行和试调保存的全部日历表、资源状态、永久身份、停机、人员个人日历、轮班及 Schema 版本形成共同日历事实。日期缺少显式例外时按保存版本的默认规则解释。保存资料缺项或无效才表达 unknown；合法休息、禁排和停机扣尽为真实 0。夜班归属开始日，逐自然日包含前日尾段并按现行优先级裁剪。当前业务资料变化不回填历史归档。

当前值班台容量仍提供同事务事实，明确 `current_transaction_snapshot` 来源；它与归档调用者共享计算规则，保留实际事实来源。缺比较对象与已知空安排区分：缺对象的占用、负荷为 null，已知日历容量仍可显示。

## 3. 计算职责

`facts/archived_calendar.py` 负责保存表适配和按日容量，复用领域日历引擎；`resource_intervals.py` 负责永久工序、资源区间索引；`resource_projection.py` 负责窗口、逐日占用与冲突；`resource_summary.py` 负责资源汇总。接口、界面、导出不重新实现算式。

- 可用班时使用班表和停机后的窗口并集；占用为安排与可用窗口交集的并集；需求为每道独立工序各自合并后求和。
- 需求／容量保留重叠压力，占用／容量表达实际资源占用。班外为已知自然日内安排并集减班内占用；未知日保留已知小计。点事件不占资源。
- 重叠冲突提供区间、永久工序和实际行身份；同一工序重复片段先合并，不制造独立工序冲突。
- 日峰覆盖完整窗口；任一已知日占用率达到 90% 计高压力资源一次；零容量有任务、unknown 日和班外安排分别呈现。
- 汇总占用率以总占用／总容量计算；均衡 CV 使用固定集合中全部正容量资源的容量权重。均值为 0 时 CV 为 null／not_applicable；容量或占用缺项保留覆盖和已知小计。

## 4. 服务与界面

decision 共同 query 新增 `resource_view`，scope 携带固定两类资源身份。`resources` 提供设备／人员表、双方整窗汇总、正式覆盖、Top 10 压力／增长和当前资源页的日热力图；`resource-days` 按单资源读取逐日安排与冲突。原总览、批次、工序和导出沿同一比较上下文。

资源行支持身份筛选、压力筛选、稳定排序和 20／50 分页；热力图独立显示 7／14／31 天，日分页只控制显示，整窗汇总始终完整。Top 10 可展开到资源表全部记录。未知值排末，同值按永久资源身份升序。

甘特钻取使用实际侧的候选身份；正式侧使用 `reference_view` 和归档 `plan_ref`。资源、日期、冲突行定位带真实目标范围与工序／行身份。返回恢复模式、所选候选、基准、整窗、视角、类别、筛选、排序、资源页、热力图页和单资源焦点。显式 URL 按现行白名单校验，并保持顶层 `view` 与 `nav.view` 一致。

原候选资源统计、值班台资源比较和试调容量消费共同投影；产品保持 Win7 x64、Python 3.8、离线单机，静态构建目标 Chrome 109。

## 5. 导出与性能

CSV 导出当前资源筛选的全部行，单资源逐日导出完整日期；XLSX 全部增加资源影响表，逐日入口可增加单资源逐日表。资源行的正式缺口、普通未排和待料使用原生数量；XLSX 另以“覆盖工序”表逐侧、逐分类、逐永久工序保存完整身份，避免将大集合塞入单个Excel格。逐日冲突保存原生工序数量，“资源冲突”表逐区间和实际成员保留工序、行及批次身份。导出复用相同 service、scope 和 snapshot。数字保留数值类型、null 留空，百分数按单位转换，沿用文本编号和 CSV 公式保护；指标口径表的常用标记与实际来源分别表达。

请求内复用归档解码、日历和资源区间索引。20k 任务／候选、4／6／8 候选沿主方案目标验证；40k 资源日是分块预算，完整汇总遍历全部资源日，显示明细按需生成。单资源逐日索引只查相交安排；分页和热力图页不进入 snapshot 的事实绑定，视角、窗口、集合和业务筛选进入绑定。典型查询以 2 秒为目标，Win7 实机性能留最终整体验收。

## 6. 验收契约

- C01：固定资源集合和共同窗口；正容量空闲 0、跨日裁剪、边界相接、重复片段与不同资源容量的加权 CV。
- C02：保存版本默认、全局日历、停机、个人日历、轮班及夜班；真实 0 与逐日 unknown 区分，当前变化不影响归档。
- C03：独立工序需求、占用并集、重叠和班外、点事件、零容量有任务、日峰和 90% 高压力数量。
- C04：两种视角、同次及正式模式、共同正式覆盖、缺比较对象和已知空安排、未排／暂缓及旧资源消费者。
- C05：设备／人员表和日热力图、Top 10／展开、筛选排序分页、整窗不截断、实际甘特定位与完整返回。
- C06：资源和单资源逐日 CSV／XLSX 与屏幕原始值、身份、范围、筛选一致，全部表维持统一 scope。
- C07：相关测试、适用日常门禁、离线构建、实际浏览器／导出、性能和文档同步；保留原阶段证据和当前实例身份。
