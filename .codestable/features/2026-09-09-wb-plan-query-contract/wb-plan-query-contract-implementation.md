# 计划查询接入记录

- v24新增持久计划源引用、任务引用及修订计数。正式计划按不可重用版本标识，历史摘要变动不旋转正式身份；候选、角色绑定、场景、执行工序与安排实例分别维护，删除后同编号新实例不能接走旧引用。
- 注册当前版本24、升级入口、schema.sql及新库计数种子。新库只忽略精确未使用的计数种子，不把有业务行、旧引用、已使用计数或缺失计数判为空库。已有残缺引用结构拒绝自动重建。真实v23升级保留全部原表数据，生成升级前备份；重启引用不变。
- `GET /api/workbench/v1/plans`按版本或场景进行有界游标分页，默认20、最大50，不透明游标绑定目录快照；角色条目数不等于版本数。单个超大计划、坏角色绑定及缺失身份只禁用对应目录项，正常条目仍可读取。
- `GET /plans/<plan_ref>/workspace`和详情别名读取精确指定身份及本地半开时间范围。不静默切换最新，不裁剪任务起止，不将没有交集当作整计划为空；超过10000任务或8MiB明确拒绝而非截断。目录快照不能冒作workspace快照。
- 公共DTO仅保留业务标识及永久ref。SQLite int64版本/工序号超出JS安全整数时输出规范十进制字符串；前端拒绝舍入后的number。时间保持工厂本地秒级ISO，不按原型两日日班补齐。
- `PlanAPI.js/PlanContract.js`接入现有只读transport，校验角色、范围、任务归属、完整性和快照；未完整接入的baseline/calendar/occupancy/delivery_risks明确为not_loaded，不伪装空投影。文件已纳入最终构建加载清单，尚未将原计划页面替换为不完整查询页面。
- E/F联合324项通过，前端181个VM断言和19条真实SQLite/Flask响应校验通过；主线程实际迁移7项、计划/构建/工艺汇总综合309通过1跳过，跳过的资产浏览器探针随后指定Chromium109补跑1通过。这些集合有重叠，不相加。万版本有界读取测试保留既有规模证据，本轮未重新跑旧50万明细规模项。
- 统一基线/日历/占用/交付风险投影、同范围导出及页面接合仍待实现，不能将身份与公开读取视为整个feature完成。未提交、未运行全仓交付门禁，无Win7真机证明。
