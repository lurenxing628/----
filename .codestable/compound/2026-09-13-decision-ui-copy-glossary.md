# 决策：工作台用户可见文案统一词表

## 一句话结论

工作台所有用户可见文案（前端字符串、后端返回给界面的 message / label / 列名 / 文件名、模板、页内说明书）按本词表写：**一个概念一个词，内部机制词一律不出现，数字带中文单位，时刻按本机时间显示、标签不写时区**。词表是唯一事实源，`tools/ui_copy_glossary.json` 是它的机器可读版本，`tools/scan_ui_copy.py` 负责扫描残留。

## 背景

2026-09-13 全量扫描前端 209 个文件、后端 300 余个文件和页内说明书，共记录 1,641 处可读性问题。根因不是错字，而是数据契约层、并发恢复层、数据库层的词汇原样进了按钮、弹窗标题、错误提示和导出文件：回执 / 快照 / 受理 / 引用 / 投影 / 实体 / 事实 / 基线 / 上下文 / 协议，以及 `Operators.name` 这类表名列名、`int64` 这类类型名、`\N` 这类哨兵、19 条纯英文排产阻断原因。同一概念在不同域有 4 到 9 种叫法。既有术语表 `WorkbenchTerms.js` 只有 7 个名词 8 个动词且无人强制。

用户裁决（2026-09-13）：允许使用大于号、小于号；所有 UTC 时刻一律换算成本地时间（UTC+8）显示，标签不写时区字样（机器本身就在北京时区，写"北京时间"是多余的）；其余按本词表执行。

## 五条原则

1. 只允许一个概念一个词，词表里每行只给一个"改成"。
2. 用户看得见的东西按界面上的名字叫：侧栏叫"现场记录"就不能叫"执行台账"；提示里引用按钮要写按钮的真实文字。
3. 内部机制不解释，只说后果和动作："数据已更新，请刷新"，不说快照、上下文、回执。
4. 业务词不动：候选方案、正式计划、试调、采用、预检、排产、批次、工序、换型、齐套、外协、自制、图号、交期、报工、工时定额、工种、资格。
5. 例外写进词表，不靠口头约定。

## C. 单位与格式

| 项目 | 规则 | 例子 |
|---|---|---|
| 小时 | 一律"小时"，不用 h | 12.5 小时；表头"换型工时（小时）" |
| 分钟 / 秒 / 天 | 中文全称 | 晚完成 18 分钟；计算用时 3 秒；周期 3 天 |
| 数字与单位、数字与中文之间 | 一个空格 | 20 批、第 1 页、8 MB |
| 文件大小 | MB，不用 MiB | 文件不超过 16 MB |
| 括号 | 中文句里用全角 | 有效工时（小时） |
| 百分比 | 数字紧跟 % | 利用率 96% |
| 比较符号 | 允许 > < ≥ ≤ = | 仅看偏差 > 20% |
| 版本 | 句子里"第 N 版"；表格单元格和页头身份标签允许 v3 | |
| 量词 | 记录条、批次批、工序道、设备台、人员人、文件行 | |
| 时间格式说明 | 给例子不给模板串 | "请按 2026-09-13 08:30 这样填" |
| 时刻与时区 | 值一律按本地时间（UTC+8）显示；标签不写任何时区字样 | 原 UTC 值按 +8 换算；"提交时间 UTC"→"提交时间"；禁止出现 UTC / 世界时 / 北京时间 |
| 空值清除符 | `\N` 允许出现，每次出现都带解释 | 要清空请在格子里填 \N（大写） |

## D. 允许保留的英文和专业词

| 保留 | 条件 |
|---|---|
| CSV / XLSX / Excel / PDF / ZIP | 只作为文件格式名 |
| JSON | 只作为文件格式名；填表要求改成举例 |
| SHA-256 | 只在系统维护的折叠详情里 |
| APS | 产品名 |
| BOM | 计划部门通用 |
| 日志级别 | 不保留英文，改"信息 / 警告 / 错误 / 调试 / 严重" |
| 导出文件名 | 全部中文，形如"现场实际甘特-20260913-0815.csv" |
| ZIP 包内条目名 | 保持 ASCII（如 logs.csv、aps.log_READ_FAILED.txt）；Win7 压缩文件夹按 cp936 解码 UTF-8 条目名会乱码（2026-07-19 D06 审计裁决），中文说明写在文件内容里 |

## E. 句式模板

结果未知这一族提示，前端用 `WorkbenchTerms.outcomes`，后端用 `core/services/workbench/messages.py`，不再各域自己写。

| 状态 | 模板 |
|---|---|
| 查询中 | 上次{操作}的结果还没查到，可能已经生效。请点「查询结果」，不要重复提交。 |
| 被拒绝 | 上次{操作}没有生效：{原因}填写内容已保留，改好后重新提交。 |
| 已成功 | {操作}已完成。{下一步} |
| 结果不确定 | {操作}结果不确定，可能已经生效。请刷新后核对，不要重复提交。 |
| 数据过期 | 数据已更新，请刷新后重试。刚才的选择已保留。 |
| 功能未开通 | 此功能尚未开通。 |
| 程序出错 | 操作没有完成。请刷新重试；仍不行请联系维护人员，并告知下方编号。 |

其他错误提示统一三段式，最多两句：发生了什么 → 哪些没变 → 点哪里。动作要写界面上真实存在的按钮名。禁止只写系统没做什么。

## 落地与守卫

- 前端词表：`frontend/workbench/app/WorkbenchTerms.js`；后端模板：`core/services/workbench/messages.py`。
- 扫描器：`python3 -m tools.scan_ui_copy`，读 `tools/ui_copy_glossary.json`，扫前端字符串、模板和后端返回界面的字符串字面量；测试 `tests/workbench/test_ui_copy_glossary.py` 要求残留为零，例外按文件加白名单。
- 改文案的两类连带：测试断言要同步改；`frontend/workbench/app/styles/37-reports.css` 用 `aria-label="校准明细"` 做选择器，改这句文案前先换成 data 属性。
