# IG 局部任务预算、插入预筛和状态收敛后的尾段复用

用户在 OR-Tools 源码核查后明确要求“都做了吧，争取有一个大提升”。本决定补充同日 SGS 启动预算决定，授权范围为已讨论的三项实现及必要的完整解码降本。保留“不跑全门禁”、Win7 x64 / Python 3.8、离线交付、完整业务分数和采用前完整解码验证。工作区开始时有 525 条未提交路径，先冻结 4171 个源码及本地资源文件，不替换此前的历史回执。

1. 从 128 道工序起，局部邻域有独立的自身用时预算，仍受全局截止和解码次数上限约束。邻域超时记录未完成和缩小反馈，但不自动结束整个 IG；全局截止继续终止阶段。先以一道工序完成最小邻域，之后破坏规模按剩余时间、已测解码成本和完整验证预留量限制；局部切片不能反复低于已测的单次试算启动成本。大实例以有界任务是否完成调整难度，质量改进统计单独保留，不将贪心任务完成等同于 CP-SAT 的最优性证明。
2. 插入位置先按已有结果的加工时长、工序依赖、资源串行近似和当前目标排序，再送少量新顺序给正式 SGS。近似忽略日历和空档填充，只是筛选启发，不产生可发布时间结果，不宣称安全支配剪枝或保留整个原邻域的最优位置。
3. 断点请求可以携带局部预算检查，SGS 在工序放置之间检查，中止的半份结果不进入候选。已完成的试算仍须通过既有完整验证才可替换 incumbent。
4. 大实例完整参考解额外保留终态。在中段正常续排后，如果参考检查点与当前状态的未来相关部分逐项一致，允许按参考尾段结果回放资源占用、批次进度和图完成事件。必须保持输入签名、剩余优先键、已完成集合、未满足依赖、未来所需前置结束时间、资源时间线、忙时和换型状态一致。只支持原生固定资源的正工时工序；外协、自动选资源和未知回调不采用这条加速路径。
5. 换型历史可忽略历史 op_id 的条件是时间/类型序列相同且所有旧段为正长度、互不重叠；未来正长度工序不能落入这些占用段，因而历史 ID 不会成为相同时间插入的比较分歧。零长度或重叠历史不使用这项等价。
6. 唯一图优先键的大实例维护可排工序堆。堆首仍由原评分器检查；只有其可行性罚分为零时才省略其他 ready 工序，否则恢复完整评分。并列键、小实例和不具备原生输入证明的情况保持原路径。
7. 任何尾段复用的候选被采用或成为下一轮参考前，仍独立完整解码并比较结果摘要与完整分数。重复复算不是可以直接删除的验证；本次通过缩小试算与加速完整解码降低它的成本。
8. 缓存里已有正式评分的原位置仍参加最佳位置比较，近似预筛不能把它丢掉。如果一个新起点并未优于本轮参考，而剩余时间不足以验证它并再搜索两次，则保留已有参考，并记录推迟次数；时间充裕时保留既有退火走法。此项只控制起点变更，不阻止已经完整验证的严格改进进入 incumbent。
