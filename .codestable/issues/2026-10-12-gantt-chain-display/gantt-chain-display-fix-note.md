# 候选方案与正式计划甘特关联展示

## 根因与已完成修改

计划与候选甘特原来只绘任务条，点击选中单任务，悬停显示提示。正式计划的冻结 `process_order` 只用于详情前后序；候选接口没有输出工艺关系。

- 两种 workspace 新增统一 `gantt_graph`。正式计划与既有 `process_order` 共用同次冻结资料读取，候选使用排产时保存的完整资料；日期筛选不截断关系图。
- 共用关键链算法接收显式工艺依赖，支持分件分支、共同工序汇合、零工时点；零工时不产生设备/人员占用边。采用前后使用永久工序引用确定同时间顺序。
- 两个甘特默认显示关键链；悬停显示同零件前后工序及关联线，点击保留，悬停其他工序后移出恢复所选路线。分件路线包含共同工序，不扩散到其他分件；选共同工序展示本批全部工艺分支。
- `GanttGraph.js` 与 `GanttGraphLayer.jsx` 统一路线选择、连线及画面外数量提示；DOM、Canvas、零工时标记共用状态。初始计划不参与当前图的连线坐标。
- 根据用户现场反馈，去掉顺序任务连线的人为回环。等时跨行从任务条边缘直接连接，同轨相接显示短箭头，仅实际时间倒置保留向后绕行。采用原型金色细线，关联路线强调时弱化其余全局链，重合端点的工艺线覆盖资源线。

主要文件：`core/services/workbench/facts/gantt_graph.py`、`core/services/scheduler/gantt/critical_chain.py`、计划与候选 workspace，前端 `GanttGraph*`、`PlanGantt*`、`RunCandidateGantt.jsx`、两处 API 契约、`PointGanttModel.js`、甘特样式与构建清单。已重建 `static/workbench/app/main.js`、`workbench.css`。未新增密码算法、摘要清单或数据迁移，未提交和发布。

## 原型复刻核对与遗留

用户进一步要求核对整体复刻程度。已实际打开原型计划甘特及现场甘特，并与当前组件截图、代码逐项对照：**本轮两项功能已补齐，但当前整体甘特仍不是原型完整复刻。**

原型计划页是 `GanttBoard → PlanTimeline`，现场页是 `FieldGanttScreen`；悬停关键链属于后者，不能混称为同一原型。

当前仍有这些偏离：计划图的日期分组轴被逐刻度日期和额外缩略图替代；条内主次文案、资源工时/容量说明及基线布局不同；详情没有原型完整工艺顺序列表；候选图缺原型的“仅变更、展开”；现场图缺原型独立的“状态/偏差”列。原型截图为本轮直接打开源码捕获，数据与真实 worker fixture 不同，只用于结构和视觉核对，不声明像素一致。

`.codestable/roadmap/workbench-prototype-migration/workbench-prototype-migration-roadmap.md:18` 明确要求保持原型布局、风格和操作流程；`drafts/verification-and-release-assessment.md:355-357` 明确关键图形换样、删交互不能算兼容；`legacy-option-disposition.md:19` 明确旧 UI 退役不能删除当前样板能力。旧 Frappe 实现/测试退役不代表用户接受删减原型功能。

旧正式计划缺少冻结关系或既有来源身份已失效时，继续明确显示不可用原因，不按当前 BOM 猜测历史关系。

## 用户补充的还原边界

原型作为视觉和交互参照，保留当前已经完成的有效增强，不机械照搬原型样例：

- 保留重叠安排分轨与真实资源冲突区分、连续真实时间及跨夜/跨日、零工时标记、密集任务 Canvas/虚拟行、缩放和滚动定位。
- 保留真实候选/正式计划身份、冻结工艺关系、范围外工序提示；全局关键链和同零件完整工艺路线分别表达。
- 需要按原型恢复的是日期/小时的清晰层级、任务条的工序主文案、克制配色、完整路线浏览和候选/正式操作一致性。保持现有时间坐标，不通过压掉夜班来复制原型轴。
- 原型写死的两天 08:00–18:00、示例产能与工时数值不能进入真实界面；负荷信息只能使用真实投影。

本轮已完成两项关联功能及对应绘线样式修正；整图信息结构恢复属于本次核对发现的后续范围，尚未实施。
