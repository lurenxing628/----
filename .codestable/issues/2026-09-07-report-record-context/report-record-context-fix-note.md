## 问题与原因
更正表单固定插在工序汇总行下、历史报工行上，打开时还重绘记录并滚动表单，原记录被推走造成“消失”的观感。补充信息以一串 flex 文本显示，缺少字段和值的分区。表单补充区的三列网格、`wide` 与原因跨列规则冲突，原因落成窄列；文本域固定自身高度，也没有共同行高。移除最大件数后，固定宽度数量输入框未吸收空出的空间。

## 修复
- `前端设计/ui_kits/workbench/field-report-editor.js:35`：同一展开工序内不再重建原记录；已有报工的更正/补齐表单放到对应记录及已展开的信息后方，并以原记录作为滚动参照。保留原行高亮、再次点击收起、草稿、取消焦点与保存校验；新增及整道确认仍位于工序汇总下方。
- `field-report-views.js:35`、`field-reporting.css:234`：记录信息使用四组字段/值，作业备注独立分区，长文本换行，窄屏分行显示，复用现有主题与分隔线。
- `field-report-form.js:18`、`field-reporting.css:294`：设备、人员位于第一行；备注、原因位于第二行。原因改多行输入，同行文本区通过网格拉伸和 flex 共享行高，保留纵向调整；无需原因时备注占满整行。选择框维持 36px 高度。
- `field-report-form.js:10`、`field-report-editor.js:75`、`field-reporting.css:249`：只显示“最小 / 最大”，统一 44px 按钮，最大件数保留在悬停提示与输入上限。数量输入框伸缩填满剩余空间，最大按钮对齐区域右侧；不改变数量算法。`index.html` 更新相关资源版本。
