# 工艺编辑流程整改

关联总方案：`workbench-manual-remediation / wbfix-process-flow`，覆盖批注 3、5、7、8、9、10、11、12；工艺列表删除同步使用全站 `trash-2` 和可见“删除”。

## 修改结果

- 归属页不再要求逐行核对、全选当前页或全部核对。点击“保存归属并继续”自动预检全部有效工序，无外协组变化即直接提交；只有实际解除组关系时展示原组影响，确认解除后仍由同一保存按钮提交。
- 归属保存保留完整有效工序集合、真实工种、供应商能力、组关系、快照和事务校验。前端只在明确保存动作构造 `confirmed: true`，打开、搜索和翻页不会写确认记录。
- 工时页拆为自制工时、外协周期两张编辑表，使用列分隔和统一输入高度。整组周期只在外协组处填写，按组周期的成员只读并指明编辑位置。搜索/翻页仅控制显示，保存始终包含全部有效工序及合并组。
- 取消常驻零值复核框。单件工时为 0 且当前内容尚未确认时，保存弹窗列出工序及“数量增加不会增加加工时长”的影响；“按 0 保存”直接提交。已确认且未变化的零值直接保存；改变换型工时等当前确认内容后需重新明确按 0 保存。
- 新增 `process_zero_hours.py`，在事务内根据内容绑定的确认记录判断是否需要零值确认；字段归一化只检查明确布尔类型与数值格式。服务端拒绝码为 `zero_unit_hours_confirmation_required`，工艺写入接口返回具体 `operations.<ref>.unit_hours` 字段路径。
- 工时文件预检和写入复用同一零值规则。已确认内容的原样 CSV/XLSX 往返不重复要求确认；新值或尚未确认的零值通过“按 0 导入”表达最终保存意图，不再叠加零值框和总核对框。文件导入仍不冒充完成整个工时阶段。
- 删除旧模板的常驻黄色来源说明，保留实际缺项提示。路线页只显示路线导入导出，原始文本/解析标记/备注/确认记录折叠。批次影响改为“此工艺已用于 N 个批次。修改后，已有批次工序不会自动更新。”

## 数据边界

没有修改真实数据库，没有自动补工时或历史确认记录。空值与 0 区分、正外协周期、有效合并组、工时校准采纳锁、历史批次与计划/报工记录、过期快照和同请求回执校验均保留。共享控件、批次模板完整性以及真实浏览器总验收由并行条目承担。
