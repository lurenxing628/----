# IG 局部预算、插入预筛和尾段复用

已实现并加载到本机生产进程，保存的配置仍为 `improve / 20 秒`。同条件 5000 工序容量测试完成 5 轮有界小邻域，原版本为 0 轮；相同调整动作的续排平均用时减少 71.34%。没有引入 OR-Tools、NumPy、新语言或新运行时，未运行全门禁，未提交。

## 修改和约束

- 大实例从 128 道工序起使用独立邻域预算。先以一道工序完成最小邻域，再按实测成本和剩余时间控制规模；局部超时允许继续换邻域，全局截止仍终止阶段。试算和完整验证已放不下时明确停止，避免重复启动过短切片。
- 插入位置按工时、依赖、资源串行近似和当前业务目标预筛，只将少量新顺序送给正式 SGS。已有正式评分的原位置仍参加比较。近似不产生可发布结果，也不宣称保留原全邻域的最佳位置。
- 正常重解变化中段后，若未来所需的依赖结束时间、资源占用、忙时、换型状态、图进度及剩余优先键与参考检查点一致，则回放已解尾段。引用可变工序时间的 `seed_results` 禁令不变；采用或切换到新参考前仍独立完整解码并比较摘要和完整分数。
- 尾段复用只支持经过证明的原生固定资源、正工时路径；外协、自动选资源、输入签名变化和被替换的调度回调不走这条捷径。中断试算不发布半份结果；最后一道工序完成后，不再被局部预算检查丢掉完整结果。
- 唯一图优先键的大实例维护 ready 堆，省去逐步扫描整个 ready 集合。堆首仍经正式评分，罚分不为零时恢复完整候选评分；并列、小实例和未知输入继续使用原路径。
- 大实例难度按有界任务是否完成调整，质量统计单独记录。临近截止、没有更好的候选且来不及验证并继续搜索新起点时保留旧参考；时间充裕时保留既有退火走法。

改动为 12 个产品文件、3 个新增测试文件和测试注册表，共 16 个 Python 文件。逐文件前后哈希和完整补丁见证据包 `implementation-files.json`、`implementation.patch`。决定与证明条件见 [局部任务决定](../../compound/2026-09-15-decision-ig-local-tasks-and-tail-reuse.md)。

## 同条件容量复测

两臂都是本轮冻结源码、100 批 × 50 工序、基础方案加 3 个图权重、`improve / 20 秒`，外部上限仍为 180 秒，串行测量。这里的 4 方案不是本机默认图权重数 5 对应的 UI 六方案配置。

| --- | ---: | ---: |
| 完整方案 | 4 / 4 | 4 / 4 |
| 受理至完整终态 | 22.3105 秒 | 21.2617 秒 |
| 完成的 IG 小邻域 | 0 | 5 |
| 完成的正式续排试算 | 2 | 5 |
| 完整参考解码 | 1 | 1 |
| 复用前缀工序放置 | 2222 | 10000 |
| 复用尾段工序放置 | 0 | 11667 |
| 中途放弃的解码 | 0 | 0 |
| 严格目标改进 | 0 | 0 |

最终 5 轮采用新的有界邻域：本次每轮实际拆 1 道工序，共预筛 25 个新位置，正式试算 5 次；五次均保留原位置。不能将其解释为 5 轮旧版“3 道工序 × 最多 6 个位置”的全扫。第 6 轮因试算加完整验证预算不足而未启动，报告保留 `interrupted_iterations=1`；这不是一次已进入 SGS 的中断解码。

四个方案的完整 validated payload 与修复前逐项相同，持久化 20000 条任务；隔离服务退出、重启、结果保留和源码加载检查均通过。因此本容量例证明搜索和速度收益，不证明业务分数提高。总耗时还包含准备和持久化等工作，不能把 20 秒搜索预算当作接口硬实时承诺。

## 固定工作量与质量

固定工作量用相同 5000 工序、相同参考顺序和两个相同的相邻独立工序交换位置，对比原生续排与新加速续排。覆盖同机同人工时一致、四组资源工时不同两个输入，共 4 对动作，前后顺序交替。所有加速结果都与单独完整解码逐项相同，跨版本摘要相同，运行前后源码及实际导入根校验通过。

| 指标 | 修复前 | 最终版本 |
| --- | ---: | ---: |
| 4 个相同动作平均续排耗时 | 1.34314 秒 | 0.38495 秒 |
| 单次耗时范围 | 1.07023～1.63541 秒 | 0.36832～0.41022 秒 |

平均耗时减少 **71.34%**，约 **3.49 倍**速度。独立完整验证在固定动作计时区间之外；不能将这个倍数套到整个排产请求或 IG 迭代吞吐。

| 质量对照 | 更好 | 相同 | 变差 |

| SMTWT 250 例，3 秒 | 0 | 250 | 0 |
| SMTWT 250 例，5 秒 | 1 | 249 | 0 |
| 原端到端 20 例 | 0 | 20 | 0 |
| 补充 192 工序、两种资源场景 × 四目标 | 0 | 8 | 0 |

补充大例包含不同工时、交期、齐套日期、班次日历、停机和共享/可选资源；优化预算 5 秒，外层比较预算 12 秒。它们通过完整结果审计，但没有观察到分数改善。本轮收益主要在解码速度和短预算内能完成的搜索，不宣称已有大幅业务质量提升。SMTWT 继续使用项目的 `min_overdue` 完整目标向量，不是任意加权单机问题的最优性认证。

完整小例矩阵绑定 `delivery/source`；最终绑定 `delivery-final/source`。矩阵冻结后只修改了大实例的验证预留准入、相应报告字段，以及非空解码预算回调在末道工序之后的行为。小例原求解器字节相同，按 `N < 128`、预算回调为 `None` 化简后的模块 AST 相同，见 `small-route-continuity.json`。不声称两棵整源码字节相同。最终大例、固定动作和容量测试使用最终源码。
