# 分阶段生产输入复核修复

用户已明确要求全部修复并禁止子代理。本轮全部由主代理实施；未调用子代理，未运行日常或全量门禁，未提交、推送、发布或操作生产数据库。

## 修复范围

| 已确认问题 | 根因与最终处理 | 对应验证 |
|---|---|---|
| 分阶段前序可排但候选不能采用 | 采用要求覆盖全部原工序。现在共用 `require_candidate_scope` 和明确的物料暂缓集合，只允许 stage 策略下已核实的缺料后序待排；仍要求完整覆盖可排工序、已有正式安排和前序依赖。 | 真实 admission→worker→采用；后序无到料或到料超出窗口；缺资源、算法漏排、遗漏原正式安排仍拒绝。 |
| 有齐套日期的批次拆分报 500 | SQLite DATE 对象与 ISO 文本直接比较。现在先统一日期形式，原齐套日期与分配日取较晚值，保留事务和回执。 | 使用 `PARSE_DECLTYPES | PARSE_COLNAMES` 的 HTTP 预览与确认，较早、较晚原齐套日两种情况。 |
| 分件校验不认分次到料和第二工种 | 分件读取的事实表清单和齐套校验过旧。现在与整批共用采用事实清单，并核对本次物料策略及安排起点；完整工艺和分件数量校验不变。 | 8 道共同/分件工序、第二工种、2030 年到料与相应排产日期，真实计算及采用均通过；前序放行、后序待料也覆盖共同/分件链。 |
| 设备第二工种报工被拒 | 报工只比较设备主工种。现在按主工种和附加工种集合校验，保留人员技能与设备操作授权校验。 | 真实报工命令允许有效第二工种；没有该能力时仍拒绝。 |
| 小数用料拆出的子批被误判缺料 | 分配量、需求量分别经 REAL/JSON 存储后，末位出现差值。数量比较集中处理最多两个 binary64 epsilon 相对误差，整数量比较精确，不改写或增加到料。 | 3 组同比小数拆分、需求/已有到料/分次到料守恒；明显小数短缺、极小正需求无到料、大整数少一单位仍拒绝。 |
| 工作→休息→工作保存成零工时 | 切休息清空 periods 后未恢复。编辑中保留并恢复原时段，新工作日使用页面默认时段；前后端均拒绝无时段工作日。 | Chrome109 实际点击、保存和重新读取；原自定义两段时间保留；空工作时段不能保存。 |
| 拆分子批允许删除但触发外键 500 | 删除判断遗漏拆分历史。原批和子批均显示不能删除的原因；命令和文件替换预览复用删除约束，历史外键保留。 | 两种批次清除物料需求后，页面能力关闭、命令明确拒绝且不写库、文件替换预览说明原因。 |
| 旧个人日历仅改备注由 4 小时变 8 小时 | 原修改基底丢失 shift_hours。现在非时间修改保留旧时长；明确清空结束时刻沿用原默认推算口径，切休息仍为零工时。 | 页面保存、文件稀疏更新，09:00 起的旧 4 小时记录保持 4 小时；原清空结束、夜班、休息日用例回归。此项是既存缺陷。 |

分阶段计划同时验证两条完整路径：候选直接采用后进入试调再次采用；候选先建试调方案再首次采用。候选来源仍展示缺料工序和不完整的整批范围；采用只承认本次可排范围，试调不把前序结束时间当作整批交付依据。遗漏原正式任务、无效工艺或任意缺项不能借物料暂缓规则通过。

浏览器回归中还发现同一资料目录的删除按钮使用图标按钮样式却带文字，文字溢出；已复用现有纯图标按钮，保留 `aria-label`、说明和删除确认。未增加或修改 CSS。
