# 基线生命周期与集成检查

## 范围

本轮授权为后端正确性和优化收尾；不包含启动锁、离线包、新前端、算法策略扩展。
正式基线必须来自通过测试的干净工作区，不能把已有脏基线的标记改成 false。

## 已实施

- `write_baseline` 在文件写入前核对工作区状态、commit、结果状态、case 集合及度量值，失败不覆盖旧文件。
- 轻基准采集运行前后 commit 和 dirty 状态；中途提交不能把开始时的脏输入变成 clean 证据。
- CLI 更新和检查模式互斥，失败返回非零并说明原因。
- 比较器拒绝未知工作区状态、失败快照、重复 case 和 seed/目标/预算错配。
- 轻基准不再把“正式基线永远是脏的”设成测试通过条件。
- 前置去重允许减少完整解码次数，但保留全部配置覆盖、去重记账、多样性及方案质量约束。
- A3 集成测试保护算法依赖边界，不再冻结全仓模块数量或要求其他已修依赖环重新出现；增加重新引入环的负向测试。

## 验证

主线程以 Python 3.8 实跑：基线生命周期、轻门禁、A3 依赖合同合计 43 项通过。
复杂度拆分后，基线生命周期与轻门禁再次 29 项通过；Ruff 通过。
新测试验证脏/未知/失败快照不覆盖已有文件、质量恶化、重复 case、seed/预算变化必失败。

## 未完成的证据条件

当前工作区仍包含既有未提交改动，因此本轮未重写正式 tracked 基线。
后续应在最终提交的干净工作区用正常 CLI 重建，并再次检查；本轮诊断结果不构成 clean-worktree proof。
完整质量门禁及新质量矩阵的最终结果由本轮主集成记录报告，不能用本文件局部测试替代。
