# SGS 首解与 IG 启动阻塞修复

四项已确认原因已修复，并在本机生产模式重启生效。工作区接手时已有大量未提交内容；按用户要求不跑完整质量门禁，本轮未提交，不构成 clean-worktree proof。

## 根因与实现

| 原因 | 修复 |
| --- | --- |
| 每次槽位查询重复复制整条时间线 | 长时间线用原生公共变更协议和版本证书复用；短实例在解码入口选择原内容比较路径，避免额外资格检查成本。未知输入与同长度修改继续精确比对。 |
| 同机同人候选反复估算、旧缓存始终零命中 | 恒定工作窗口内共享最早可用槽位，独立重算换型代价；按最高图优先级组作严格支配剪枝，同组完整比较、最高组全不可行时恢复其余评分；固定资源零命中时停止重复维护无效缓存。 |
| 截止检查把已有等价结果也跳过 | 先查已完成且预先认证的等价候选，截止后仍可发布复用结果，不再开始准备或新解码。 |
| 首解与前置阶段花光 IG 时间 | 记录首解实际成本，跳过预计放不下的可选完整解码；只有昂贵首解挤压剩余时间时才让 IG 提前启动。大实例的后缀准入按剩余工序及实测续排成本判断，不把廉价的邻域/重复检查当成整图解码。 |

为通过短预算的逐例质量要求，既有交期起点还增加了有界顺序插入：前段 EDD、后段 SPT 的二段排列不能表达所有有益穿插。单换与顺序插入共享 2048 次不同顺序探测的上限，构造最多使用 IG 剩余时间的 5%；只有一个完整建议顺序进入正式 SGS 验算，估算不能直接成为发布结果。详见 [技术决定](../../compound/2026-09-15-decision-sgs-startup-budget.md)。

修改覆盖 19 个产品 Python 文件，集中在 `owned_timeline`、`slot_overlap_reuse`、`sgs_shared_slot`、SGS 评分/剪枝、候选复用和优化预算/IG 起点模块；另有 11 个测试文件和测试注册表。逐文件 SHA 与完整补丁见证据包 `implementation-files.json`、`implementation.patch`。

## 实测结果

同一 100 批 × 50 工序、4 方案、`improve / 20 秒`、外部 180 秒上限：

| 指标 | 修复前 | 交付版本 |
| --- | ---: | ---: |
| 原生首轮 SGS 解码 | 27.3811 秒 | 7.1204 秒 |
| 评分次数 | 495050 | 252500 |
| 成功复用同资源槽位 | 0 | 244728 |
| 完成方案 | 2 / 4，另外 2 个被跳过 | 4 / 4，每个 5000 工序 |
| IG 实际解码 | 0 | 3：1 次完整起点、2 次后缀试算 |

首轮同条件 SGS 用时减少 **74.00%**，约 **3.85 倍**吞吐。最终受理到完整终态为 **22.2549 秒**，通过 180 秒容量项，合计 20000 条任务完成持久化；重启保留与源码加载路径检查通过。图方案的结果、正式验证 payload 和完整分数与修复前逐项相同；基础方案完整分数相同，但其排程发生变化，不能声称所有 payload 都一样。

IG 保存了 2222 次前缀工序放置。20 秒内仍未完成整轮破坏重插：`iterations=0`、`interrupted_iterations=1`、严格改进数 0；不能把两次试算说成两轮 IG，也不能声称这个容量例的排产目标得到改善。首个续排耗时按剩余工序比例估算，后续保留已测续排成本下限；这不是硬实时上界，已启动的单次解码可能超时，报告保留真实超时量。

| 质量对照 | 更好 | 相同 | 变差 |
| --- | ---: | ---: | ---: |
| SMTWT 250 例，3 秒 | 163 | 87 | 0 |
| SMTWT 250 例，5 秒 | 163 | 87 | 0 |
| 端到端 20 例 | 0 | 20 | 0 |

两档 SMTWT 的延期批次数均与修复前相同，改善来自完整目标分数中的后续指标；样例总延期时间合计分别减少约 **2.0273% / 2.0274%**。这不是生产业务实际延期时长的统计，也不是一般最优性证明。计时包含原生构造、试解和必要验证，两个源码进程逐例交替先后，输入、目标、阈值和运行前后源码哈希均核对。

完整小例矩阵绑定 `candidate-v6`。最后只添加了从 128 道工序起使用的大实例预算子类：40/50 工序的 SMTWT、最多 48 工序的端到端样例仍使用字节相同的原求解器。入口按小实例分支化简后 AST 与计时版本一致，时钟调用不变；只存在这两个产品文件差异。相关证明见 `small-route-equivalence.json`。最终容量测试与交付代码的产品及基准辅助文件共 1000 个逐字节相同，见 `delivery-binding.json`。不冒称交付整棵源码与小例计时版本逐字节相同。

## 未采用的实验与证据

无条件 IG 先启动的版本被否定；短时间线每次校验完整版本协议也被确认有负收益。v3、v4、v5 的完整矩阵分别有 3、2、1 例退化，均未采用；v1、v2 的中止回执也保留，缺失样例未被当作平局。旧版容量复测的第一次启动因新测试引用旧源码不存在的模块而被源码守卫拒绝，没有算入性能数据；修正隔离夹具后重新取得上述 27.3811 秒记录。

证据归档：`evidence/Benchmarks/2026-09-15-sgs-startup-budget/`，包含原始矩阵、各版本源码、实际容量运行、测试失败、源码/AST 证明、生产保留证明与逐文件归档校验。该目录按仓库规则被 Git 忽略。未应用的额外种子交换提案仍只在临时研究目录，没有进入交付代码。
