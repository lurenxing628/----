# 工艺与外协维护一致性修复

## 授权和边界

用户在完成只读排查后明确要求“全部修复”，沿用已授权的子代理协作。修复覆盖工艺录入、工时及资源文件、外协段维护、批次承接、外协登记和相应页面。保留用户现有工艺文件的组织方式，不强制改成每道工序一行。

本轮不提交、不推送、不发布，不操作正式业务数据库或执行正式排产。迁移和行为验证仅在内存及隔离测试数据库执行。历史原值无法重建时不伪造历史；升级时捕获的外协上下文明确记录来源。

## 已确认根因

- 批次外协组仍按当前零件模板回查，模板变更会改变旧批次的周期解释及后续排产输入。
- 批次关键变更保护没有读取外协登记，普通改供应商、同步和删除可切断在途登记。
- 合并发出只校验批次、供应商和分件，未检查实际工艺连续段。
- 路线预检按新名称解释，但已有同序号只改名称，后续确认可沿用另一工种的旧绑定。
- 结构化工序转字符串未保留序号/名称边界，导出编辑回导可能把第10序“3D打印”改成第103序“D打印”。
- 外协组当前有效周期与成员旧周期展示混用；组维护、默认策略、选择器与文件维护规则不一致。

## 集成复核补充修复

- 合并段批次工序不能逐道改派供应商；预检及严格、非严格输入均独立核对现存成员。独立内存复现证明修前两家供应商错误共用一次周期，修后拒绝；逐序模式仍可独立改派。
- 段保存成功后详情读取失败时，子弹窗曾挡住父级查询恢复。修后只对已验证回执关闭覆盖层，工时草稿不丢、不重复写组。
- 新快照原先每道保存完整成员列表，导致重复存储，新增成员校验也重复遍历。主代理实测100道同组仅校验耗1.4635秒；改为各道持有自己的冻结成员关系，组规则及实际成员按组一次检查，不增加新表。最终真实输入预算：200道0.0142秒，1000道0.0663秒；1000道整库增长1.638MB，保留线性资源预算回归。
- 旧候选方案升级后继续使用同一份历史归档解释外协规则；只有归档版本和DDL均能证明早于v33才走显式旧版解释，不从当前资料补历史空缺。
- 日常门禁识别出22处新增函数分支复杂度超限，按解析、校验、索引、事务动作拆分职责；所有新函数回到阈值15以内，不扩大治理豁免。拆分后的架构检查20项通过，主链Pyright零错误、零警告；编号解析55994个输入差分对照结果及错误合同完全一致；路线解析6020次结果与错误文本对比、6组真实内存库预检对比均零差异。
