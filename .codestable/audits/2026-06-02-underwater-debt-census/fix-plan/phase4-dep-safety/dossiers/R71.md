## 7) 收口行为差异及所需 parity 测试

**当前两路逐字等价(§1 已逐行比对),理论上无行为差异。** 但 parity 测试的存在意义是「钉住此等价、阻止未来 drift」,且必须覆盖三 helper 的**边界分支**(否则等价是「碰巧」而非「被守卫」):

- `_float_matches_choice(value, choices)`:真值表需覆盖
  - `choices=()` → **return True**(空 choices 视为不约束;反例若一侧误改成 False 即分叉)。
  - 浮点容差边界:`abs(diff) == 1e-9`(含)vs `> 1e-9`(不含)——`<=1e-9` 是边界,parity 须 pin 此 inclusive。
  - `choices` 含非数字串(如 `"abc"`)→ `float()` 抛 → `except Exception: continue`(**静默跳过,不 raise**)→ 若该串是唯一项则 return False。**这是已存在的吞错行为(灵魂线敏感),parity 必须保真而非"修好它"**。
- `_normalize_valid_texts(values)`:样本需覆盖
  - 含空白:`" A "` → `"a"`(strip+lower)。
  - 大小写:`"YES"` 与 `"yes"` 视为重复 → 仅留一份。
  - 空串/None:`values=None` → `or ()` → 返 `()`;`""`/纯空白 → 跳过。
  - 顺序保持:首现序保留(out.append),parity 须 pin **tuple 顺序**(set 去重 + list 保序的组合,反例:若一侧改用 `sorted(set(...))` 顺序就分叉)。
- `_coerce_degradation_event(raw)`:dict 边界需覆盖
  - 已是 `DegradationEvent` 实例 → 原样直返(短路)。
  - 非 dict(如 None/list/str)→ **return None**(反例:None vs raise——若一侧误改成抛错,排产侧降级事件读取会从"静默丢弃"变"崩",静默→loud 的方向反转)。
  - `code`/`scope`/`message` 任一 strip 后为空 → **return None**(三者皆必填)。
  - `count`:`raw.get("count")` 为坏值(如 `"x"`/负数)→ `int()` 抛 → `except: count=1`;合法负数 `-5` → `max(1, -5)=1`(**下限钳到 1**)。parity 须 pin `max(1, int(... or 1))` 全分支。
  - `field` 空/None → `field_text or None` → 落 None;`sample` None → None 否则 `str()`。

**parity 落点(收口点)**:扩 `tests/config/test_scheduler_config_spec_sync_contract.py`,新增三个 test 函数,直接 `import` 两栈同名 helper,对上述真值表/样本断言 `model_fn(x) == service_fn(x)`。此为 R71 收敛的**硬前置守卫**,且在物理收敛前先单独续命(Batch-1 / 前置门)。
