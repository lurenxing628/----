## 7) 收口行为差异 + 所需 parity 测试

本债主体是直删，**唯一需要 parity 论证的点 = benchmark_fjsp.py:505 的 repoint**（§8 真消费者）。

**死方法 vs 活孪生 · 逐分支等价性（针对 version-only / adopted 路径）：**

本轮逐行比对：
- 死 `get_version_time_span(version)`（schedule_repo.py:36–59）：SQL = `SELECT MIN(start_time), MAX(end_time) FROM Schedule WHERE version=? AND TRIM(CAST(start_time AS TEXT))<>'' AND TRIM(CAST(end_time AS TEXT))<>''`；`if not row: return None`；`if not start_time or not end_time: return None`；`return {"version":int(version),"start_time":str(...),"end_time":str(...)}`。
- 活 `schedule_plan_query_repo.get_plan_time_span(version=, source_table=SOURCE_SCHEDULE, candidate_id=None)`（:257–310，本轮 sed 复核）：`source_table==SOURCE_SCHEDULE` 分支 SQL **逐字符相同**（MIN/MAX + 同样的 TRIM 守卫），同样的 `if not row → None`、`if not start_time or not end_time → None`、同样的 return dict 形状。

**结论：version-only / SOURCE_SCHEDULE 路径下两者逐分支等价（byte-equivalent SQL + 同 None 收敛 + 同 dict 形状）。** 活孪生是严格超集（多 candidate / scenario 两分支 + 未知 source raise ValueError）。

**边界值反例核查（确认无差异）：**
- 空版本（无记录）：两路 MIN/MAX 返回 NULL → `start_time`/`end_time` falsy → 两路均 `return None`。等价。
- 版本存在但全行 start/end 为空串：两路 TRIM 守卫均过滤 → 同上 None。等价。
- **唯一差异点**：调用契约。死方法位置参数 `get_version_time_span(version)`；活孪生**强制 keyword-only**（`*, version, source_table, candidate_id`）。benchmark:505 当前传裸 `version` 位置参，repoint 时必须改成 `get_plan_time_span(version=v, source_table=SOURCE_SCHEDULE, candidate_id=None)` 并 import `SOURCE_SCHEDULE`，否则 TypeError。这是**调用形态差异，非返回值语义差异**。
- **若误传 candidate_id 给活孪生**：死方法根本无此参数；活孪生 candidate 分支才用 candidate_id，SOURCE_SCHEDULE 分支忽略它 → 仍等价。无 None-vs-raise 反例（adopted 路径不触发任何 raise）。

**所需 parity 测试（repoint 自证）**：在 benchmark 改完后，对同一 (conn, version)，断言 `schedule_repo.get_version_time_span(version)`（删之前）与 `schedule_plan_query_repo.get_plan_time_span(version=version, source_table=SOURCE_SCHEDULE, candidate_id=None)` 返回 dict 完全相等（含 None 情形）。此 parity 测试只在删前做一次性回归比对（删后死方法不存在），可写成临时校验脚本或在 detail_queries 迁移用例里加一条等价断言。
