- **方向（待裁）**：把 :335-337 的 `except` 分支由「warning 后落到 :343 os.replace」改为与 :338-342 else 分支**同语义**——
  ```python

      # 我是故意的：校验执行失败比"校验不通过"更严重——连完整性都跑不起来的库不算可信备份，绝不升正式

      raise RuntimeError(f"备份后的数据库完整性检查执行失败（视为不可信备份，不落地）：{e}") from e
  ```

## 7) 收口行为差异 + 所需 parity 测试

非收口（改 raise），故无「新旧两路逐分支等价」问题。但改 raise **改变了 `backup()` 的可观测契约**，须用契约/回归测试钉死新行为（防回退、防下游误吞）：

- **行为差异**：
  - 旧：`integrity_check` 执行抛异常 → `backup()` **返回 backup_path（成功）**，下游拿到一个未经校验的 .db。
  - 新：`integrity_check` 执行抛异常 → `backup()` **raise RuntimeError**，无返回值，.tmp 被 finally 清除，不生成正式备份。
- **边界反例（须各写一条 parity/契约用例）**：
  1. `dest.execute("PRAGMA integrity_check")` 抛 `sqlite3.OperationalError`（如 `database disk image malformed`）→ 断言 `backup()` **raise**（旧码会返回路径）。
  2. `fetchall()` 抛异常 → 同上 raise。
  3. 校验跑通且 rows[0][0]=="ok" → 仍正常 `os.replace` 并返回路径（**回归不动**，防误伤 happy path）。
  4. 校验跑通但 ≠ok（else 分支，:338-342）→ 仍 raise（**已有行为，回归确认未被改弱**）。
  5. raise 后断言 `backup_path` 与 `tmp_path` 均**不存在**（finally 清理生效，不残半成品）。
- **新增测试落点**：tests/ 当前**零** `integrity_check` 用例（已核），须新建一个 `regression_backup_integrity_*` 文件 mock `sqlite3.Connection.execute` 让 integrity_check 抛错。
