## 7) 收口行为差异 + 所需 parity 测试

**逐分支比对两版(support `:32-51` vs provider `:113-137`)**:

| 分支 | support 版 | provider 版 | 是否等价 |
|---|---|---|---|
| `raw` 非 dict | `raw = {}` (`:33-34`) | `raw = {}` (`:114-115`) | ✅ |
| `available` 解析 | `available if isinstance(bool) else True` (`:35-36`) | `if isinstance(bool): is_available=available else True` (`:116-120`) | ✅(写法不同,结果同) |
| `reason` 取值 | `_text(raw.get("reason"))` = `str(x or "").strip()` (`:37`) | `str(raw.get("reason") or "").strip()` (`:121`) | ✅(`_text` 即 inline 写法,见 support `:10-11`) |
| `reason_code` 取值 | `_text(raw.get("reason_code") or raw.get("reason"))` (`:38`) | `str(raw.get("reason_code") or raw.get("reason") or "").strip()` (`:122`) | ✅(`_text` 的 `or ""` 内化,等价) |
| available 时清空 | `reason="";reason_code=""` (`:39-41`) | 同 (`:123-125`) | ✅ |
| `available` 出参类型 | `bool(is_available)` (`:48`) | `is_available`(已是 bool) (`:134`) | ✅(`is_available` 必为 bool) |
| 其余 7 键 | 同(`ids`/`edges`/`makespan_end`/`edge_type_stats` 四键默认/`edge_count`/`reason`/`reason_code` 回填) | 同 | ✅ |

**结论:两版逐分支语义等价**(P5 真复制,非"看似同实则异")。但收口仍**必须配 parity 测试**,因为:

1. **边界反例(必须钉死的等价点)**:
   - `raw={"available":"yes"}`(非 bool 真值)→ 两版均走 `else True`(**不是** Python 真值判断)→ `available=True`。若收口时手滑写成 `bool(available)` 会把 `"yes"`→`True` 但 `available=0` 误判,**与现行 `isinstance(bool) else True` 不等价**(现行:`0` 非 bool → `True`;`bool(0)` → `False`)。**反例:`available=0` 现行得 `True`,`bool()` 写法得 `False`。**
   - `raw={"reason_code":"NoSuchCode","available":False}` → 归一保留 `"NoSuchCode"`;真正的白名单收敛在 **下游 `gantt_contract.py:32-34`**(`if reason_code not in _ALLOWED…: "unknown"`)。归一层**不得**提前 clamp,否则改变两阶段职责(parity 须验归一层输出 `reason_code` 原样透传给 contract)。
   - `raw={"available":False}` 无 reason/reason_code → `reason_code = ("unknown" if not is_available else "")` = `"unknown"`(`:50`/`:136`)。**反例:available 缺省+无 code → "unknown",不是 ""。**
   - `raw={}` → `available=True`、`reason=""`、`reason_code=""`、`edge_type_stats={process:0,machine:0,operator:0,unknown:0}`、`edge_count=0`。
2. **必备 parity 契约测试(收口前不存在,须新建)**:对一组 raw 输入(含上述边界:`{}`、非 dict、`available=0`、`available="yes"`、`available=False`+无 code、含 `reason` 无 `reason_code`、`reason_code` 非白名单值、`edge_type_stats` 部分键缺失),断言**新单份 helper 输出 == 旧两版输出逐键深等**。建议新增 `tests/regression_gantt_critical_chain_normalize_parity.py`(单一归一来源 parity,registry 指出当前缺失)。
