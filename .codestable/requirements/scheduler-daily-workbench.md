# 每天先看计划工作台处理风险

## 用户故事

- 作为每天早上打开系统的计划员，我希望首页先告诉我今天有什么要处理，而不是自己在分析页、甘特图和报表之间来回找。
- 作为需要追排产风险的人，我希望系统把超期、方案确认、资源压力、现场情况和基础数据缺口放在一起，而不是让我凭经验猜哪里不对。
- 作为需要继续往下查的人，我希望每条提醒旁边都有下一步入口，而不是只看到一句告警却不知道点哪里。
- 作为已经打开报表的人，我希望报表中心和报表明细也能带着当前版本、方案、日期、批次和资源继续回到甘特图、资源派工或计划和现场实际，而不是看完报表后重新找入口。
- 作为不想被误导的用户，我希望系统说清楚这些提醒是实时算出来的，不要让我以为它已经记住了我处理到哪一步。

## 为什么需要

原来的首页更像一个入口集合，有统计卡，也有常用页面链接，但它没有回答“今天先处理什么”。计划员要先看最新计划、再自己判断有没有超期、有没有方案待确认、有没有现场情况缺口，操作路径长，也容易漏掉风险。

## 怎么解决

系统把首页变成计划工作台。用户进入后，先看到当前最新计划和今日待处理，再从每条提醒跳到排产分析、甘特图、资源派工或计划和现场实际。提醒用中文说明影响、证据和当前状态；没有风险时也用中文告诉用户当前没有必须马上处理的排产风险。

报表中心和报表明细也纳入工作台闭环。用户在超期清单、资源负荷、计划和现场实际、停机影响里看到问题后，可以用同一套版本、方案、计划身份、返回地址、日期、批次和资源上下文回到甘特图、资源派工或正式方案复盘继续处理。报表会说明自己能回答什么，也会说明哪些事情当前不能证明，避免把“没有数据”误读成“现场一定没有问题”。

## 边界

- 它不替用户自动处理风险，只负责把风险和下一步入口摆到首页。
- 它不保存“已处理 / 已忽略 / 指派给谁”的状态，当前提醒根据数据库实时生成。
- 它不直接填写现场实际，现场记录仍从资源派工和计划实际相关页面处理。
- 它不决定候选方案是否采用，只把需要确认的方案入口放到用户面前。
- 它不取代排产分析、甘特图、资源派工和报表明细；复杂信息仍要进入对应页面继续看。
- 报表回跳只负责把用户带回可继续查看或处理的页面，不把报表变成现场记录写入入口。
- 报表当前只支持设备和人员资源筛选；班组维度、未知维度、只有资源编号没类型、只有资源类型没编号、资源主参数与别名冲突的半截资源筛选不假装支持，入口会直接提示用户切回设备或人员。
- 停机影响第一版只说明设备级停机影响和设备级回跳，不推断任务级受影响明细。
