# 工作台真实业务流程

## 用户需要

计划员需要在同一个工作台维护资源、工艺与批次，先核对排产条件，再比较真实候选并明确采用；现场事实和试调不能悄悄改变正式安排。管理人员需要从同一份事实查看交付风险、实际进度、报表和校准建议，并能查询维护和恢复结果。

计划员每天使用工作台时，需要按资料准备、计划、现场和分析找到入口，在相关页签之间继续查看同一对象；密集表格中仍能找到关键编号和操作。填写资料后准备关闭或离开时，需要先确认是否放弃未保存内容，选择留下就继续原来的输入。

## 当前实现合同

- 主数据、工艺三步确认、批次三种文件导入、复制与批量操作保留预览和整批事务边界；新页面未展示的旧字段不因此删除。
- 排产通过真实受管worker产生完整持久候选，候选查看不等于正式采用。采用、再采用、执行反馈和冻结事实冲突必须明确拒绝。
- 试调草稿可恢复；正式采用有版本和原请求回执。零时长计划点、共享及分件工序保留原身份，不伪造占用或完成。
- 分次报工、补录和更正按追加事实处理；实际甘特不从计划时间猜测实际结束或剩余安排。报表和校准使用同一已核实范围。
- 值班处理状态、外协状态与业务风险分别表达；关闭处理单不等于风险消失。备份文件存在不等于可恢复，恢复必须经过真实宿主与重启核对。
- 跨页、刷新和回返保留精确对象与范围。失败、缺证据、过时快照和未知提交结果显式呈现，不自动换对象或样例数据。
- 导航将值班台放在前面，资料准备入口集中；计划相关视图、报表与复盘通过页内页签衔接。已有链接继续定位原视图、对象和范围，菜单合并不代表查询入口或业务能力被删除。
- 用户可在同一工作台切换主题、打开本地帮助和选择舒适或紧凑表格。密度偏好在本机保存，顶栏和系统设置中的选择保持一致；只改变行间距和留白，不缩小字号或改变数据。偏好读取或保存失败会明确提示。
- 批次、工艺、试调和报工等编辑器在关闭、切页、浏览器前进或后退会丢失未保存输入时先确认；选择留下时，原页面、查看范围和输入保持一致。未保存输入不会因这项保护自动落库；保存结果待核实时仍核对原操作，不把离开页面当作保存成功或再次提交。

### 2026-09-15 手动整改后的业务合同

- 工艺保留路线、归属、工时三个步骤；“保存归属并继续”和“保存工时”确认整份有效工序，无逐行或本页重复核对。搜索、分页只改变显示范围。自制工时与外协周期分区填写；整组周期只填一次。单件工时为空时提示缺项；新填、改为或尚未确认的 0 仅在保存时说明影响并提供“按 0 保存”，已确认且内容未变的 0 不重复询问。工时文件导入沿用相同零值规则。
- 修改工艺模板不会自动更新已有批次工序。批次“从工艺模板更新工序”统一检查必要资料，预览新增、删除、修改及将清除的设备/人员指定，确认后原子更新；旧模板没有新确认记录不单独构成禁用理由，已有计划/报工和过期快照仍禁止替换。旧 `strict_mode: false` 请求明确拒绝。
- 全部可达页面的删除使用本地垃圾桶图标及可见“删除”文字；关闭、减少、解除关联和撤销报工保留各自含义。图标、按钮、筛选及编辑表格使用共用规则，长原因与主要操作分区。
- 数据库恢复后，排产查询先查当前任务及回执。只有服务器能证明属于恢复前数据的旧请求才解除等待；无记录或查询失败持续 60 秒时暂停自动查询并保留同号手动查询，真实计算继续查询，不自动再次提交。空范围和无可排工序在排产预检阶段明确说明。
- 人员详情可维护既有“可操作设备”关系，资格校验与排产资源选择共用原服务；具备工种技能不等于默认获准操作全部设备。编辑其他人员字段不清空未展示的旧关系。
- 旧外协工序只要当前批次、零件、供应商和成员关系完整，就可在正常登记预览中核对来源，一次确认同时保存登记及本次关系事实。缺失的历史出生记录保持原值，已有来源与当前实例冲突时仍拒绝绑定。
- 资源占用率统一按同一计划和窗口内的“班表内占用并集 / 逐资源实际可用时长”计算；累计负荷、重叠负荷、班表外占用单列，零可用时长显示未知。网页及已开放的 CSV/XLSX 导出共用结果；现有占用率入口统计计划安排，实际工时报表继续读取执行事实。
- 单次报工可明确撤销，保留原报工、更正和撤销原因；有效事实汇总排除已撤销记录。零产出不等于撤销，其他有效报工及旧开工事实继续影响状态；已被后道、正式采用或工时校准采用依赖的记录不能随意撤销。
- 由候选进入试调时显示实际候选来源。草稿约束与正式采用前预检分开，历史“功能未开通”说明不再冒充约束失败；正式采用仍核对完整范围、资源、现场事实与版本，不因展示修复放宽。
- 系统导出的资料清单可按已支持格式回导；声明为参考的创建时间、旧只读资料和批次状态会在预检说明，不导入为业务写入字段。未知列与错误值继续拒绝，文件不是数据库备份，也不凭参考列恢复设备权限。
- 维护班次或设备组后返回人员/设备表单，最新资料与保存依据一起刷新，已填写的修改保留，不再额外点一次“已核对”。现场从原任务定位切换另一任务报工，保存后刷新同时定位当前任务及工序，继续保留原计划和筛选范围。
- 从当前正式计划创建试调时，已有可信执行事实的工序按实际执行固定；原计划保留用于对比，用户不能移动已固定工序，其他待排工序需避让实际占用。旧场景与真实固定冲突时明确要求重建，不在正式采用时悄悄换时段。采用预检的真实阻断原因完整展示，不能用去掉齐套/前后序检查换取成功。
- 日志列表的翻页和导出使用本次已读范围，读取自身追加的新日志不会使该次导出立即失效；刷新后才纳入新日志。过期、重启或数据库恢复后要求重新读取，备份下载及写入仍检查当前真实对象。

## 验收边界

以上业务已接入当前源码，2026-09-15整改的手动验收正在补当前独立功能组，详细清单及状态见执行盘点；试调正向采用不以候选采用代替，现场文件导入不以报表导出代替，不能将独立入口缺证据当作参数穷举边界排除。已验证证据保留，不重跑所有文件格式、参数、跨页与跨恢复组合。迁移路线图的历史范围包括全站验收、5000同资源四候选容量、分批归档与旧UI退役，不能拿历史局部结果覆盖当前修改。本轮用户明确禁止全门禁：只运行受影响专项、构建及浏览器手动验证，未运行 `run_quality_gate` 任何模式或整仓测试，该约束已履行；未提交工作区不能声称 clean-worktree proof。不包括Win7打包、真机或最终发布，能力族数量不当作原子动作数。

旧入口只有在新入口验收通过后退役：等价GET保留身份和筛选，不等价入口说明原因；既有JSON、写操作和下载不得被泛化删除。代码回退与新业务数据保全是两件事，不以旧数据库覆盖迁移后新增事实。
