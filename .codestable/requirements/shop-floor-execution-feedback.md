# 记录车间实际开工完工和异常

## 用户故事

- 作为现场人员，我希望能在派工上下文里反馈开工、完工、暂停或异常，而不是让计划员事后口头补录。
- 作为计划员，我希望看到计划时间和现场实际时间的差别，而不是把计划开始结束误当成真实生产时间。
- 作为负责重排的人，我希望系统知道哪些工序已经开工或完工，避免重新排程时把已经发生的现场事实随意挪走。

## 为什么需要

计划排程描述的是“原本打算怎么做”，车间反馈描述的是“现场实际发生了什么”。这两件事如果混在同一行数据里，后续复盘、异常处理和重排都会变得不可信。

## 怎么解决

现场反馈作为独立事实记录，从资源派工上下文进入。用户可以按任务提交开工、完工、暂停、继续生产和报异常；计划员可以在复盘里看到计划和现场实际的差别。重新排程时，系统会尊重已经发生的现场事实：已经开工或暂停的工序不随便移动，已经完工的工序保留真实时间，异常中的工序先提示处理异常。

## 边界

- 不把现场实际时间直接覆盖到原来的计划排程行。
- 不允许候选方案、模拟预览或历史正式方案写入现场反馈。
- 第一版不做完整 MES，不做扫码枪依赖、IoT 实时采集、电子签名、工资计件或完整质量追溯。
- 撤销开工、撤销完工、纠错和反冲要单独设计，不在第一版里静默覆盖历史事件。
