# 记录车间实际情况

## 用户故事

- 作为计划员或调度员，我希望能在资源派工页里填写现场实际开工、实际完工、暂停时间和异常记录，而不是被迫像实时系统一样不停点按钮。
- 作为计划员或调度员，我希望能下载填写模板、整理 Excel 后批量导入实际情况，避免一条一条手填大量任务。
- 作为计划员，我希望看到计划时间和现场实际时间的差别，而不是把计划开始结束误当成真实生产时间。
- 作为计划员，我希望在甘特图点开任务时，也能看到这道工序有没有现场记录、实际开工和实际完工是什么时间，而不是必须先跳到别的页面才知道现场情况。
- 作为负责重排的人，我希望系统知道哪些工序已经开工或完工，避免重新排程时把已经发生的现场事实随意挪走。
- 作为计划员，我希望在甘特图上一眼看出哪些工序已经完工、哪些正在生产或出了异常，而不用逐个点开详情确认。
- 作为计划员，我希望在周计划页直接看到每道工序的现场状态（待开工/生产中/已暂停/异常中/已完工），不用逐个跳到甘特或派工页确认。
- 作为连续登记现场情况的计划员，我希望新建报工时能核对时间建议或复制同任务上一条有效记录，确认本次保存完成后直接填写下一条；没有把握的时间仍可留空，离开未保存输入前能选择继续编辑。

## 为什么需要

计划排程描述的是“原本打算怎么做”，现场记录描述的是“现场实际发生了什么”。这两件事如果混在同一行数据里，后续复盘、异常处理和重排都会变得不可信。

当前 APS 没有接 MES 和 DNC，普通用户主要靠人工填写或整理 Excel。资源派工页不应该让人误以为系统已经能实时采集设备状态，更合适的做法是把它做成“填写实际情况”和“导入实际情况”的工作入口。

## 怎么解决

现场记录作为独立事实记录，从资源派工上下文或工作台的现场报工入口进入。用户可以按任务填写实际开工、实际完工、暂停时间和异常记录；也可以先下载填写模板，再把整理好的 Excel 一键导入。

当前工作台的新建报工提供可见、可清除的时间建议：同任务、同工序上一条有效实际完工不晚于本机当前时间时，可作为实际开工建议；否则建议本机当前时间，实际完工也建议当前时间。用户核对后再保存，清空的时间仍保持未填写。已有记录的补齐、更正以及恢复的草稿不重新套用这些建议。“复制上一条”把同任务、同工序上一条有效记录的可填写内容带入当前草稿供核对，不复制原记录身份或提交信息，也不直接保存。

保存结果得到确认后，工作台自动重新读取当前任务。“保存并继续”仅用于新建：重新读取成功、仍是原任务和工序、尚未完工并且允许继续登记时，才打开下一张草稿。结果未核实、重读失败、任务变化或尚未取得新的可写状态时保留原因，不重复提交或直接开始下一条。字段错误就地说明并定位到需要修改的输入；关闭或离开会丢失未保存内容时先确认。

2026-09-15 新增单次报工的明确撤销：先填写原因并预览数量、剩余量和执行状态的变化，再确认撤销。系统追加撤销事实，原报工、全部更正及原时间/资源/备注保留在历史中；现场、实际甘特、报表、风险与校准统一排除已撤销报工。单次撤销不撤销同工序的其他报工，也不抹除历史开工事件；填 0 或清空时间都不表示撤销。存在后道事实、正式计划或已采用工时定额依赖时，预览列明原因并禁止确认；过期预览需要重新核对。

Excel 导入在后台会先检查整份文件：哪些行能匹配任务，哪些行找不到任务，哪些时间格式不对，哪些完工早于开工，哪些暂停时间重叠，哪些可能重复导入，以及最后会新增、忽略、冲突多少条。检查有错误时一条都不写，并把错误明细显示给用户；整批无错误时才直接写入。

计划员可以在复盘里看到计划和现场实际的差别。重新排程时，系统会尊重已经发生的现场事实：已经开工或暂停的工序不随便移动，已经完工的工序保留真实时间，异常中的工序先提示处理异常。

甘特图任务详情区也读取同一套现场执行事实。点击任务时，详情区显示计划时间、现场状态、实际开工、实际完工和“暂未记录现场实际”等小结；这些字段只从执行事件聚合结果来，不从计划行硬猜。

周计划页同样读取这套现场执行事实：预览表每行与 Excel 导出显示「现场状态」中文标签（词表与甘特详情同源），计划行没有任何事实时显示「待开工」（没有事实=尚未开工，不是数据缺口）；周计划页仍只读，不写现场记录。

## 边界

- 不把现场实际时间直接覆盖到原来的计划排程行。
- 不允许候选方案、模拟预览或历史正式方案写入现场记录。
- 第一版不做完整 MES，不做扫码枪依赖、IoT 实时采集、电子签名、工资计件或完整质量追溯。
- 不做实时设备采集，不做自动控制设备暂停或继续生产，不在异常记录后自动重排。
- 不把 `op_id`、`schedule_id`、`state_revision`、`execution_snapshot_revision` 这类内部字段放进普通用户填写模板。
- 工作台单次报工的撤销已单独实施；旧开工/完工事件的通用撤销和反冲不在此能力范围，不能静默覆盖历史事件。
- 甘特任务详情区只是查看现场实际小结，不在甘特页写现场记录，也不开放拖拽改计划。
- 时间建议和复制内容均需用户核对，不是设备采集的现场事实；清空建议不按零时刻或当前时间补写，未知时间与零数量、零工时仍分开表达。
- 新建、补齐、更正和单次报工撤销沿用追加事实、原记录核对和写入许可。已撤销记录不能补齐、更正或用原单号重新导入；没有新增自动报工或通用反冲能力。

## 变更日志

- 2026-05-28：资源派工页把用户入口调整为“现场记录 / 填写实际情况 / 导入实际情况 Excel”。实际开工、实际完工、暂停时间和异常记录都支持手填；反馈人可空；Excel 普通页面采用一键导入，后台先检查整份文件，有错误不写库并展示错误明细，整批无错误才写入；暂停/继续不再作为醒目的实时动作，而是填写暂停时间段。
- 2026-05-27：从 draft 升级为 current。现场开工、完工、暂停、继续生产、报异常、计划和现场实际复盘，以及重排尊重现场事实已经形成闭环；撤销和纠错仍保留为后续单独能力。
- 2026-06-01：甘特任务详情区接入现场执行事实；点击任务后能看到计划和实际小结，没有现场记录时显示“暂未记录现场实际”，但甘特页仍只读，不负责写现场记录。
- 2026-06-13：甘特条形接入现场执行事实可视化（fusion-gantt-execution-visuals）：已完工工序整条显示半透明绿色罩层，生产中/已暂停/异常中以蓝/琥珀/红描边区分（超期红边仍优先），图例可查；任务详情侧栏补优先级/加工方式/时长，旧弹窗补现场摘要；甘特仍只读。
- 2026-06-12：周计划页接入现场执行事实（fusion-week-plan-enrich）：预览表与 Excel 导出新增「现场状态」列，同工序跨日各段行同状态，无事实的计划行显示「待开工」；周计划页仍只读。
- 2026-06-01：资源派工页把“计划员查看”和“现场事实”分成两个视觉区域；顶部“查看计划和实际”只作为复盘入口，卡片内按钮改为“查看现场记录”；现场记录任务卡显示图号/物料、计划/实际时间和偏差，执行流水显示记录来源和落库时间。非正式方案、历史方案和模拟预览不输出现场记录写入 URL 或空的 `data-*` 写入地址。
- 2026-09-12：补入工作台新建报工的可清除时间建议、复制同任务同工序上一条有效记录、保存确认后自动重读与条件满足后继续登记；补齐、更正和已有草稿保持原值，未知结果不重复提交，未保存输入受离开确认保护，原台账与整批导入边界不变。
- 2026-09-15：新增单次报工显式撤销与统一有效事实读取，保留原报工和历史事件；程序专项与手动覆盖分别见[实施盘点](../roadmap/workbench-manual-remediation/execution-20260915/implementation-and-coverage.md)。本轮按用户要求未跑全门禁，不能将当前源码能力当作全部手动验收通过。
