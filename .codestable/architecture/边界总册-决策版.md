# 项目边界总册 · 决策版

> **这份怎么用**：你要加功能、改东西、做决定时，翻到相关那条，看第③段"这对你做决定意味着什么"。
> 每条边界都写成三段：**①规矩是啥（举例）→ ②谁在守 → ③你做决定时要注意啥**。
> "谁在守"里：**🛡️ 有报警器**=焊死了，你违反它会自动报错；**⚠️ 没报警器**=只能靠你自己留神。

# 第一类：交付铁律（碰了这些，软件装不上客户机器 = 白干）

## D1 · 必须能在老 Windows 7 上离线跑
- **①啥意思**：客户的机器是 Win7 64 位，没装 Python，也不联网。你的软件得在这种机器上自己跑起来。比如你不能写"运行时去网上下载个组件"——客户机没网，直接崩。
- **②谁在守**：🛡️ 有报警器（`test_win7_launcher_runtime_paths`、装包时还会检查依赖都打进去了没）。
- **③做决定时注意**：你想引入任何新的第三方库、新工具，**第一个问题永远是"它能在 Win7 + Python 3.8 离线装上吗"**。不能，就别用，哪怕它再好用。这是你所有技术选型的天花板。

## D2 · 只能用 Python 3.8 的老语法
- **①啥意思**：Python 3.9 以后有些新写法（比如 `list[int]` 这种），你不能用，因为开发和打包都卡在 3.8。用了新语法，打包机直接报错。
- **②谁在守**：🛡️ 有报警器（专门有个扫描器 `scan_py38plus_syntax` 在门禁里跑，用了新语法会被拦）。
- **③做决定时注意**：这条你基本不用操心——手滑用了新语法，门禁会红。放心写。

## D3 · 页面不许依赖外部网络资源
- **①啥意思**：网页里不能写"从某某网站加载字体/脚本"。所有图片、样式、脚本都得打包在软件里。因为客户机没网，外链全是死的。
- **②谁在守**：🛡️ 有报警器（`regression_frontend_offline_static_assets`）。
- **③做决定时注意**：想用个新的前端效果、新图标库，先确认"能不能下载下来打进包里"。能，就行；只能在线用的，放弃。

## D4 · 只能用老 Chrome 109 支持的网页功能 ⚠️
- **①啥意思**：客户浏览器是老版 Chrome，新浏览器才有的网页功能（某些新 CSS、新 JS API）它打不开。
- **②谁在守**：⚠️ **没有硬报警器**。只有个"页面别错位"的粗略检查兜底，但它不锁浏览器版本。
- **③做决定时注意**：**这条要你自己留神。** 你做前端大改、用某个炫酷新效果时，得自己确认"老 Chrome 支持吗"。这是少数几条门禁帮不了你的。

## D5 · 给用户看的默认用简体中文 ⚠️
- **①啥意思**：界面文字、提示、报错给用户看的，都用中文大白话，不要蹦英文术语。
- **②谁在守**：⚠️ 没报警器，靠你自己和 review。
- **③做决定时注意**：加新页面、写新提示语时自己把关用中文。问题不大，但门禁不管。

# 第二类：房子的承重墙（这些是"代码怎么分层"的铁规矩，全部焊死了）

> 这一整类有个天大的好消息：**我用工具把整个项目扫了一遍，这 10 条承重墙一条都没被破坏过。** 这是你"地基牢不牢"最硬的答案——牢。

## L1-L2 · 算法和数据模型是"干净的底层"，不许往上勾连
- **①啥意思**：你的排产算法、数据模型，是最底层的东西。它们只能被上面调用，**不许反过来去碰上层的业务逻辑**。好比地基不能伸手去抓二楼的家具。一旦算法层开始依赖业务层，整个结构就会缠成一团乱麻，再也拆不开。
- **②谁在守**：🛡️ 工具全量扫描，**0 违规**。
- **③做决定时注意**：你在算法层（`core/algorithms`）或模型层（`core/models`）写东西时，**不要 import 上层的 service**。真要这么写，说明你的设计反了，停下来想想。但放心，真写错门禁会拦。

## L3 · 页面的"数据准备层"必须干净
- **①啥意思**：viewmodel（专门给页面准备数据的那层）只能做数据整理，**不许自己去查数据库、不许调业务服务**。它就是个"摆盘的"，不下厨、不进仓库。
- **②谁在守**：🛡️ 有报警器（`test_viewmodels_do_not_import_...`）。
- **③做决定时注意**：写 viewmodel 时只整理已经拿到的数据，要查数据让上游查好传进来。违反了门禁会红。

## L4-L5 · 网页路由不许直接碰数据库
- **①啥意思**：处理网页请求的代码（route），不能自己写 SQL、不能直接调数据库仓库，必须通过中间的 service 层。好比前台不能直接进仓库搬货，得通过库管。
- **②谁在守**：🛡️ 有报警器（`test_routes_do_not_execute_sql_directly` 等）。
- **③做决定时注意**：加新页面/接口时，数据操作都丢给 service，route 只管收请求、返结果。违反门禁会拦。

## L6 · 业务服务层不许碰"网页请求"对象
- **①啥意思**：service 层是纯业务逻辑（比如"怎么排产""怎么算齐套"），它不该知道"自己是被网页调用的"。所以不许在 service 里 `from flask import request` 去读网页参数。打个比方：厨师只管做菜，不该跑到前台去问客人点了啥——点单信息应该由服务员（route 层）整理好递进厨房。
- **②谁在守**：🛡️ 有报警器（`test_services_do_not_import_flask_request`）。
- **③做决定时注意**：如果你发现自己想在 service 里读 `request.args`，说明分工错了——把参数在 route 层取出来、当普通参数传进 service。这样 service 才能脱离网页单独测试、单独复用（比如以后做命令行批处理也能调它）。违反了门禁会红。

## L7 · 业务服务之间不许"循环依赖"
- **①啥意思**：A 服务调用 B 服务、B 又回头调用 A，这就成了死结（甚至 A→B→C→A 这种绕一圈的）。循环依赖一旦形成，这几个模块就**焊死在一起再也拆不开**，改一个必牵动一串，是腐烂的典型起点。
- **②谁在守**：🛡️ 有报警器（`test_no_circular_service_dependencies`，而且它能查出绕好几个模块的环，不只是两两直接的）。
- **③做决定时注意**：你想让 A 调 B，但 B 已经在调 A 时——**不要硬连**。正确做法是把两者都依赖的那部分逻辑抽到一个更底层的公共模块，让 A、B 都去依赖那个底层，而不是互相依赖。门禁会拦住新的环。

## L8 · SQL 只能写在数据库层，业务层一句裸 SQL 都不许有
- **①啥意思**：所有 `SELECT`/`INSERT` 这种数据库语句，只能待在 `data/repositories`（数据库层）里。service 业务层里**一句裸 SQL 都不该出现**——它要数据就调 repository 的方法，不自己拼 SQL。好比库管才能进库房按单取货，业务员只能开单子，不能自己翻货架。
- **②谁在守**：🛡️ 第一轮审计 grep 全层验证**成立**（service 层零裸 SQL），加上 L5（route 也不许写 SQL）一起兜。
- **③做决定时注意**：你在 service 里想"顺手查一下数据库"时，停——去 repository 加一个查询方法，service 调它。这样 SQL 全集中在一处，将来换数据库、改表结构只动一层。这条让你的数据访问"只有一个入口"，是可维护性的关键。

## L9 · 业务层不许用 `assert` 当"运行时保护"
- **①啥意思**：`assert x > 0` 这种断言，看起来能拦住非法数据，但**软件正式上线用优化模式（python -O）跑时，所有 assert 会被整个删掉**——你以为有道防线，上线后那道防线根本不存在。所以保护用户输入、保护业务契约，必须用真正的 `if ... raise`，不能用 assert。
- **②谁在守**：🛡️ 有报警器（`test_services_do_not_use_assert_for_runtime_guards`）。
- **③做决定时注意**：assert 只能用在"开发期自查不变量"（那种就算被删也无所谓的）。凡是"这个数据非法就该报错给用户"的地方，老老实实写 `if 非法: raise 错误`。门禁会拦住 service 里的 assert。

## L10 · 核心代码不许 `import *`
- **①啥意思**：`from xxx import *` 这种"把一个模块里所有东西一股脑导进来"的写法，会让人看不清这个文件到底用了啥、名字从哪来，时间长了变成一团糨糊。核心目录禁止这么写，必须明确写出导入了哪几个名字。
- **②谁在守**：🛡️ 有报警器（`test_no_wildcard_imports`）。
- **③做决定时注意**：这条你基本碰不到——正常写代码不会用 `import *`。手滑用了门禁会红。它的价值是让每个文件的"依赖关系"始终清清楚楚。

# 第三类：给客户的安全底线（不能泄密、不能让用户乱改）

## S1-S2 · 内部编号绝对不能让用户看见
- **①啥意思**：系统内部有一堆编号——方案 ID、计划角色、工序 ID、数据库行号这些。这些**只能在背后用来对齐数据，绝对不能出现在用户看的页面、按钮、导出的 Excel 里**。用户该看到的是"3 号车床""一批齿轮"这种人话，不是"op_1078"。
- **②谁在守**：🛡️ 有好几个报警器（`excel_hidden_payload_contract`、`resource_dispatch_public_output_contract`、`domain_model_internal_source_contract` 等）。
- **③做决定时注意**：你加任何"给用户看"或"导出"的东西时，确认里面没漏内部编号。但放心，真漏了，这几个报警器很灵，会红。

## S3 · 甘特图只能看，不能拖着改
- **①啥意思**：甘特图（那张任务时间条的图）是给人看排产结果的，**任务条不能拖、不能拉**。不能让用户以为"我拖一下就改了计划"。
- **②谁在守**：🛡️ 有报警器（`gantt_readonly_mode_contract`）。
- **③做决定时注意**：你以后想给甘特图加交互功能时，**这是条红线**——可以加"点击看详情"，但不能加"拖拽改计划"。想做拖拽改计划是个大决定（你 requirements 里明确说第一版不做），要做先回去改边界。

## S4-S5 · 只有"正式采用的方案"才能写现场记录
- **①啥意思**：你有正式方案，也有一堆"候选方案、模拟预览、老的历史方案"。**只有当前正式采用的那个，才能让现场填实际生产情况**。其他那些方案的页面上，连"写入"的按钮、Excel 导入入口都不能出现——不能让用户以为"这个也能写"。
- **②谁在守**：🛡️ 有报警器（`scheduler_workbench_link_guardrails`、`dispatch_plan_identity_guardrails`）。
- **③做决定时注意**：你做任何跟"现场记录、方案切换"相关的功能时，记住这条逻辑：**写入权限只跟着正式方案走**。这块逻辑绕，但有报警器盯着，写错会红。

## S6 · 导出的 Excel 只放中文业务字段
- 🛡️ 有报警器（4 个 excel contract 测试）。**③** 改导出格式时别把内部字段塞进去，会被拦。

## S7 · 现场已经在干了，就不许偷偷重排覆盖
- **①啥意思**：如果某些工序现场已经开工/暂停了，系统重新排产时**不能把这些现场事实冲掉**，发现冲突要停下来用中文提示，不能硬写。
- **②谁在守**：🛡️ 有报警器（`reschedule_execution_minimum_guardrails`、`freeze_window_fail_closed_contract`）。
- **③做决定时注意**：动重排逻辑时，这条是安全底线，有报警器守着。

# 第四类：你说好"不做"的事（防止越做越大，刹不住车）⚠️

> 这一整类**几乎都没报警器**——因为它们是"产品范围承诺"，不是代码规矩，工具管不了。
> **这是你做决定时最该主动对照的一类。** 你以前一时兴起容易越界，做着做着就把小工具做成大平台了。

| 你说好不做的 | 具体啥意思 | 做决定时 |
|---|---|---|
| **C1 不重写排产算法** | 算法是核心，别动它的根 | 想优化算法可以，想推翻重写 = 大决定，先停 |
| **C2 不做完整 MES/IoT** | 不做扫码枪、不做设备实时采集、不做电子签名、不做工资计件、不做质量追溯 | 这些是"另一个产品"，碰到需求往这飘，立刻警惕 |
| **C3 不做甘特拖拽改计划** | 见 S3 | 同 S3，想做先改边界 |
| **C4 候选方案只比三个代表** | 不展示全部 3/5/7 档、不做任意两方案自由对比 | 用户要"全都能比"，先想清楚是不是真要扩这个 |
| **C5 延期诊断不瞎编原因** | 没数据就说"缺数据"，不猜根因，不承诺自动找唯一原因 | 别被"能不能自动告诉我为啥晚了"带跑偏 |
| **C6 报表只按设备和人员筛** | 班组、半截资源条件直接拒绝，不假装支持 | 要加新筛选维度是个明确扩张，对照这条 |
| **C7 停机影响只到设备级** | 第一版不做"具体哪个任务受影响" | 要做任务级是第二阶段的事，别提前塞进来 |
| **C8 资源派工不做热力图/大屏** | 不做花哨可视化 | 想加炫酷图表前，对照这条 |
| **C9 短期不做的** | 反馈人必填、多人现场账号、Excel导入预览/二次确认 | 这些明确押后了，别顺手做了 |
| **C10 复盘只看正式方案** | 模拟/候选方案不进"计划vs实际"复盘 | 同 S4 的逻辑 |

# 第五类：代码卫生规矩（防止代码慢慢烂掉，全部焊死）

这些全 🛡️ 有报警器，你不用记，违反了门禁会红：
- **R1** 文件名用小写下划线（snake_case）
- **R2** 单个文件别超 500 行（超了要先登记）
- **R3** 单个函数别太复杂（超阈值要先登记）
- **R4** 别在核心代码里新写零碎的解析小函数（防止满地重复）
- **R5** "出错先用默认值兜着"的地方必须登记到台账
- **R6** 降级提示码必须登记
- **③做决定时注意**：这一类是"门禁帮你自动维持整洁"。唯一对你有影响的是 R2/R3——你写着写着文件超 500 行/函数太复杂，门禁会让你要么拆开、要么登记。这是好事，逼你别堆屎山。

# 🎯 全文精华：你做决定时，真正要主动看的就这两块

其余所有边界都有报警器焊死，你违反不了。**做决定时你只需要主动对照这两块**：

### 1. 技术选型决定 → 看第一类的 D1（Win7离线）+ D4（老Chrome）
想引入任何新库、新工具、新前端效果，先问："Win7 离线装得上吗？老 Chrome 支持吗？"

### 2. 功能范围决定 → 看第四类那整张表（C1-C10）
想加新功能时，对照"说好不做的事"扫一眼，确认你没有正在把小工具做成大平台。**这是你最容易刹不住车的地方，也是门禁唯一管不了的地方。**
